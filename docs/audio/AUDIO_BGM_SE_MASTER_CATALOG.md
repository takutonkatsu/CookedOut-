## 1. 役割と変更ルール

本書は「何の音が必要か」と「候補をどう探し、採用するか」の正本である。ゲーム仕様を増減する文書ではない。ステージ、料理、操作、配達、ランキングの仕様が上記正本と食い違う場合は上記正本を優先し、本書の割当だけを更新する。

安定IDは実装イベント、ファイル名、候補台帳、QA不具合で共用し、採用後は改名しない。差替えはIDを維持して版番号を上げる。候補は一候補一行でCSVへ追加し、権利確認が完了するまでゲーム本体へ組み込まない。

## 2. 音の共通方針

- 明るく玩具的で、短い立ち上がりと明確な輪郭を持たせる。忙しくても「成功」「注意」「危険」「通信」を聞き分けられることを優先する。
- 焦げ、火災、注文期限、厨房変化、配達事故は、BGMを小さくしても互いに区別できる音色・リズム・高さにする。
- 重要情報は音だけへ依存せず、形、動き、HUD、振動と併用する。消音時もプレイ可能にする。
- 実在店舗のチャイム、著名曲・著名ゲームに酷似した旋律、過度に写実的な事故音、悲鳴、銃声に聞こえる破裂音は避ける。
- キャラクター種ごとの言語ボイスは作らない。必要なリアクションは非言語の短い掛け声を共通イベントとして扱う。
- BGMは自然にループできる基礎曲を中心にし、残り30秒、配達、動的厨房は同一テンポ・同一小節長のステムを重ねる。ステムが調達できない候補は、同拍・同キーの短いレイヤーを内製するか、別曲への小節同期切替で代替する。

### 2.1 優先度・状態・納品形式

| 記号 | 意味 |
|---|---|
| P0 | 縦切り1-1〜1-3と基本操作に必須 |
| P1 | 第1章完了とコアループに必須 |
| P2 | 初期54ステージ・メタ画面に必要 |
| P3 | 仕上げ、追加変化、運用改善 |

制作・入手状態は `未探索 → 候補あり → 権利確認中 → 試聴中 → 仮採用 → 実装済み → QA済み → 採用` とする。不採用候補もCSVから削除せず理由を残す。

- マスター: WAV、PCM、48 kHz、24 bit。短いSEは原則mono、空間を持つ環境音・BGMはstereo。
- Unity実装: BGM・長い環境音はプラットフォーム圧縮後のループ継ぎ目を実機確認。短いSEはWAVマスターから用途に応じて圧縮し、原本を保存する。
- ループ素材: 先頭・末尾の無音、ループ点、BPM、拍子、キー、正確なサンプル長を記録する。MP3しかない素材はギャップレス性と再圧縮劣化を理由に原則不採用。
- 音量目安は実装ミックスで決める。マスターへ過度なリミッターが掛かり、波形が常時張り付く素材は避ける。

## 5. 同時発音・ミックスの実装方針

1. 優先順位は `火災・焦げ・注文期限・動的予告・切断 > 操作成功・提供 > 移動・環境` とする。
2. 同一プレイヤーの足音、切る音、設置音は短い再発音間隔を持たせる。同時注文・得点は100〜250 ms内の発生を一つの強い音へ集約する。
3. 同種のloopは距離の近い上位だけを鳴らす。鍋・フライパンは各最大4、火元は最大3、ギミック駆動音は最大3を初期値とする。
4. 重要警告中はBGMを2〜4 dB、環境音を4〜8 dB一時的に下げる。複数の警告が重なっても全体音量を上げない。
5. 画面外の重要音は過度な3D減衰を掛けず、HUD通知と結び付ける。通常操作音は自分を中央、仲間を軽く定位して区別する。
6. 端末スピーカー、イヤホン、消音、BGM 0%、SE 0%、低音量で検証する。iPhone内蔵スピーカーで高域が刺さらず、低域だけで意味が失われないことを採用条件にする。

## 6. 候補音源の登録と採用手順

「フリー」「無料」「royalty-free」という表示だけでは採用しない。royalty-freeは著作権放棄を意味せず、無料素材でもアプリへの埋込みや再配布を禁じる場合がある。

### 6.1 登録

1. [AUDIO_SOURCE_TRACKER.csv](AUDIO_SOURCE_TRACKER.csv)へ候補IDと対象の安定IDを記入する。一つの候補が複数IDへ使える場合も、用途ごとに行を分ける。
2. 音源ファイル直リンクではなく、作者・配布元・利用条件が分かる配布ページURLも残す。
3. 作者名、曲名／音名、ライセンスの正式名称と版、規約URL、確認日を記録する。不明欄を空欄のまま採用へ進めない。
4. 規約ページ、作品ページ、購入証明、作者の追加許諾がある場合はPDFまたはスクリーンショットとして `docs/audio/evidence/<candidate_id>/` に保存する。規約変更へ備え、確認日と取得元URLを一緒に残す。

### 6.2 権利ゲート

以下をすべて明文で確認する。判断できない場合は `要問い合わせ` または `不採用` とする。

- 有償アプリ、広告収益、アプリ内課金を含む商用利用が可能か。
- トリミング、ループ化、音量調整、EQ、圧縮、他音とのミックス等の改変が可能か。
- クレジットが必要か。必要なら指定文言・リンク・表示場所を確保できるか。
- Unityビルドへ埋め込み、ユーザー端末へ配布できるか。素材単体での再配布禁止と、ゲームへの組込み許可を分けて確認する。
- Content ID、著作権自動検出、配信・実況・広告動画への申し立て条件があるか。作者以外の登録可能性も確認する。
- 生成AI製、AI学習利用、AI生成物禁止、学習データ保証、追加表示義務などの条件があるか。
- ライセンスの適用主体が作者本人で、第三者の録音・サンプル・演奏を無断利用していないと合理的に確認できるか。
- CC系の場合は正確な版と要件を確認する。`NC` は本作に使わない。`ND` はループ加工・編集と衝突し得るため原則使わない。CC0でも配布者の権利保有と第三者要素を確認する。

法的に曖昧、作者不明、規約が画像だけで保存不能、規約同士が矛盾、Content ID方針不明、アプリ組込み不可のいずれかなら仮採用もしない。これは法的助言ではなく制作上の保守的な採用基準である。

### 6.3 音質・用途ゲート

1. 原音をヘッドホンとiPhoneスピーカーで聴き、ノイズ、クリック、歪み、過度な残響、過圧縮を確認する。
2. BGM・環境音は最低10周ループし、継ぎ目、拍ずれ、残響切れ、圧縮後ギャップを確認する。30秒、配達、動的レイヤーは基礎曲と同時再生してBPM・拍・キーを確認する。
3. SEは実プレイ密度で連打し、同じ音の機械的反復、警告同士の混同、BGMへの埋没を確認する。
4. 用途適合・音質・ループ性・ライセンスを各0〜5点で評価する。ライセンスが5点でない候補は総合点に関係なく採用不可とする。
5. 仮採用後にUnity実機ビルドで音量、レイテンシ、圧縮、メモリ、同時発音を確認し、QA済みになってから採用へ進める。

### 6.4 採否の目安

| 観点 | 5点 | 3点 | 0点 |
|---|---|---|---|
| 用途適合 | 発音イベントが無説明で識別でき、世界観にも合う | 加工で使用可能 | 他イベントと混同、作風不一致 |
| 音質 | 原音・端末・圧縮後とも問題なし | 軽い補修が必要 | 歪み、著しいノイズ、修復困難 |
| ループ性 | 10周と圧縮後も継ぎ目なし | 編集で改善可能 | 拍・残響・権利条件上編集不可 |
| ライセンス | 全権利欄が明文で確認でき証跡保存済み | 不明点あり | 商用・組込み不可、権利者不明 |
