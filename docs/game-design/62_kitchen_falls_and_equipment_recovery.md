# COOKED OUT! 厨房落下時の設備復旧と料理損失仕様 v0.2

- 作成日: 2026-09-13
- 状態: 2026-09-13ユーザー「良いです。次に行きましょう」により、公開した設備・器具返却と内容物損失、空の手持ちで復帰、同一区画の安全地点、落下自体の追加減点・コンボリセットなし、料理の作り直し、配送事故との区別を採用。本文の「案」は公開承認範囲に限り採用として読む。復帰秒数・具体地点・判定済み注文との再紐付け等の未公開細部は検討／検証待ち。未実装
- 範囲: 厨房で料理人や道具が穴・水・場外へ落ちる場合。バイクの衝突・散乱・配送期限・自動帰還は変更しない

## 1. 手持ちの器具・設備は返すが、中身は失う

料理人は短い復帰待ち後、安全地点へ戻る既定を維持する。生食材や料理・使い捨て配達容器は失う一方、鍋・フライパン・ジャー・トレー・可搬設備本体・消火器は永久消失させない案。

器具だけを持って落ちた場合は空の器具を、設備一式を持って落ちた場合は空の一式を、復帰した本人の手へ戻す。鍋だけ落ちたならコンロは元の場所に残る。ジャーだけなら本体は残る。一式に含まれていた本体と器具だけを返し、新しい付属品を増やさない。

内容物は完成度・焦げ状態を問わず全量損失し、その料理を作った進捗もなくなる。運搬による状態保持とは異なり、場外落下はその料理自体の損失である。料理がなくなった空の器具に古い料理の焦げタイマーを残さない。設備の種類Lv・所有数は下げず、修理費・買戻し・耐久度を加えない。

## 2. 復帰地点

本人はその時点で安全に立てる地点に復帰し、設備を持ったまま再び操作できる。初期スポーンへの固定ワープで区画を飛び越えることを標準にせず、元の担当区画・島を維持する安全地点をステージごとに設計する。

同じ厨房画面内で状況を示し、確認ダイアログ・新しい回収メニューを加えない。復帰待ちや復帰直後保護の具体秒数は試験で決める。床変形直後に再落下する地点、仲間と重なって動けない地点は復帰先にしない。適切な空き作業台と操作可能な安全床を復帰区画に確保する。

## 3. 注文・スコア・コンボ

厨房で料理を落としただけでは注文を即時失注にせず、残り時間内に作り直せる。落下そのもののスコア罰金・コンボリセットも加えない。失った内容物からスコア・コインは発生しない。

営業・注文・配送・他設備の調理は復帰待ち中も進む。注文が期限に達した場合だけ既定の失注処理を適用する。準備前の料理損失と期限切れを二重に罰しない。

初回積載等で既にコンボ判定済みの注文に紐付いたパックを厨房で失った場合、その物体の紐付けだけを解除して作り直せるようにする案。注文単位の初回判定履歴・記録済み倍率・依存関係は維持し、作り直し・再積載で二回目のコンボ判定をしない。準備タイマーを巻き戻さず、未納品のままならボーナスも確定しない。具体的な再紐付けは既存の注文照合規則と整合させる。

## 4. 道具だけが場外へ落ちた場合

道具は通常投げられないが、将来の動的床等で道具だけの場外が生じる可能性を扱う。短い復旧待ち後、直前の安全な区画へ空の状態で戻す案。最終有効設置面が空いていればそこへ返す。埋まっている場合は仲間の物を押し退けず、作者が保証する区画内の安全な予備復旧先へ戻す。元の購入先本体へ専属返却する方式にはしない。

復旧用の常設メニューや新しい購入設備は増やさない。予備復旧先の形状・複数道具が同時に失われた際の置き場所確保はステージ設計で詰める。戻す位置・待ち時間を保証できない盤面は出荷対象にしない。

一時的に橋が閉じている・別の島へ置いた・仲間が持っているだけの道具は紛失扱いしない。ギミックが再接続するまで待つ判断を自動返却で消さない。物理不具合による壁埋まり等の救済は、ゲーム上の場外落下と区別し、食品消失の可否も別途検討する。

## 5. バイク事故との区別と検証

路上で転倒して近くへ散らばった配達パックは、これまでどおり料理を保持し、拾って元の荷台へ載せる。厨房の水没損失を配送の路上散乱へ拡張しない。配達パックを到達不能な位置へ飛ばさない既定も維持する。

検証: 鍋だけ・コンロだけ・中身入り一式・ジャー・消火器の落下、島が動いた後の復帰、連続落下、同時復旧、準備判定済み料理の作り直し、復帰中閉店、切断との重複。死亡演出を過激にせず、残機制・ゲームオーバー条件も追加しない。

故意落下を空器具の無料配送や高速廃棄として利用する可能性は残る。料理の損失・復帰待ち・同一区画への帰還で通常運搬より有利にならないか検証し、必要なら復帰位置や待ち時間を調整する。新しい罰金を最初から重ねない。
