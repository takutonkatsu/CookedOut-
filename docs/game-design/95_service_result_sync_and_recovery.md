# COOKED OUT! 営業結果の同期待ちと復旧案 v0.1

- 作成日: 2026-09-14
- 状態: 2026-09-14、ユーザー承認で公開方針を採用。正規終了結果の保存・自動再送・重複付与防止、確認中表示・確定後反映、ホームへ戻れる導線、保存済み結果の再起動後再送、閲覧・報酬なし練習、同期待ち中の強制広告なし、復旧不能時の確認・問い合わせ・解消経路が対象。未公開細部、保存保証・期限・実装方式は未確定。実装・障害試験は未実施
- 既定: 営業開始にオンライン接続、一回限りの営業チケット。ソロの一時通信断は完走可能、結果を同期待ちにする。未同期結果がある間は次の報酬営業を開始しない。正規終了前にアプリ終了で状態を失った営業は途中再開しない

## 1. 正規終了後の結果を保護する

営業が正規終了したら、送信前に再送用の結果を端末へ保存する。スコア・納品・参加条件等の検証に必要な情報と営業識別子をまとめる。結果検証後にサーバーで星・報酬・進捗を確定し、何度再送しても一営業を二重計上しない。

サーバーでは確定したが応答だけ届かなかったケースも、同じ営業の確定状況を照会して解消する。保存形式・検証証拠・保存完了前のクラッシュ対策は実装時に設計し、端末破損や再インストールまで無条件に復旧できると約束しない。

## 2. 結果画面

- プレイ結果は表示し、未検証の星・コイン等は「確認中」と分かる表示にする
- 確定前のコインは使用可能残高へ加算せず、昇格・料理解放・ランキング掲載も確定後にする
- 通信復帰時に自動再送し、手動の再試行も用意する。何度も受取操作を要求しない
- 同期待ちからホームへ戻れる。後で確定したら短く通知し、結果画面の再閲覧を必須にしない
- 同期待ち画面に強制広告を挟まず、復旧後に広告を後払いさせない。任意広告の報酬処理は別途

## 3. 同期待ちの間にできること

次の通常営業・出張営業・シーズン挑戦は既定どおり開始不可。マルチへの新規出発も対象。保存済みの料理図鑑・設備・進捗等の閲覧は可能にし、既定の報酬なし練習厨房への入口を用意する。練習内容の範囲は別途決定する。

「通信待ち」という理由を開始ボタン付近で示し、タップしてから理由不明のエラーにしない。長い通信障害で遊びが制限される欠点はあるが、今回の案で正式オフライン営業を追加しない。配置編集・購入など他の更新操作をどこまで許可するかは別途整理する。

## 4. 再起動と復旧不能時

端末へ保存済みの正規終了結果は、アプリ再起動後も再送対象にする。営業途中で状態を失ったケースと区別する。

再試行中を永久に表示するだけにはしない。サーバー確定済みか照会し、未確定でデータ破損等が判明した場合は復旧できない理由と問い合わせ導線を示す。今回の結果が復旧不能と確認できた場合に限り、今回分の報酬・進捗を確定できない旨を確認して次の営業へ戻る解消経路を用意する案。通信断だけで自動破棄しない。

解消済み営業に対する遅延再送は新たな付与として扱わない。具体的なサーバー状態遷移・解消権限・問い合わせ対応・補填基準は未決定。ユーザーに証拠ファイルの手動編集・削除を要求しない。過去の確定コイン・設備・星は今回の障害を理由に消さない。

## 5. 競技・協力との境界

シーズンは締切前完走を検証でき、既定の受信猶予内に届く結果だけ順位へ反映。再送で締切後プレイを有効にせず、通常の結果保存期間とランキングの受信期限を混同しない。期限秒数は保留。

マルチは既定の切断・参加時間による記録資格を維持する。結果送信だけの失敗と、営業中の不参加を混同しない。チーム正規結果を確認できた参加者の確定を、別参加者の結果画面への接続だけを理由に止めないことを推奨。ホスト障害時の権威ある結果復旧方式は別途設計する。

## 6. 検証対象

送信前の通信断、確定後の応答消失、重複再送、保存後の再起動、保存途中の終了、破損、シーズン締切、マルチの一人だけの結果受信失敗。実際の保存・復旧保証は実装と障害試験を経て定義する。
