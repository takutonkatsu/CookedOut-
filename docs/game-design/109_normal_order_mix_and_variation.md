# COOKED OUT! 通常営業の注文割合と順序案 v0.1

- 作成日: 2026-09-15
- 状態: 2026-09-16、ユーザー承認で公開方針を採用。1系統各50%、2系統半々・各料理25%程度を初期試験値とし、生成注文の偏り抑制・固定一巡なし・比率設定なしを採用。割合の最終値と偏り上限は未実測、実装は未実施
- 範囲: 通常営業のみ。出張・シーズンの固定注文列、注文補充・失注処理・配送期限の共通ルールは変更しない
- 既定: Lv1〜4は定番の基本2品、Lv5〜20は定番2品＋選択系統2品。追加系統は今回Lvより前の定番に限る。通常営業は制約付き再生成で、ウェーブ操作は不要

## 1. まず均等な割合で試す

| 対象 | 初期の出題割合案 |
|---|---|
| Lv1〜4 | 基本2品を各50%程度 |
| Lv5〜20の系統比率 | 定番50%・選択系統50%程度 |
| Lv5〜20の各料理 | 各系統内で半々、全体では4品それぞれ25%程度 |

定番を極端に多くして選んだ系統の影響を薄くしたり、追加系統だけで営業が回る構成にしたりせず、両方の調理・配置を考える機会を作る。実際の作業時間を50／50にする意味ではなく、生成する注文件数の割合。

各4分の営業で件数を厳密に一致させる保証はしない。注文発行数や終了位置はプレイによって変わる。対象は生成注文であり、未処理・失注・配送未完了も発行済みとして数える。提供成功した料理だけから不足分を判定し、都合のよい料理が出るまで失注させられる仕組みにはしない。

## 2. 並びは毎回変え、極端な偏りを抑える

同じ料理が続く機会を残しつつ、片方の系統ばかりになる、長工程料理と遠距離配送だけが固まるといった偏りを抑える。必ず交互、必ず4品一巡といった見抜きやすい固定順にはしない。

偏り補正は直近の生成内容を基準にする。プレイヤーの成功率・スコア・課金状態を見て、上手い人だけ不利な注文に変える動的難度は使わない。連続上限・集計区間・距離帯ごとの目標は試験して決める。

次に来る正確な料理が予告されなくても、同じ献立を理解して仕込み・共用材料・器具の空きを考えられる余地を残す。選んでいない料理や基本3品目を飛び入りさせない。

## 3. プレイヤーに注文割合の設定をさせない

初期は定番／追加の比率をプレイヤーがスライダー等で調整する仕組みを設けない。献立の選択、設備配置、仕込み、配送方法に判断を集約する。比率は内部調整値であり、営業前に毎回確認させる画面を追加しない。

ウェーブごとの休憩、発注ボタン、料理ごとのノルマは追加しない。注文は既定の供給処理で自動発生し、生成列の都合だけで全注文が終わる空白を作らない。実際の発生間隔・発送補充等は共通ルールと別途検証する。

## 4. 均等でも収入・難度が同じになるわけではない

4品各25%でも、料理の手作業・自動加熱・合流・材料共用・設備競合によって負荷は変わる。料理基本点が高いことだけで必ず最適になるとも、簡単な料理が必ず最適になるとも決めつけない。

同一Lv・同じ設備水準で、献立の組合せと生成列を変えて、星到達、納品基本点由来のコイン、忙しさを測る。営業Lv固定の星基準を抽選ごとに変える仕組みや、料理ごとの新しい星基準は設けない。数値が合わない場合の工程・基本点・生成負荷の調整は別の明示的な検討とする。

## 5. 確認項目

序盤2品が長く片方に偏らないか、Lv5で2系統の両方を扱えるか、終盤に簡単な系統だけが最適にならないか、同一献立の再挑戦で単調にならないか、遅いプレイ・失注・まとめ配送で出題分布が意図せず操作できないか。試験値と最終値を区別する。
