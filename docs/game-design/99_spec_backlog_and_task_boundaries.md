## 3. 明示的に後日へ保留しているもの

- マネタイズ方法。104の外見共通セット・試着・手動装備は採用し、具体入手経路・販売商品構成・価格・有償通貨等は後日相談。2026-09-15のユーザー指定による
- デイリー具体仕様と週次ミッション不採用案。93を参照し、話題を勝手に再開しない
- 新章追加時の追加通常Lvの難度・必要評判の具体値。92を参照し、実際の追加時に相談する
- シーズン4課題の具体テーマ・料理の組合せ等。仕組み自体は決定済みで、通常営業・ステージ側の検証結果を踏まえて内容を詰める

## 4. 文面だけでは確定できない調整

- 工程秒数・設備Lv係数・注文間隔／猶予・配送期限・代行所要時間
- 自配達と代行の得点／分の差、料理基本点の補正、設備価格と必要評判の最終値
- 面別の星基準点と人数別負荷。本タスクで共通式、ステージ側で面別設定を扱う
- HUD・図鑑の実寸、タッチ判定、長押し秒数、視認性、配達物理・復帰時間、端末性能

これらも追跡するが、未実測の数字を机上だけで最終確定しない。試験値と合格条件を決め、試作の観察を受けて更新する。

## 5. このタスクの直近の推奨順

1. 直前の練習厨房とつながる、設備台数・配置編集・保存の残りを閉じる
2. マルチの準備・離脱導線と、アカウント／セーブの扱いを整理する
3. 外見・ショップ・任意広告、設定とヘルプの具体仕様を整理する
4. 料理／ステージ側の進行と合わせ、通常営業の定番・解放・経済を接続する

順序は提案。各テーマについて選択肢と推奨を示し、ユーザーの返答を受けて採用する。本書の作成だけで残件の答えを決めたり、機能を実装したりしない。

## 6. ステージ設計タスクへ引き継ぐ要点

参照優先はCURRENT_GAME_SPEC、料理統合台帳、75の解放条件、98の設計順序。旧54面・旧8面チュートリアル・旧料理候補を現行確定として使わない。

最初の作業は48面の粗い役割表と第1章の操作導入の整合確認。第1章から具体盤面を相談し、全48面を一括承認扱いにしない。料理は既定の20系統60品を参照し、変更が必要なら理由を添えて相談事項にする。具体スコアは試験値と最終値を区別する。

ステージ専用の検討表・決定ログを持ち、共通仕様や料理定義を独断で上書きしない。共通ルールの変更が必要な箇所は現在タスクへ返す申し送りとして残す。実装・画像生成・他タスクへの送信は別の明示依頼に従う。
