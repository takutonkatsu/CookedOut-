# COOKED OUT! 仲間のパック回収と配送担当の範囲 v0.2

- 作成日: 2026-09-13
- 状態: ユーザー承認により出発前の共同積載・取出し、乗車した人が配送担当、出発後の仲間の回収と元バイクへの再積載、発送後の別バイク移載・運転交代不可、期限切れ時の仲間手持ちパックの返却、専用貢献点なしを採用。具体同時処理とソロ二キャラ切替は未確定・未実装
- 前提: 一人一個持つ、積載は置く、乗車は作業。出荷準備判定は注文ごと一度。配送期限は一出発共通、全納品／期限切れで当該配送が自動帰還

## 1. 出発前は誰でも準備できる

乗車前の荷台には、誰でも完成料理を積める・取り出せる案。専用の予約・担当指名・承認操作は作らない。荷台の容量はそのバイクの容量を使い、持ってきた人の設備Lvで変えない。

初回受理時の注文対応とコンボ記録は、取り出した人が変わっても維持する。未発送なら別バイクや代行へ回す場合も同じ注文の一回の判定を引き継ぐ。乗車する人が出発時の配送担当となる案であり、料理を最初に持ってきた人に固定する意味ではない。

## 2. 出発後は回収を助けられるが、配送担当は変えない

事故で散らばったパックは近くの仲間も拾える案。元のバイクへ積み直すことで回収を手伝える。元の配送期限と注文対応は保持し、他人が触っても時計やコンボを再判定しない。

初期版では、発送済みパックを別バイクへ載せて別の配送へ合流させる操作、出発後の運転担当交代は認めない案を第一推奨とする。荷物の混載で異なる複数期限を一人が管理する状況や、帰還先・担当者が不意に変わる問題を避けるため。元のバイク以外への積載は受理せず、持ち物は手元に残す。失敗だけで廃棄・失注・コンボ切断にしない。

制約の代償は、仲間が代わりにそのまま届ける救援ができないこと。今後それを重視するなら、荷物ごとの元の期限、配達者の自動帰還、バイク容量と報酬帰属をまとめて再設計する。今回この制約を既定の決定として扱わない。

パック上に番号や所有者マークを増やして制約を説明するのではなく、通常の近距離対象輪郭と、受理できない操作時の短い反応で示す。複数バイクが近接する時にも戻す先が理解できるかを検証し、分かりにくさが大きい場合は機能範囲自体を見直す。

## 3. 時間切れ時、仲間が持っている場合

既定の自動帰還と合わせ、期限切れになった当該配送パックは仲間の手持ちからも元の荷台へ返却する案。仲間のキャラクターやバイクは帰還させない。手持ちから消える理由として配送終了の短い反応を出すが、長いダイアログは不要。

配送終了・回収・納品が同時になる場合も、同じパックの所有場所は一つだけにする。二重回収・他便の荷物回収・時間切れ後の納品加点を防ぐ。具体イベント順は共通時刻の仕様に合わせて実装前に確認する。

## 4. 評価とソロの扱い

回収支援の専用ポイント・個人貢献度・称賛操作を新設せず、既定のチーム結果スコアへ反映する。支援で早く配送再開できれば、得点・ボーナス・厨房不在時間で自然に効果が出る。

ソロ出張の二キャラは、操作中のキャラで仲間分の荷物を回収することはできる案。ただし非操作キャラが勝手に拾うAI行動は追加しない。街と厨房のキャラ切替、運転中に切り替えた場合の安全停止・配送時計継続は別の未決仕様として残す。

## 5. 検証

- 回収を手伝えることが簡単に伝わり、担当指名UIなしで成立するか。
- 異なるバイクへ置けないことが不自然な操作拒否になりすぎないか。
- タイムアウトによる返却が、仲間側で意味不明な持ち物消失に見えないか。
- 配送対象の注文を、担当変更や触った人の変更で二重判定・二重加点しないか。
- 元の配送担当が切断中の場合の復帰・既定タイムアウトと整合するか。専用AI代行は追加しない。
