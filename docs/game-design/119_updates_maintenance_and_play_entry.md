# COOKED OUT! 更新・メンテナンス時の案内と開始制限案 v0.1

- 作成日: 2026-09-16
- 状態: 2026-09-16、公開4点をユーザー承認で採用。任意／必須更新の区別、準備中のマルチ互換性確認、計画メンテ前の開始受付停止、障害中の案内と既存結果保護。具体猶予・技術方式・補填等は未確定。更新・メンテ・自動化の設定やコード変更は行わない
- 既定: 正式営業はオンライン開始、結果保護と再送は95、通信不可時の練習は96、シーズンの更新境界と新章参加条件は88〜90に従う。新しい常設モード・課金方式は追加しない

## 1. 任意更新と、遊ぶために必要な更新を区別する

現在の内容を安全・公平に遊べる更新はホームの小さなお知らせに留め、起動するたび全画面で遮らない案。必要ならプレイヤーが詳細を開く。

新章の必要データや互換性・重大修正により旧版を認められない場合は、正式営業の開始前に更新が必要と明示し、ストアの該当アプリへ進む入口を置く。営業中に通常の更新告知で強制退出させない。更新案内と、本編章・店ランクのゲーム内解放条件を区別する。

ストアへの反映前に必須更新を有効化して「更新先がないのに遊べない」状態を作らない運用を要件とする。配信確認方法・対象地域・ロールバック等は技術設計で確認する。特定ストアの現行仕様を本案で断定しない。

## 2. マルチはロード開始前に遊べる組合せか確認する

参加者のゲームルール・ステージデータ等の互換性を準備中に確認し、更新が必要な本人のプロフィールに短い表示を出す案。不一致を放置して全員準備後のロードで失敗させない。互換性が解消するまで開始不可とする。

アプリの表示バージョンが完全一致しなければ一律不可、とは決めない。互換性のある軽微な更新なら一緒に遊べることを目指し、実際に許可する版の組合せは検証して管理する。旧版を無検証で許可しない。

現在の部屋の招待を再利用できる場合は、更新後にそこから再参加する。更新中の席予約・無期限の部屋維持を新設しない。料理習得や章選択が未解放というゲーム内状態と、アプリの更新不足を別の理由として示す。

## 3. 計画メンテは前もって案内し、直前の新規開始を止める

ホームに開始予定・終了予定を短く表示し、予定変更時は更新する。通常の予告を営業中に大きな画面で割り込ませない。

開始直前には、新しい報酬営業を受け付けない時間帯を置く案。開始ボタンには理由と予定時刻を示す。既に始まった営業は原則完走できる運用を目指すが、4分営業に加えてロード・ソロの一時停止・再接続があるため、「4分前に止めれば全員完走」とは保証しない。受付停止の余裕と稼働中セッションの扱いは別途試験・設計する。

シーズン締切と計画メンテは別物であり、通常の月末切替ごとに全サービス停止を必須にはしない。公平な締切の変更や未完走結果への得点付与を、この案で追加しない。

## 4. 待つしかない画面に閉じ込めない

メンテ中はその旨と終了予定を表示し、終了時刻が未定なら未定と伝える。接続失敗だけで原因が判明しない場合は、メンテと断定せず接続できない旨を表示する。再試行と、保存済み内容の図鑑・報酬なし練習への入口を用意する既定を維持する。

更新・メンテの案内で、未同期の営業結果や確定済み資産を消さない。結果の保護・再送は95、古い版で正規終了した結果の検証はその営業開始時のルールと記録に従って設計する。新しい版へ更新しただけで古い結果を二重計上しない。

緊急停止では全ての進行中営業の完走を保証できない。途中でゲーム状態を失った営業を保存済み正規終了結果と同一扱いにはしない。再開・復旧・補填の具体方針、重大な不具合でオフライン内容にも制限が必要な例外は別途決める。今回は補填通貨や回数を一律に設定しない。

## 5. 検証・範囲外

互換版の組合せ、ストア更新先の利用可能性、受付停止の猶予、メンテ延長、ソロ一時停止、再接続、結果同期待ち、シーズン境界をまたぐ更新を検証する。インフラ・配信技術・料金・運用担当・監視・補填規則は未確定。実測なしに無停止やデータ無損失を達成済みとは扱わない。
