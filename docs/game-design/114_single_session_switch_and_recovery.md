# COOKED OUT! 単一ログインの端末切替・復帰案 v0.1

- 作成日: 2026-09-16
- 状態: 2026-09-16、公開4点をユーザー承認で採用。同じ端末の自動復帰、通常画面で確認付き端末切替、営業中・結果確認中は切替待ち、故障・切断時の状態照会と復旧。具体期限・認証方式・範囲外事項は未決。実装・障害試験は未実施
- 他作品の実際の認証方式を調査・再現したものではない。製品上の体験を定める案であり、特定認証基盤の仕様・費用を断定しない

## 1. 同じ端末なら毎回ログイン操作を要求しない

同一端末への復帰は、有効な認証状態を安全に再利用できる場合は自動で行う。他端末が有効なログインを取得済みなら自動で取り返さず、第2項の確認に進む。アプリを閉じるたびにアカウント連携をやり直す体験にはしない。認証の有効期限や再認証が必要な場合は別途定める。

## 2. ホーム・準備中は確認して新端末へ切り替える

別端末がログイン中の場合、新端末で「この端末で続けますか？」と確認し、選んだ場合だけ有効なログインを移す案。旧端末は同時利用不可の案内へ戻し、新しい操作・保存・取引を受け付けない。端末同士で自動的にログインを奪い合う挙動は避ける。

旧端末が通常のホーム・準備状態なら対象とする。マルチロビーにいた場合は旧端末の参加を終了し、既定の退出・管理役交代を使う。新端末をロビーへ自動復帰させず、同じ招待から参加し直す案。未保存・未同期の配置は旧端末内で保持し、新端末で利用できるのはサーバー同期済みの配置に限る。旧端末が再接続しても失効したログインで後追いの保存を行わない。

## 3. 営業中・結果同期待ちは切替を待つ

進行中の正式営業がある場合は、後から来た端末へログインを移さず、「別の端末で営業中です」と示す案。既定どおり進行中営業をログインだけで強制終了しない。マルチの再接続と、別端末への営業状態移送は区別し、初期は営業途中の端末移送を設けない。

営業結果の確認待ちも、同期・照会による状態確定を優先して切替を待たせる案。新端末をログイン待ちの画面に留め、重複した営業・報酬を発生させない。未同期の配置だけが残っている場合は第2項の扱いであり、営業結果の待ちと区別する。

## 4. クラッシュや端末故障で永久に締め出さない

通常の同一端末での一時切断は、まず本人の再接続を試みる。別端末へ切替済みなら旧端末から有効ログインを勝手に再取得しない。通信断中の端末を即時遠隔停止できるとは約束せず、再接続後の認証と保存・取引受付で一台の権限を守る。

アプリ終了・圏外・故障で残ったログインは、サーバーで営業・取引状態を確認して解消する経路を用意する。単純に一定秒数で結果を破棄したり、同じ営業を二重付与したりしない。未同期結果が復旧不能な場合は95の確認・問い合わせ・今回分を確定できない旨の説明を経る解消手順へつなぐ。

短い切断を故障と誤認しない期限・照会・排他の詳細は未決で、実機と通信障害試験で詰める。旧端末の未送信結果が後で到着した場合の扱いも、正規終了結果の検証と一意な営業記録に整合させる必要がある。

## 5. 今回の範囲外

認証提供元、再認証の具体条件、ログイン・営業予約の有効期限、本人確認・問い合わせ手順、完全オフラインの練習画面への制限可否、不正ログイン対策の詳細。旧端末紛失時に端末内データを無条件復元することや、初期版で営業途中に別端末へ移れることは保証しない。
