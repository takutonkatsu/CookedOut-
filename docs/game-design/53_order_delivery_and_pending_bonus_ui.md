# COOKED OUT! 注文状態・配送・保留ボーナスの表示 v0.2

- 作成日: 2026-09-13
- 状態: 未発送票と配送状況の分離、次の準備対象、落下状態、確定スコアと保留上乗せの分離を採用。ユーザー修正で自配達・代行は同じ配送状況欄へ集約し、自配達期限は数値時計ではなくバーを第一方針にする。寸法・バーの詳細・案内操作は未確定・未実装
- 前提: iOS横持ち、既存17の基本配置、注文自動発生、初回出荷準備順コンボ、配送中別期限、上乗せ保留支払、全納品／時間切れで自動帰還
- 後続変更: 54のユーザー指定により、路上の落下パックへの注文番号・追加目印は不採用。以下の回収位置マーカー案は使わず、本体デザインと散乱配置で視認性を確保する。注文票・荷台一覧の番号は別の情報として維持する

## 1. 厨房の注文票は未発送を中心にする

| 状態 | 見せる情報 | 配置案 |
|---|---|---|
| 未準備 | 完成料理・材料・行先番号・注文タイマー・基本点 | 上中央の通常注文票 |
| 積載済み、まだ乗車前 | 通常票に荷台印と準備判定済み印。注文タイマーは進む | 通常票の位置を維持 |
| 初回積載後に取り出した | 注文対応と準備判定済みは維持、荷台印は外す | 通常票に実際の状態を反映 |
| 自配達で発送済み | 行先・残件数・配送期限・配達者の顔 | 配送状況へ縮小して移す |
| 代行受付済み | 配送中件数・各到着見込み | 自配達と同じ配送状況欄へ縮小して移す |
| 納品済み | 納品演出、確定加点。必要なら上乗せ保留 | 通常票は消し、保留はスコア側へ集約 |

積載済みだからといって注文タイマーを消したり、新規注文の枠を空けたりしない。乗車して発送した時だけ通常票から移す。積荷を取り出しても準備判定をやり直す表示にはしない。皿・容器上で完成しただけでは準備判定済み印を付けない。

未発送上限の候補は3〜5件だが、配送中は別枠なので全件を同じ大きさで並べない。自配達・代行を別パネルや別タブにせず、一つの配送状況欄にまとめる。運ぶプレイヤーの顔と代行マークで区別し、詳細表示・配送単位のまとめ方は54で検討する。関係ない人数分の空き枠は表示しない。担当者を事前割当する機能は作らず、実際の配送状態だけ示す。

## 2. 次の準備対象を明示する

未判定で最も古い注文に「次」の印と輪郭を付ける。色だけに依存しない。準備済みの古い票が配送待ちで残っていても、その票を再びコンボ対象のように強調しない。

正順で初回受理した時に短くコンボの反応を出し、記録倍率を示す。これは注文順の評価であって得点加算ではないため、スコアへ飛んで入る演出は納品・上乗せ確定時だけにする。未判定の票に今のコンボで正順準備した場合の倍率を表示するかは密度検証後に決める。

出荷順と配送経路を分け、運転中の地図に古い順を強制する印は置かない。

## 3. 配達中は残件数と配送期限を主にする

- 選択中の行先と方向、残り件数を表示する。自配達期限は「あと○:○○」という数値時計ではなく、残り猶予を表すバーで示す方向。目的地までの距離や納品件数の達成率を表すバーではない。バーの増減方向・警告方法は54で提案する。
- 営業残り時間は既存の時計位置を維持し、配送期限と明確にラベル・形を分ける。同じ注文の準備タイマーと配送タイマーを二重に動かして見せない。
- ミニマップは右上、左下アクセル／ブレーキ、右下左右の既定配置を維持する。営業時間・スコア・積荷表示と競合しない寸法は後で実機調整する。
- 納品したら残件数が減る。事故で落としただけでは未納品件数は減らず、荷物アイコンを落下状態に変える。パックの位置を目印で確認できるようにする。
- 回収中は徒歩操作へ切り替わるが配送時計は維持する。回収するパックに注文番号を付け、再積載でも期限・コンボが更新されないことを示す。
- 全件完了なら完了表示から短い自動帰還へ。期限切れなら失注件数を短く示して帰還し、毎回の結果ダイアログは挟まない。

厨房の火災など離れた場所の緊急情報は既存の顔／状態アイコンと短い警告へ集約し、ライブ映像や常時大きな厨房小窓は追加しない。無関係な軽微通知を運転中へ連発しない。

## 4. 確定スコアと保留上乗せを混ぜない

メインのスコアは確定済み得点だけとする。自分の納品は済んだが根拠注文の完了待ちである上乗せを、スコア付近に小さく「ボーナス待ち +○」として集約する案。まだ一件も納品していない注文の見込み報酬全体を足した値ではない。

根拠注文がすべて届いたら、保留分をスコアへ加算する演出。根拠注文が失注したら該当の保留分を外すが、獲得済みスコアを取り消す「−○」演出にはしない。必要なら「ボーナス条件未達」と短く説明する。失注そのものの基本点50%減点は別のイベントとして区別する。

詳細を開けば、どの未達注文を待っているかを番号で確認できる案。普段から最大5件の根拠一覧を常時表示して読むことは要求しない。星到達演出には保留を足さず、確定スコアを使う。

既存の通常チップ最終四捨五入と、1.0倍分／上乗せ分の分割支払で合計がずれない丸め方を実装前に検証する。50の支払方式を採用したことが各部分の独立した二重丸めの許可になるわけではない。

## 5. ヒントを出す場面

- 初回積載: 「注文順の判定は最初の1回。出発までは注文時間が進みます」
- 初回の取出し: 「積み直しても順番の判定は変わりません」
- 初回の保留発生: 「関係する注文を届けると、ボーナスを獲得できます」

初回だけの短い非遮断表示を候補とし、後から遊び方で読めるようにする。操作が混み合っている時に強制停止・長文・確認ダイアログを追加しない。色・文字だけでなく印と動きで区別する。

## 6. 検証

- 準備済み票を見て注文タイマーが停止したと誤解しないか。
- 未発送3〜5票に配送中が加わっても厨房の盤面を隠さないか。
- 配送期限と営業時計の早い方までに届ける必要が分かるか。
- 積荷落下を納品完了と誤認しないか。
- 保留上乗せの獲得／失効と、通常の失注減点を見分けられるか。
- 帰還直後に入力配置が切り替わって誤操作しないか。
