# COOKED OUT! 問い合わせ・不具合報告の導線案 v0.1

- 作成日: 2026-09-16
- 状態: 2026-09-16、公開4点をユーザー承認で採用。設定／復旧エラーからの入口、短い報告と任意の調査情報・画像、受付確認と再送、報告だけで自動補填しない方針。窓口・返信手段・保存期間等は未確定。フォームや送信先は作成していない
- 既定: 正規終了結果の保護・再照会・重複付与防止を優先する。問い合わせをしただけで未確認の結果を正当と扱わない。自由文チャット・ゲーム内通話は今後も非採用。本書の運営への問い合わせ文はプレイヤー間チャットとは別

## 1. 設定内と、復旧できないエラー画面から入れる

設定内に「お問い合わせ」を設け、復旧できない結果確認・引継ぎ等のエラー画面からも同じ入口へ進める案。普通の通信失敗では先に再試行・状態確認を案内し、毎回報告を強制しない。

本番営業中に報告フォームで操作を塞がず、営業後に報告できる導線を基本にする。既知の障害がある場合は窓口手前で短い案内を示すが、それを読まないと送信できない強制手順にはしない。通信・サービス障害時の到達経路も設計する必要がある。

## 2. 短い説明と、任意の調査情報で報告できる

利用者は分類（不具合／データ・引継ぎ／意見・要望等）と起きたことを短く入力する案。再現手順・画像は分かる範囲の任意情報とし、技術用語やログファイルの手動取得を必須にしない。スクリーンショットは本人が選択したものだけを対象とし、勝手に撮影・添付しない。

「調査用情報を添付する」を選んだ場合は、アプリ版、端末機種・OS版、対象モード／ステージ、発生時刻、エラー識別子、問題の営業を照会するための識別子等、調査目的に必要な範囲をまとめて確認できる案。必要なアカウント識別子も公開プロフィール情報とは別に、窓口へだけ渡す。

パスワード・認証トークン・決済カード番号・端末の連絡先は求めず、無加工の全ログや画面録画・音声を自動送信しない。調査情報の添付を断っても、文章での報告は可能とする。調査用情報がなく原因を特定できない場合もあるため、復旧を保証しない。報告本文・添付をゲームバランス分析へ無条件流用しない。

## 3. 送信できたか分かるようにする

受付先から確認が得られて初めて「受け付けました」と表示し、問い合わせ番号等の参照手段を用意する案。送信が未完了・結果不明なら成功と表示しない。

入力済み内容は失敗時に保持し、再送で同じ報告を大量に重複登録しないようにする。報告を送信してもゲームの未同期結果を消したり、同期完了扱いにしたりしない。報告の受付状態と、営業結果の確定状態を別に管理する。

返信経路・問い合わせ履歴をゲーム内に持つか・窓口サービスは未決。問い合わせ番号の提示は受付の確認であり、全件個別返信や一定時間内の解決を約束する表示にはしない。

## 4. 報告だけでコインや星を自動付与しない

不具合を報告した回数に応じた報酬、未確認の損失申告だけでの自動補填は設けない案。まずサーバーに結果が確定しているかを照会し、既に受け取っている報酬を重複付与しない既定を維持する。

復旧や補填が必要な場合は、確認できる記録と別途定める運用基準に従う。正当な結果の復元と、障害へのお詫びの配布は区別する。未検証の申告からランキングスコア・星を作り出さない。金額・配布条件・承認権限は今回決めない。

## 5. 今回の範囲外

窓口サービス、返信経路、運用担当、対応時間、本文・画像・調査情報の保存期間と閲覧権限、本人確認方法、年齢・プライバシー・ストア要件への対応、アカウント削除／購入復元の具体手順。該当サービスや法的要件を採用するときは公式情報を確認する。今回の案を実装済み・規約適合済みとは扱わない。
