# COOKED OUT! 画面構成・厨房HUDレイアウト仕様 v0.2

- 更新日: 2026-09-11
- 状態: 厨房HUD、四操作、配達操作、ミニマップ、本店ホーム、結果画面の基本配置を決定。寸法は実機調整
- 前提: iOSのみ、横持ち、1〜4人オンライン、厨房全体固定カメラ、配達時は追従カメラ

## 1. UI全体の目標

1. 厨房とキャラクターを最優先し、中央へ恒常UIを置かない
2. 初心者が文字説明なしでも、注文、残り時間、持ち物、対象、失敗原因を理解できる
3. 経験者が視線を大きく動かさず、注文順、残り時間、スコア更新を判断できる
4. 左親指を移動、右親指を行動へ固定し、持ち替えを減らす
5. Safe Areaと手で隠れる領域を最初から設計へ含める
6. 通常営業、出張営業、常設ランキング、シーズン競技で基本HUDを共通化する

## 2. 主要画面の導線

```text
起動・認証
  ↓
本店ホーム
  ├─ プレイ
  │   ├─ 通常営業
  │   ├─ 出張営業 → 章 → ステージ → ソロ／ルーム
  │   └─ シーズン競技 → 競技厨房 → 自分の設備配置 → ソロ開始
  ├─ 店づくり → 設備購入・強化・配置プリセット
  ├─ 課題 → デイリー・ウィークリー・ログイン報酬
  ├─ ランキング → 常設／シーズン
  ├─ キャラクター → 動物・帽子・制服
  └─ プロフィール・設定
```

マルチプレイを独立した最上位モードにはしない。出張ステージから「ひとりで」「ルームを作る」「コードで参加」へ分ける。シーズンは通常営業の延長のソロ専用とし、人数選択・ルーム・招待・仲間の準備完了を設けない。

## 3. 厨房HUD第一案

### 3.1 情報領域

| 位置 | 常時表示 | 内容 |
|---|---|---|
| 左上 | 営業時計 | 残り時間。残り30秒で形、動き、音を変える |
| 上中央 | 注文票列 | 完成品、材料、個別タイマー、提供先。表示順がコンボ順 |
| 右上 | スコア | 現在値。自己ベスト接近時だけ短い差分演出 |
| 画面端 | 離れた仲間 | 配達中、事故、切断中の動物顔と状態印 |
| 対象物付近 | 状態表示 | 作業進捗、加熱、焦げ、火災、対象輪郭、提供不可 |

注文票は上端中央へ一列で置く。画面幅を超えるほど同時注文を出さず、縮小しすぎない。初期試験値は最大5枚とし、人数別負荷の実機試験で3〜5枚から確定する。

### 3.2 操作領域

「左右コーナー型」を採用し、次の配置とする。

- 左下: 固定位置の仮想スティック
- 右下中央: 最も大きい取る／置く
- 取る／置くの左上: 作業
- 取る／置くの上: 投げる
- 右端: ダッシュ
- ボタンは常に同じ位置とし、対象によって位置を変えない
- 押せない操作は消さずに弱く表示し、指の記憶を壊さない
- 作業長押し中の進捗は対象物の上へ表示し、指の下だけに情報を置かない

比較した「下部帯型」は厨房下端を広く隠し、右親指の移動距離も増えるため不採用とする。

## 4. 配達HUD第一案

- 左下: アクセルを大、ブレーキを小。移動量ではなく速度を担当する
- 右下: 左・右。右利きの多いプレイヤーが精密な操舵を担当する
- 左上: 積載している注文容器
- 上中央: 現在選択中の配達先と方向
- 右上: 道路、現在地、厨房、配達先を示す簡易ミニマップ
- 営業残り時間と現在スコアは左上の積載表示と競合しない細い上端領域へ置く
- 画面端: 厨房に残った仲間の動物顔、火災・切断等の緊急状態
- ミニマップには配達中の仲間も表示する。料理内容や細かな建物装飾は表示せず、道路判断に必要な情報へ絞る
- 道路上の目印と画面端方向表示も併用し、ミニマップだけを見続ける運転にしない

配達完了後は自動的に次の配達先へ固定せず、積載中注文から選べる余地を残す。選択方法はバイク操作試作後に決める。

## 5. ステージ選択とロビー

### 5.1 出張営業

- 章は横方向に並べ、選択章内の一本道ステージを中央へ大きく表示する
- 各ノードはステージ番号・最高星を中心とする。2026-09-13の変更で、開始前の盤面・ギミック印・動作例の公開は撤回。料理アイコンは許容候補、その他の事前表示範囲は[63](63_outing_preview_ready_and_start.md)で整理する
- 選択時に人数別自己ベストと常設順位を右側の詳細欄へ表示する
- 常設順位は星3基準以上の有効記録がある場合だけ表示し、未登録なら「星3でランキングに掲載」と示す。ランキング閲覧と人数別自己ベスト表示は星3未達でも可能。詳細は[66](66_outing_leaderboard_three_star_eligibility.md)を優先する
- 未解放ノードには解放条件だけを短く表示する

### 5.2 シーズン競技

2026-09-14更新：85・86を優先する。「4厨房」は本人の厨房と固定街で行う4つの営業課題。課題選択時に献立・個別料理・必要設備を確認でき、初回だけ本店配置を下書き複製して課題別に保存する。以後は保存配置を使用し、本店とは自動同期しない。不足設備を示す準備の後、成立済み配置なら編集を強制せず開始できる。

- 4厨房を一画面に並べ、未公開週、未挑戦、自己ベストを明確に区別する
- 上部に4厨房合計スコア、現在順位、残り日数を表示する
- 厨房選択後に、設備ロードアウト・配置編集へ進む
- 本人の設備・配置を確認してソロ開始。シーズンに協力ロビーを作らない

### 5.3 マルチロビー

- 最大4枠へ動物の顔、表示名、接続状態、準備状態を表示する
- ホストだけがステージ・配置を変更できる
- ゲストは変更内容を確認後に準備完了する
- 先行参加ステージでは「未解放」を警告ではなく情報印として表示し、参加を妨げない

## 6. 結果画面

全モードで次の順序を共通化する。

1. 星0〜3または完走状態
2. 大きなスコア
3. 自己ベスト更新と順位変化
4. コイン、経験値、初回報酬
5. リトライ、次へ、ホーム

常設ランキングではステージ内の順位、シーズン競技では週自己ベストと4厨房合計を追加する。競技スコアを単に「スコア」と表示し、換算前スコア、換算式、基準値は出さない。

## 7. ランキング画面

- 最上位タブ: 常設ステージ／シーズン
- 人数切替: 出張常設だけ1人／2人／3人／4人。シーズンには人数タブを表示しない
- 範囲切替: 世界／国内／フレンド
- 上位記録と本人周辺順位を同じ縦一覧へ表示する
- 常設協力ランキングをチーム名義にする場合、順位、動物顔2〜4個、表示名、スコアを一行にまとめる
- シーズンは本人のソロ記録のみで、各厨房の記録詳細に協力メンバーを表示しない

## 9. 実装時に調整する項目

- 注文票最大5枚で料理と材料が判別できる最小寸法
- 四行動ボタンの直径、間隔、右手内の優先順位
- ミニマップの寸法、北固定／進行方向回転、道路省略率
- Dynamic Islandとホームインジケータを含む端末別Safe Area
- 視線移動、誤操作率、二本指同時押し、長時間プレイ時の疲労
