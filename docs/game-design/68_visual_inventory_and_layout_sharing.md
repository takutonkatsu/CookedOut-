# COOKED OUT! 絵中心の設備一覧と配置共有リンク案 v0.2

- 作成日: 2026-09-13
- 状態: 絵中心の設備一覧、本店限定共有、69で公開した取り込み・保存方針は採用。不足位置は空白、ゲーム内リンク入力入口なしへ修正。技術構成の細部は提案。未実装

## 1. 設備一覧は「今、置けるもの」を見せる

厨房に配置したものは盤面そのもので見せ、下部の設備一覧には未配置の設備を見せる。選択した種類の未配置分を設備の小さな絵で並べ、配置すると一覧から一つ減り、収納すると一つ戻る。最大4台という上限内では実物の絵で数を表現しやすい。

9種類をすべて個体単位で横並びにして小さくしない。種類の絵を選び、その種類の残りを見せる。必要なら絵の隅に残り数を補助表示する。盤面の一台と一覧の二台で「一台使用中・二台置ける」が分かるようにし、常時の所有／配置／未配置という三列の文章は使わない。

未配置0でも種類の入口自体は消さず、空の輪郭等で残りなしを示す。未解放は鍵の形、所有上限・コイン不足等の理由は選択時に短く説明する。色だけで区別せず、絵の有無・枠形状・動きで伝える。Lv・価格・数量・購入確認の意味を曖昧なアイコンだけへ置き換えない。

## 2. 共有するのは本店の配置図

共有対象は通常営業の本店配置だけとする（採用）。以下の共有データ・導線の細部は提案：設備の種類、配置座標・向き、対応する厨房テンプレートと形式版を配置図として共有する。保存配置から共有ボタンでリンクを作り、ユーザーが任意に外部へ送る。自動投稿、公開ランキングや配置検索サイトは追加しない。

コピーしないもの: コイン、設備Lv、所有台数、店ランク、料理解放、報酬、注文、調理途中の材料、他人のセーブデータ。床・固定原料箱・水場・提供口等を勝手に変更できるデータにしない。献立・原料箱の中身も初期共有の対象外。器具と共通熱源の配置・付属品数は実際の配置保存形式に合わせる。

本店の配置共有は、出張ステージの事前盤面非公開とは別の機能。出張営業とシーズン競技の配置は共有・取り込み対象外。出張の作者指定盤面・秘密ギミック・ランキング用リプレイへ広げない。

## 3. 取り込みはプレビューから

URLを開く→ゲームで配置図を確認→自分の設備に照合→編集画面へ取り込み→必要なら修正→保存先を選ぶ、という案。

リンクを開いた瞬間に既存配置・保存3枠を上書きしない。最初は編集中の仮配置へ読み込み、保存時に空き枠または上書き先を選ぶ。全枠使用中でも既存の保存済み配置を勝手に捨てない。取消時は元の配置へ戻る。

足りない設備の位置は空白にする。輪郭・仮設備は表示しない。置ける設備は自分の所持分と自分のLvで配置し、未所有物・未解放物・超過台数を生成しない。自動購入はせず、所持分だけ編集・保存できる。選択献立の必須設備等が不足すれば営業開始不可とし、コピー元との完全一致は求めない。詳細は69を優先する。

本店未解放の受取人はコピーで本店を解放しない。案内を示し、解放後に同じリンクを開けるようにする。営業中にリンクを受け取っても営業の配置を変えず、保留して営業後に確認する。iOSで外部アプリを開くこと自体の中断は57の既定に従う。

## 4. iOSでの実現方法と制約

AppleのUniversal Linksを使い、HTTPSの共有URLからインストール済みアプリの該当機能へ遷移することは可能。アプリ未導入時はWebへフォールバックする。アプリとドメインの関連付け、およびアプリ側のリンク受信処理が必要。これは実現可能性の確認であり、本プロジェクトで設定済み・動作確認済みという意味ではない。

アプリ未導入のWebページにはインストール案内を置く設計案。インストール後の自動的な配置引継ぎを保証せず、初期版では同じURLを再度タップして取り込む導線を基本とする。ユーザー指定によりゲーム内の「リンクから取り込む」入口は設けない。開いたアプリやユーザー設定によってWebへ留まる場合のWeb側案内・再試行は技術検証事項とし、代替ボタンを無断追加しない。クリップボードの無断常時読取りは行わない。

データをURL内に格納する方式と、短い共有IDからサーバー上の配置図を読む方式を比較する。現段階で方式は確定せず、URL長、LINE等での取り扱い、保存量、悪用対策、保守費用を検証する。専用ドメイン／HTTPS配信・関連付け設定が必要となるため、無料・サーバー不要とは約束しない。

## 5. 安全性・長期互換性

共有リンクは信頼できない入力として、設備ID・座標範囲・向き・占有・固定セル・器具数・データ量・形式版を検査する。リンクを処理するだけでコードを実行、任意URLを取得、課金、権限変更しない。読めない／非対応の配置は短い理由を示し、現在のセーブを変えない。

リンクは作成時の配置を参照する固定スナップショットを推奨し、送信者の後日の編集に追従させない。個人のアカウント情報や本名は共有データへ含めない。リンクを知る相手へ配置が伝わり再共有され得ることは共有導線で扱う。公開カタログ・コメント・通報モデレーション機能までは今回新設しない。

ゲーム更新で厨房テンプレートや設備種が変わる場合は版対応を検査し、不適合を黙って誤配置へ変換しない。共有リンクの保存期限・削除・発行数制限はサーバー方式選定時に決める。

仕様と実現可能性の調査のみ。URL発行・ドメイン設定・外部送信・Unity実装・新規画像生成は行わない。
