# COOKED OUT! 配送終了時の自動帰還と再開 v0.2

- 作成日: 2026-09-13
- 採用: 配送期限・失注コンボ・上乗せ保留支払。全納品完了または配送期限切れで店へ自動帰還し、手動の帰路運転をなくす
- 後続承認: 短い帰還切替、バイクは元の駐車位置・料理人は荷台横に降車状態で復帰、演出中も営業進行、帰路時間の裏差引なし、失注パックの自動持戻し、閉店時は直接結果へ進む方針を採用。演出秒数・同時イベント・仲間の移載・空荷走行・任意帰還の詳細は未確定・未実装

## 1. 一回の出発が終わったら帰還

判定対象はそのバイクの一回の出発に紐付いた注文。チーム全員の配送、代行配送中、未発送注文の完了を待たない。全納品できた時は成功帰還。期限切れ時は未納品分の失注処理と保留上乗せ処理を行ってから帰還する。

最後の納品後に別の帰還操作を要求しない。成功でも失敗でも基本の帰還演出は短く揃え、失敗時だけ長い待ち時間を足さない。帰還にコインや広告は要求しない案。

## 2. 料理人は降車状態で店の荷台横へ

短い画面切替で、バイクは出発時の駐車位置、料理人はその横の安全な位置へ戻す案。帰還後に降車操作を挟まず、すぐ厨房の仕事へ戻れる。厨房カメラ・徒歩操作へ切り替え、運転の押しっぱなし入力が料理の廃棄・投擲等として誤発火しないようにする。

本店では本店、出張営業ではそのステージの厨房・発送拠点へ戻す。ステージから本店へ退出する機能ではない。複数人同時帰還でも料理人・バイクが重なったり通路を塞いだりしない安全な戻り位置を設ける。

帰還演出中も営業時間・加熱・注文・仲間の操作は通常どおり進む案。世界全体の時間を飛ばしたり停止したりしない。数秒以上の帰路を省略した分の時間を裏で差し引く方式にもせず、短い共通の操作切替だけにする。演出時間は実機で決める。

## 3. 時間切れの料理パック

その出発の未納品パックは、手持ち・荷台・路上のどこにあっても、自動帰還時に同じ現物として元の荷台へ回収して戻す案。事故回収は期限内に配送を成功させるため必要であり、時間切れ帰還は失注済みの失敗終了として区別する。タイムアウトを待って無料で成功配送を再開できない。

料理自体を自動廃棄しない既定方針と整合させ、失注した注文番号・配送期限・旧ボーナス権利は終了する。新規注文への自動再発送はせず、必要なら取り出して厨房で再利用・廃棄する。元の荷台枠を残ったパックが占めることを確認できるようにする。

路上のパックと帰還後のパックを二重に作らない。将来仲間が回収・移載できる仕様を入れる場合は所有権と帰還対象の整合が必要で、今回勝手に別出発の料理を引き寄せない。原則一出発の荷物だけを扱う。仲間の手持ちからの回収方法はその機能の採否と合わせて確定する。

## 4. 閉店が先なら結果へ

営業時間が終了した場合は、帰還して営業再開する演出を挟まず結果へ進む案。閉店時料理リセット・追加失注減点なし・保留上乗せの未達扱いは既定どおり。全納品や配送期限と閉店が重なる場合、納品・失注・帰還・営業終了を二重処理しない。同時刻の判定は51の境界検証へ統合する。

途中で任意に即帰還できるボタンは初期案では増やさない。事故・スタックから近くの安全な道路へ戻す復帰操作は、店への自動帰還とは別。配送を中断して帰る機能を追加する場合は失注と報酬の扱いを別途決める。

配送中はルートを自由に走れるが、全納品すると自動帰還するため配送終了後の寄り道はできなくなる。空荷で街を自由走行する場合のモード・時計は別の未決事項。注文ゼロを全納品と誤認して乗車直後に即帰還させない。自由走行モードを新設したと解釈しない。

## 5. 帰路廃止による調整

- 配送期限はもともと最後の納品までで算定する方針なので、帰路削除だけを理由に一律短縮しない。
- 厨房不在時間が減り、通常営業の処理量・失注率・得点/分・納品基本点/分が変わる。旧往復前提の時間や星基準、設備費用の営業回数目安を確定値として再利用しない。
- 自配達が代行より完璧プレイ時5〜10%程度高い得点/分という既存目標は維持し、自配達追加点係数は再検証する。先に一律の減額を確定しない。
- 一件ずつ配達する際の帰路負担もなくなるので、まとめ積載の優位性が縮む可能性がある。バイクLv1〜5の価値を、複数件の近接巡回・一回の出発準備負荷と合わせて確認する。容量を増やしたことによる追加の罰則は作らない。
- 期限切れ自動回収で失注料理を容易に回収できても、時間・失注減点・ボーナス失効を含めて、放置帰還が通常納品より有利にならないか検証する。
