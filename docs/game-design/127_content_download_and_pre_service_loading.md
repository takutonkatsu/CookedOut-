# COOKED OUT! ダウンロードと営業前の読み込み案 v0.1

- 作成日: 2026-09-16
- 状態: 未承認の相談案。利用者から見える待ち方を提案し、具体の配信サービス・容量・実装は決めない
- 2026-09-16追記: ユーザーの「初回インストールで全て取得できないか」という質問を受け、推奨案を全素材同梱へ変更。質問を採用指示とは扱わず、承認待ちとする
- 既定: マルチは最初から参加可、全員ロード後に3秒カウントダウン、盤面・ギミックは開始まで非公開。正式営業はオンライン、取得済みデータによる報酬なし練習は通信障害時も可

## 1. 初期版の全プレイ素材をアプリへ同梱する

初期版の全ステージ・街・料理・キャラクター・BGM／SE等、プレイに必要な素材をアプリ本体へ同梱する方式を推奨する。App Storeでのインストール時に取得を済ませ、起動後やステージ選択時の追加素材ダウンロードを原則不要にする。制作原本・調査資料・不要な高解像度素材までアプリへ含める意味ではない。

後半章へ初回から招待された場合も、素材取得待ちを挟まず準備へ進める。素材が端末内に存在することはステージや料理の解放・習得を意味しない。

## 2. 容量と将来の更新を別途確認する

全素材同梱では初回インストール容量が増える。対応端末別の配信サイズ・インストール後サイズと初回所要時間を実ビルドで確認する。現在のプロジェクトフォルダやGitのサイズから完成版のアプリ容量を推定・保証しない。

新章や新しい素材はアプリ更新へ含める案とする。最初のインストールだけで将来の未制作素材まで取得できる意味ではない。全素材同梱は、ログイン・報酬・ランキング・マルチ・広告等の通信不要を意味せず、既存オンライン方針は維持する。

Apple公式の2026-09-16確認時点では、iOS／iPadOSアプリの非圧縮サイズ上限は4GB。上限とは別に快適な導入サイズを目指し、超過や実用上の問題が判明した時に分割配信を再検討する。現時点で分割の実装を前提にしない。

参照: https://developer.apple.com/help/app-store-connect/reference/app-uploads/maximum-build-file-sizes

## 3. 全員が遊べる状態になってから時計を動かす

マルチの参加者欄に本人ごとの「読み込み中」「準備完了」を簡潔に表示する。同梱した素材をメモリへ読み込む時間は残る。読み込み完了だけで本人の準備ボタンを自動承認しない。アプリ更新が必要な場合は119の更新案内で扱う。

全員の必要データが揃い、既定の準備とロードが完了してから3秒カウントダウンへ進む。端末の遅い人を待つ間に営業時間・注文・調理を進めない。待ち画面には料理画像等を使い、厨房盤面・ギミックの事前公開はしない。営業に必須の素材を営業途中で追加取得して足止めする方式は避ける。

## 4. 読み込み失敗では準備や成績を失わせない

失敗時は再試行と戻る操作を用意し、可能な範囲で選択面・本人のキャラ選択を保持する。処理が止まっているのに進んで見える架空の進捗表示をしない。

開始前の失敗・取消を星0の営業、失注、報酬消費として扱わない。ロードの長期停止は部屋を無期限に閉じ込めず、開始取消でロビーに戻し再準備できるようにする。待機期限は実測後に設定する。人数変更・退出・既存の準備解除規則は維持し、営業が既に開始した後の切断は別の既定処理とする。

保存データと再取得可能な素材キャッシュは区別する。素材取得失敗を理由に進捗を初期化しない。キャッシュ整理・保存容量不足・アプリ更新との互換性の具体処理は実装設計の残件。
