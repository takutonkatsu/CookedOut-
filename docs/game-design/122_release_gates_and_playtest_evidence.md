# COOKED OUT! リリース判定と自動・試遊テストの役割案 v0.1

- 作成日: 2026-09-16
- 状態: 2026-09-16、公開4点をユーザー承認で採用。重大不具合が未解決なら公開しない、自動回帰、初期56面×1〜4人の成立・星3到達経路確認、初見者理解・実機視認性の試遊。具体端末・数値・試験人数等は未決。テスト実行・実装・日程変更は行わない
- 既定: 単体・一営業シミュレーション・ネットワーク・負荷・実機・試遊・保存移行等を組み合わせる。初期本編48面＋S8面、ソロは二キャラ切替、協力は2〜4人。テスト環境・本番は分離する

## 1. 公開を止める不具合と、後回しにできる見た目調整を分ける

再現または十分な証拠があるデータ消失、重複付与、進行不能、主要経路のクラッシュ、誤ったランキング計上、必須操作ができない問題は、未解決のまま正式公開しない案。外見上の問題でも料理を誤認する・操作対象が分からない・ボタンが押せないものは重大として扱う。

プレイ判断を妨げない軽微な装飾差・演出の磨き込みは別リストとし、理由と影響を記録したうえでユーザーが公開時期を判断する。既知問題ゼロと未発見も含めた不具合ゼロを混同せず、ゼロを保証しない。重大度を公開直前に都合よく下げて通過させる運用にはしない。

## 2. 正しさを繰り返し確認する部分は自動化する

料理・注文・発送・コンボ・失注・コイン・評判・昇格・解放について、既定の入力に対して期待結果が出る回帰テストを用意する案。正常完走だけでなく積み直し、配送失敗、低Lv反復、先行クリア、章追加、シーズン境界などの分岐も対象にする。

通信・保存では結果の二重再送、サーバー確定後の応答消失、再起動、端末切替、未同期下書き復帰を再現する。分析送信障害と結果確定障害の分離も確認する。テストで使う資産・記録・ランキングは本番に流さない。

失敗を検知した変更は、そのまま公開候補へ進めない。自動化が成功しただけで面白さ・初心者理解・スマホの操作感まで合格した扱いにはしない。具体テスト技術やCI構成は実装側で設計する。

## 3. ステージは人数別に成立を確認する

初期56面それぞれについて1・2・3・4人の基本成立を確認する案。対象は計224組合せであり、224回だけ遊べば十分という意味ではない。ソロ一人は二キャラ切替であり、二人マルチの成功を代用にしない。

各組合せで必要設備・動線・受渡し・料理工程が成立し、既定の条件下で星3へ到達できるプレイ経路があることを確認する。机上の理論最大点や高速シミュレーションだけで、タッチ操作でも達成可能と断定しない。難度分布と時間・点数は試遊を踏まえて調整する。

全ギミック時刻・全配置・全通信状態の網羅を保証することはできない。危険な組合せを優先し、修正の影響範囲に応じて再試験する。面別の具体合格表はステージ専用タスクで作成する範囲とし、本書で盤面を変更しない。

## 4. 初見者の理解と実機の見やすさは人が遊んで確認する

初見プレイヤーが開発者の口頭説明を受けずに、第1章で主要操作を理解し、料理・注文・操作対象を見分けられるかを確認する案。全員が初回星3であることは要求せず、混乱の原因が難度か説明不足か操作不良かを分ける。

経験者には段取り・配送経路・配置の工夫が得点や効率につながるか、通常営業で同じ行動しか選ぶ理由がなくなっていないかも確認する。クリア率だけで面白さを決めない。

少なくとも対象とする小さい画面・基準端末・性能が低い側の対応端末で、タッチ誤操作・視認性・連続プレイの動作を確認する。具体機種、FPS・メモリ・発熱等の数値目標、試遊人数・試行回数・初心者達成率はまだ決めていないので、公開前に別途合格値を定義する。

## 5. 適用段階と残件

上記の全56面・224組合せは正式リリースの対象範囲。Core Alphaは採用済みの第1章6面と通常営業の基本部分を対象にする。過去の2週間希望を、この文書で全56面完成の確約に変えたり日程を更新したりしない。

未実装の将来候補をテストのためだけに追加せず、初期版で実際に提供する機能を対象とする。マネタイズ等が確定したら購入・広告の追加試験を定義する。具体機種・数値・試験人数・負荷規模・セキュリティ確認・法務やストア適合等は残件であり、本書だけで公開条件すべてが確定したとはしない。
