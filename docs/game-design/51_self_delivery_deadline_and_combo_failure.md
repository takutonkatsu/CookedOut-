# COOKED OUT! 自配達の配送期限と失注時コンボ v0.2

- 作成日: 2026-09-13
- 状態: ユーザー承認により、一出発共通の配送期限、期限切れ未納品の失注・50%減点・共有コンボリセット、50のコンボ上乗せ保留支払との併用を採用。秒数・厳密な同時刻境界・細部UIは未確定・未実装
- 追加決定: 全納品完了または配送期限切れで店へ自動帰還する。手動で帰路を走る工程は廃止。帰還の演出・料理パックの返却等は52で相談する
- 維持する基本: 出荷準備順でコンボ評価、乗車時の注文タイマー停止・時間帯保持、自由な配送順、事故のパック散乱・回収、閉店延長なし

## 1. 準備の期限と配送の期限を分ける

注文発生から発送までの既存タイマーは乗車で停止し、緑／黄／赤の時間帯を保持する。自配達の初回乗車時から別の配送期限を開始する案。配送期限は注文時の時間帯・通常チップ割合を再計算するためには使わず、納品が有効かを判定する。

UIは状態に応じて準備中の残り時間か配送中の残り時間を見せ、同じ注文について減り続ける二本のタイマーを同時に読ませない。営業時間の時計は別に維持する。代行は既定の距離比例・受付時確定ETAによる自動到着を維持し、制御不能な配送失注タイマーを別に重ねない。

## 2. 期限は一回の出発につき共通

同時に積んで初回発送する注文は、同じ絶対配送締切を持つ案。遠近ごとにバラバラの締切を設定し、近場を先に回ることを実質強制しない。

期限の算定候補は、その出発地点から積荷の全届け先を道路で巡回する基準走行時間＋受渡しの標準時間＋迷い・小さな事故回収のための余裕。最後の納品から店への帰還時間は配送期限に含めない。最短巡回に余裕係数を掛けるか、固定余裕を足すかは実測で決める。1〜5件と行先構成を考慮し、全出発で一律同じ秒数にはしない。

一つのゲーム内日／営業で一つという意味ではなく、一回のバイク出発単位。マルチでは各出発単位の期限を管理する。固定条件競技は同じ積荷・道路条件に同じ算定規則を用い、恣意的な速度差やランダム猶予を付けない。

出発前に見込み配送猶予を表示し、初回乗車で確定する。速度・通行状況等の実測条件、事故回収の余裕は別途検証する。長距離注文を載せるだけで短距離分の猶予を不当に稼げないかも試す。

## 3. 事故・再乗車で時計を戻さない

- 初回発送のゲーム時刻と絶対締切を各注文へ記録する。降車、荷物落下、拾い直し、再積載、再乗車で締切を延長しない。
- 一件納品しても残りの締切を再計算せず、最初の共通締切を維持する。届けた注文は完了し、その後の期限切れの対象にはならない。
- 到着順は自由。事故自体で失注・コンボ切断にはせず、回収等で期限を超えた場合に失注する。
- 配送中注文の別バイク移載・追加の新規荷物を混載する仕様は未決。仮に許可しても元の注文の絶対締切をリセットできないことを条件とする。

## 4. 配送期限切れの処理案

配送期限が営業時間内に到来した場合、未納品の注文だけを失注とする。既定の失注を拡張し、その注文の基本点50%を減点、合計スコアの下限は0。その注文の納品得点・チップ・コインは得ない。配送失注そのものに加えて事故罰金・二度目の注文失注減点を重ねない。

共有コンボの連続成功数を0へ戻し、次の正順準備は1.0、次は1.5から再開する。既に初回準備判定済みの注文を未判定列へ戻して二重評価しない。同じ締切で複数件失注してもコンボは0へ戻るだけで、負の段階や累積倍率ペナルティを作らない。減点は未納品注文ごとであるため、最大5件の同時失注の厳しさを検証する。

現物パックは既定の失注時料理保持に合わせて自動消去しない案。失効した注文番号・目的地は無効として表示し、期限を延ばして同じ配送を再開できない。厨房へ戻した料理を将来の同一レシピ注文へ再利用する場合は別注文・別の正規発送として扱う。路上で失効荷物を別注文へ即付け替えて期限だけ延長する操作は第一案では認めない。回収・廃棄の具体UIは別途確定する。

## 5. 記録済み倍率と未配達対策

配送失注で共有コンボが切れても、ほかの注文の初回順序評価を遡ってやり直したり、既に得た得点を取り消したりしない。ただし未配達注文を倍率の根拠にした上乗せを払うかは、単純リセットだけでは解決しない。

50の保留支払案を併用することを第一推奨とする。期限切れ注文を根拠に含む未払いの上乗せは、その時点で獲得不可とする。根拠に含まない注文には影響しない。既に納品した注文の基本点・1.0倍通常チップ・自配達追加点・コインは保持する。根拠範囲は記録時の直近最大5件で、営業全体を永続的に止めない。

例: ①②③を正順準備、③→②が先に納品され①だけが配送失注。①は無報酬＋基本点50%減点。共有コンボをリセットし、①を根拠にしていた②③の上乗せは支払わない。②③の到着済み基本報酬は取り消さない。次の未判定注文の正順準備は1.0から始まる。

初回順番外だった④→取出し→③→④再積載→⑤という50の例では、⑤の上乗せ根拠は③⑤。④が配送失注しても共有コンボは切れるが、④を根拠にしていない⑤の上乗せを取り消さない。③⑤が必要条件を満たせば獲得できる。

この併用を採用する。配送期限だけを採用して50を採用しない簡易案では、期限内に他注文へ高倍率を付けて後で安い一件を失注させる戦法や、閉店で失注前に終える戦法が残る。基本点50%の減点だけで必ず損になる保証はない。期限は放置の抑制と運転の緊張感、保留支払は未配達を根拠にした報酬の防止、と目的を分ける。

## 6. 閉店との関係

有効な納品には配送期限と閉店の両方に間に合う必要がある。閉店が先に来た時は従来の閉店処理を使い、未納品は無得点・無コイン、閉店由来の追加減点なし。50を併用すれば未達注文を根拠にした上乗せも受け取らない。代行の閉店超過も同じ報酬条件。

配送期限が閉店より早い場合にのみ配送失注による減点を適用する案。両時刻が同じ場合、期限内納品を優先処理したうえで残りは閉店処理とする案。厳密な同時刻・通知遅延は共通ゲーム時刻で判定し、実装前に境界テストを定義する。画面の到着演出が遅れたことを失注原因にしない。

UIでは算定配送猶予が長くても閉店で先に終わることを明示する。閉店時間へ合わせて通常チップの緑黄赤を変えるものではない。

## 7. 決定済みと残る検証

1. 自配達に一出発共通の配送期限を導入する。
2. 期限切れ未納品へ既定の50%失注減点と共有コンボリセットを適用する。
3. 上乗せの保留支払を併用する。根拠となる直近最大5件の納品を待ち、未達ならその上乗せは獲得できない。
4. 具体秒数・余裕係数・最大積載事故復帰・閉店同時刻は検証後に確定する。
