# COOKED OUT! 閉店・最終配送・再営業仕様 v0.2

- 作成日: 2026-09-13
- 状態: ユーザー承認により、閉店まで注文供給継続、代行の閉店超過警告、閉店による追加減点なし、最終納品後の帰還不要、料理・火災・配送状態の営業間持越しなしを採用。再営業ボタンの詳細と厳密な終了同時刻判定は引き続き提案
- 対象: 仕様検討のみ。コード変更・実機検証は行わない

## 1. 維持する決定

- 通常営業は4分、開始前3秒カウントダウンを含めない。出張はステージ規定時間。
- 残り30秒でBGM・時計等を終盤表示にする。
- 発送確定で注文寿命・時間チップ・コンボを確定するが、得点・納品基本点は到着時に加算する。
- 閉店時未到着の配送は得点・営業コイン集計に含めない。終了後の配送待ち延長は設けない。
- 正規終了時に確定した納品基本点から報酬を一度付与する。

## 2. 終盤の注文供給

残り30秒等で一律に注文を止めるルールは最初の試験では設けず、通常の自動生成・成功補充規則を終了時刻まで使う。仕込み済みの料理を最後の新規注文へ合わせる余地と、早く処理した人の追加得点機会を残す。終盤だけ注文内容を簡単な料理へ差し替えたり、遠距離注文を飛ばして有利な次注文を出したりしない。

この案には、ゼロから調理しては間に合わない注文も終盤に出るという欠点がある。「表示された注文は全部間に合う」という保証はしない。閉店直前は全件対応ではなく、完成品・途中品と配送距離から最後に届けるものを選ぶ時間として扱う。

未発送票があるだけで暇対策を達成したとは扱わない。全料理が未着手かつ配送も間に合わず、実質的に待つだけになる時間が頻発する場合は、注文列・献立・配送先分布の設計を見直す。新たなラストオーダーモードやウェーブ操作は増やさない。

## 3. 配送判断を助ける表示

### 代行

受理前に確認できる所要時間と、営業残り時間を比較する。受理後の到着が閉店後なら「閉店に間に合いません」を表示する。確認ダイアログや別操作を増やさず、操作前の短い表示で伝える。警告を理由に自動で自前へ切り替えたり注文を入れ替えたりしない。受付自体の禁止は設けない第一試験案とする。

例: 営業残り20秒、代行25秒なら警告する。これは代行経路について到着予定が確定できる場合の判断であり、自前でも不可能とは断定しない。

### 自前

自前は運転・訪問順で実時間が変わるため、代行と同じ精度の断定をしない。既存のミニマップと営業残り時間を使い、推定時間を表示する場合も目安と明記する。最後の配達は届ければ成立し、閉店までの店への帰還は要求しない。

### 注文タイマー

注文寿命と営業残り時間は別。閉店が先に来る票について、緑の注文タイマーだけを見て余裕があると誤解させない表示を検証する。注文寿命を残り営業時間に強制短縮してチップや失注条件を変えることはしない。

## 4. 終了時の集計

| 終了時の注文状態 | 得点・納品基本点 | 終了による追加減点 |
|---|---|---|
| 既に提供・到着済み | 獲得済み分を維持 | なし |
| 発送済み・到着前 | 加算しない（既定） | なし |
| 未発送・注文寿命は残っている | 加算しない | なし |
| 営業中に注文寿命が切れた | 通常の失注処理 | 既定の基本点50%減点を適用済み。二重減点なし |

閉店は追加の失注イベントにしない。終盤に自動補充された注文を残しただけで、それまでの得点をまとめて失う状態を避ける。これは営業中の失注ペナルティを廃止する意味ではない。

判定には共通のゲーム内終了時刻を使い、閉店と同じ時刻に到着したものを含むかも実装前に統一する。推奨は到着時刻が終了時刻以下なら有効とする方式。オンラインでは画面への結果通知が遅れたことだけで期限内到着を無効にしない。境界前・同時・境界後・結果再送のテストを用意する。

## 5. 次の営業への移行案

購入済み設備・Lv・本店配置・所持コイン・評判・解放状態は維持する。一方、今回の注文・途中食材・完成料理・焦げ・火災・配送中状態は営業終了時に片付け、次の営業へ持ち越さない。出張の再挑戦は指定の初期状態へ戻す。

同じ営業内の仕込みは戦略として維持する。前営業で大量に仕込み、次営業の4分を完成品だらけで始める抜け道は作らない。報酬は既定の納品分だけで、片付けた食品へ別の罰金は設けない。

結果画面から「同じ条件でもう一度」「準備へ戻る」を選べる案。前者は同じ営業Lv・献立・厨房配置を保持した開始前確認へ進み、勝手に次営業を開始しない。通常営業のランダム注文を完全再現する種まで保持するかは別途検討し、出張・シーズンの固定注文条件と混同しない。

通常営業で評判上限や昇格条件が変わった場合も、同じ低Lv営業の再選択自体は認める既定方針を維持する。獲得できるのがコイン・星更新のみで評判対象外なら開始前に表示する。

## 6. 検証項目

- 残り30秒で新規注文が出ても「全件片付けないと追加減点」と誤解されないか。
- 残り時間・代行到着予定・未発送票の寿命を区別できるか。
- 仕込み済み料理で最後の一件を狙えるか。無意味な注文表示だけになっていないか。
- 店へ帰らず最終納品した場合、結果遷移が自然か。
- 閉店後の配送待ち演出が次のプレイを遅らせないか。
- 到着と終了の境界処理・再接続・結果再送で得点やコインが二重計上されないか。
- 料理と配送枠が次営業で正しく初期化され、購入設備や配置は消えないか。
