# COOKED OUT! 本店設備の購入・収納・配置フロー仕様 v0.2

- 作成日: 2026-09-13
- 状態: 2026-09-13ユーザーが文字中心の台数表示を修正し、その他の公開仕様を承認。購入は未配置在庫、無料収納、営業中の在庫交換なし、配置取消と購入取消の分離、初期の売却なしを採用。絵中心の具体表示は68で提案。未実装
- 前提: 本店12×9、配置保存3枠、種類別Lv、必要設備は献立依存。所有と配置を分け、必須不足時は営業開始不可、推奨未満だけなら開始可能という既定を維持する

## 1. 買った設備は所有一覧へ追加する

追加購入・初回付与した設備は所有一覧に入り、未配置として保管される案。厨房へ自動配置したり、既存設備を勝手に押し出したりしない。購入後に希望すれば配置画面へ進めるが、既存プリセットは自動上書きしない。

厨房が満員でも種類ごとの所有上限内なら購入でき、未配置として保持できる。購入前に「今回は未配置になる」ことを示し、買えば今の厨房で即座に使えると誤認させない。未所有設備を必要とする献立は既定どおり通常の選択候補に出さず、購入を営業途中に迫らない。

「所有3台・配置1台・未配置2台」という文章中心の表示例は撤回し、盤面上の設備と、一覧に残る設備の絵・必要最小限の数字で把握できる方向にする。具体案は68を参照。種類Lvを上げると、収納中も配置中も同種全台へ適用する。所有上限は配置中＋未配置の合計であり、収納で上限を回避しない。

## 2. 収納は無料、倉庫へ歩かない

営業前の配置画面で、設備を一覧へ戻すと収納できる。取り出し・収納にコイン、待ち時間、収納枠課金を加えない。種類ごとの所有上限とは別に、全種類合計の倉庫容量を設けない案。

物理的な倉庫部屋や、設備を運んで街へ出る工程は作らない。「持っているが今回は置かない」を設備一覧だけで扱う。営業中は収納一覧の呼出し、買い足し、倉庫との交換をできず、厨房に出した設備を運ぶ既定の可搬操作だけを使う。

収納しても種類Lv・所持台数・昇格条件の達成は失われない。配置している9種類すべてをチェックするのではなく、昇格の種類Lv条件と献立の必須配置を分ける。

## 3. 配置は気軽に試せるようにする

既存のタップで設備選択→置ける枠を表示→タップで設置という操作を維持し、ドラッグを必須にしない。無効な場所へ無理に設置しない。必須設備を外すこと自体は編集途中として許し、足りないまま営業開始することを止める。

編集の「元に戻す」は設備の配置だけを戻す。コイン購入や種類Lv強化の取引を巻き戻すボタンにはしない。保存または破棄を選ぶ前に画面を離れる場合、変更がある時だけ確認し、変更なしなら確認を増やさない。

保存は既存3枠へ明示的に行う。プリセットは配置参照であり、呼び出して所有数を増やさない。献立不適合な配置を選んだ時は不足設備を示し、元の保存枠を削除したり自動購入したりしない。器具を別本体へ共用する61と矛盾しないよう、熱源・ジャー・トレー等の付属品数も検証する。

## 4. 購入・強化の確認と売却

コインを使う直前に、設備名・追加台数または強化Lv・価格・購入後残高を一度確認する案。追加購入と種類強化は別の操作として示す。無料の収納・設置には毎回確認を出さない。上限到達・未解放・コイン不足を区別する。

初期版は設備売却・下取り・任意の強化取消を設けない案。無償で収納して別献立へ使い回せることを基本とし、強化済み設備を売って昇格条件や所持数が巻き戻る複雑さを避ける。余分な台数購入のコインは任意返金されないため、購入前の確認を明確にする。将来売却を追加する余地は残す。

通信失敗は任意取消と区別し、既存の取引IDによる再照会・二重引落し防止を使う。成功不明のまま別取引を繰り返して重複購入しない。今回の仕様提案だけで実際の購入・課金・返金処理を行わない。

## 5. 検証

満員厨房への追加購入、未配置設備のLv更新、収納しても所有上限が変わらないこと、必須設備の収納→別設備配置→取消、購入後の配置取消、保存済み配置の呼出し、共用付属品数の保存、営業中の倉庫呼出し不可、通信再送時の二重引落しを確認する。

価格、各面構成、動的厨房の初期配置、オーブン・フライヤー本体を営業中に動かせるかは今回決めない。文書のみ更新し、Unity UIや経済DBを変更しない。
