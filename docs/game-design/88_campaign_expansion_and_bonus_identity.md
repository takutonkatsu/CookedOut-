# COOKED OUT! 出張営業の拡張対応と独立ボーナス枠 v0.1

- 作成日: 2026-09-14
- 状態: 2026-09-14、S-1〜S-8、最新本編章クリア必須、月末シーズン切替と新章正式公開の同期、開催中条件・過去実績保全、必要進行・料理習得も参加判定へ含める公開方針を採用。内部IDは実装前から分離する。具体の判定・運用例外等は保留、未実装
- 今回はゲーム仕様と設計要件の整理。現行コード・セーブ・通信の対応可否を検証したものではなく、実データの改番や移行は行っていない

## 1. 旧第9章を「スペシャルステージ」として独立させる案

本編の第1〜8章と、章番号に含めない独立ボーナス枠へ分ける。面の表示番号S-1〜S-8はユーザー承認済み。名称は引き続き「スペシャルステージ」、短いUIラベルは「スペシャル」を案とする。

旧9-1〜9-8は既存8面の表示先を変更するだけで、新しいステージとして作り直さない。将来追加する本編の第9章・第10章は、本編番号の続きとして9-1〜、10-1〜を使える。初期56面という数は初期収録量であり、生涯の上限ではない。

旧ボーナスの役割と既定の条件は維持する。

- 本人8-6星1までは独立枠をマップへ表示しない。ロック付きの名前や一覧の先行表示もしない
- 初期の各ボーナス面は対応する第1〜8章の6面すべて星3＝18星で個別選択可能。星を消費しない
- 解放済みホストから招待されたゲストは本人未解放でも参加でき、正規の記録・報酬を保持する。本人のマップ・選択解放は別条件
- ボーナスは通常営業・店ランク・シーズンの必須条件にしない
- 旧「9-9は作らない」は、初期ボーナス8面の後に追加最終関門を設けないという意図として維持。本編追加章や将来のボーナス追加を永久に禁止する条項にはしない

## 2. シーズン参加には最新本編章クリアを要求する（ユーザー指定）

後続90の更新で、店ランクと通常営業Lvの参加条件も当該シーズン開始時点の最新上限へ連動させると採用。以下の20固定や連動未決の記述は旧経緯として残し、初期20、第9章追加時22、第10章追加時24を正とする。最新章・必要進行・料理習得の条件は維持する。

シーズン参加条件を「本人の店ランク20＋本人の通常営業Lv20星1＋最新本編章のクリア」に変更する。シーズンに登場する料理を習得済みにするため、8-6を恒久的な参加条件に固定する旧案は撤回する。初期の最新章は第8章なので8-6、第9章追加後は第9章クリアが必要。追加章の最終面数は今回固定しない。

ソロ・協力の正規クリアは従来どおり認める。Sステージは最新本編章に含めず、シーズン参加の必須条件にしない。第9章以降を「シーズン参加者にも永久に任意」とする前案は撤回する。初期本編の区切り・エンディングと既存18→19の昇格条件は8-6のまま据え置き、今回の参加条件変更を店ランク全体へ自動拡張しない。

後続ユーザー指定で、本編1章追加ごとに店ランク・通常営業Lv上限を各2段階増やす（90）。店ランク20を恒久上限とする部分は撤回するが、設備Lv上限5は変更しない。追加料理・設備の導入順を最新章の参加条件と整合させる。以前にシーズン参加済みでも、新しい必要章を未クリアなら新条件を満たす必要がある。反映時期は第7節の公開方針を採用し、確定済みスコア・バッジ・報酬を新章未クリアだけで消さない。シーズン参加の店ランク／営業Lv20条件まで最新上限に連動させるかは別途判断する。

最新章の最終面だけを招待で先行クリアしても、前の面で学ぶ料理が未解放の可能性があるため、シーズン参加判定は最終面の記録一つだけでなく、そこまでの必要進行と出題料理の習得も含める方針を採用。先行クリア自体の記録・報酬保持と再クリア不要は維持する。必要進行・派生レシピ等の具体リストと判定詳細は未確定。

## 3. 達成済みバッジと星の見せ方を守る案

初期ボーナス制覇バッジは、初期8面という固定集合を対象にする。新しくボーナス面を追加しても対象へ自動追加せず、既存バッジを未達に戻さない。追加分は別の達成目標・追加バッジとして設計できるが、その報酬内容は別途。

表示は「第1〜8章の達成」「追加第9章の達成」「初期スペシャル8面の達成」のように対象範囲を区別する。章別の星数は各章の面定義から計算し、全ステージ総数の56や最大星168をプログラムへ埋め込まない。初期セットの最大値は人数別168、全人数672のまま保持し、追加分は別に増やす。

既存の星・自己ベスト・正当なランキング記録・初回報酬履歴・バッジを引き継ぐ。新章追加だけで既存ランキングを分け直さない。既存面の比較条件を実質変更した時だけ77の条件版分離を適用する。

## 4. 表示番号と保存用IDを分離する設計要件

保存・報酬・ランキング・招待では表示番号ではなく、変わらないステージIDを使う。所属カテゴリ、本編章、表示番号、表示順、前提条件、初回報酬、必要コンテンツ版を別々に管理する。

ユーザーから関連実装はまだほとんど行っていないと確認されたため、現在の移行作業は不要。最初からS-1と本編9-1に別の不変IDを与えて設計する。将来の改名でも記録・報酬履歴を維持する。実装されていない既存セーブを想定して移行コードを作らず、現段階では保存キーの設計と将来の回帰検証を優先する。

章リスト・ステージリストはデータから読み、末尾へ章を追加できるようにする。前提条件の循環・参照先欠落・ID重複・報酬重複・人数別星基準欠落を公開前に検出する。

## 5. バージョンの違う友達との参加を安全に扱う案

追加面の必要データ・機能に両者が対応していることを、営業開始前に確認する。ゲスト未解放でも招待参加できる既定と、アプリにステージデータがない状態は別問題。

対応していない場合は更新が必要と案内し、読めない面へ突入させない。互換性が確認できる既存面は引き続き一緒に遊べる設計を目指すが、全てのアプリ版の組合せを永久対応する保証はしない。同じ面名でもルール・必要データ版が違えば同一営業へ混ぜない。

追加方式はアプリ更新への同梱をまず許容する。既存の仕組みで表現できる盤面・レシピデータと、プログラム追加が必要な新ギミックを区別し、あらゆる追加をアプリ更新なしで配信できるとは約束しない。具体配信技術は実装設計時に選ぶ。

## 6. 拡張前提の受入テスト

- 初期版のクリア済み・途中・未解放・先行招待済みセーブを更新して、記録と選択条件が維持される
- 旧ボーナス表示変更後に新本編第9章を追加しても、ID・星・報酬・招待が混線しない
- 新章追加後も本店解放・既存昇格・既得バッジを維持し、シーズン参加だけが指定時期に最新章条件へ更新される。旧シーズンの正当な記録・報酬は保持する
- 新旧アプリ混在・不足データ・通信切断・結果再送で、二重報酬や記録破損が起きない
- 章数を増やしても選択画面・星集計・ロード・メモリが破綻しない

初期56面の完成時に、検証用の追加章データでも上記を確認することを推奨する。正式な第9章の内容を今すぐ決める必要はない。

## 7. 新章追加とシーズン切替の同期（公開方針を採用）

追加本編章の正式公開を月末21時のシーズン切替に合わせる。新シーズンは新しい最新章クリアを要求し、その章で習得する料理を出題可能にする。条件未達者は新章を進め、必要条件を満たした後に公開済み課題へ参加できる。毎月必ず新章を作る義務ではなく、追加する月の公開タイミングをそろえる方針。

開催中シーズンの参加条件・献立・記録は途中で変更しない。コンテンツ更新の配布と章の正式公開は別とし、必要データの準備完了を確認してから公開する。具体的な配信技術・運営日程は未確定。

「シーズン開始時点の最新本編章」をそのシーズンの必要章として保持する。月途中の緊急公開等が必要なら適用方針を別途決め、ユーザー承認なしに旧条件での恒久参加を許可する抜け道にはしない。

この案は新章公開直後に攻略してから競技へ入る流れになり、開始直後の競技参加は遅れる。公開済み課題が終了まで残る既定を使って追いつけるようにする。新章の攻略量・シーズン期間の負荷は検証する。
