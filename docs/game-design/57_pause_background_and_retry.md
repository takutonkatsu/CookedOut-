# COOKED OUT! 一時停止・アプリ中断・途中リトライ仕様 v0.2

- 作成日: 2026-09-13
- 状態: 2026-09-13のユーザー「よいです。次に行きましょう」により、公開したソロ全体ポーズ・明示再開・背面復帰と終了の区別・マルチ継続・途中リトライ方針を採用。未実装。本文の「案」は提案時の記述であり、この承認範囲に限り採用として読む。具体秒数、障害救済、セッション期限、端末・バックエンドの整合は検証待ち
- 既定: 通常営業4分、ソロ出張二キャラ、マルチ途中新規参加／任意退出なし、マルチ切断でも営業継続、正規終了時のみ報酬、ソロの一時通信断は営業を最後まで続行して結果同期待ちが可能。連続営業は一時停止可・初期版はアプリ終了後の途中再開なし

## 1. ソロは営業全体を一時停止できる案

通常営業・ソロ出張・ソロのシーズン競技を含め、一時停止を許可する第一案。ポーズ中は営業時計、注文、配送期限、代行到着、加熱、ギミック、物理移動を一緒に止める。片方の料理人だけ止める操作ではない。

ソロ出張のキャラクター切替では時計が進む既定仕様と区別する。一時停止中は調理・運転・配置・行先変更等のゲーム操作を受け付けない。盤面は不透明なポーズ画面等で隠す案とし、停止した盤面を自由に操作・拡大して最適化する画面にはしない。

一時停止しただけでソロの星・報酬・ランキングを無効にしない案。全員同じポーズ条件を使い、時間の評価は実際のゲーム進行時間に基づく。ポーズ中に考える時間そのものを完全に防げるとは主張しない。より厳格な無停止ランキングを追加するなら別方針として検討し、隠れた失格条件を設けない。

## 2. 復帰は明示操作で行う案

一時停止から戻る時は再開を押し、短い再開予告を経てゲーム時計を動かす。具体秒数は試作で決める。端末の画面が戻っただけで、いきなり運転や加熱が再開しない。

ポーズ前の入力を持ち越して勝手に投げる・廃棄する・アクセルが入り続けることを防ぐ。作業進捗や停止時の世界状態は保持し、巻き戻しはしない。状態保存・再開と継続作業入力の関係は実装前にテストする。

## 3. アプリ切替と終了を分ける案

ソロでアプリが背面へ移った時は、可能なライフサイクル通知で一時停止に入り、同じ営業状態が保持されていれば戻った時に再開画面を出す。背面でプレイ時間だけ進ませて事故・失注させない設計とする。

ただしアプリ切替で状態が必ず保持されるとは約束しない。アプリ終了・クラッシュ等で営業状態を失った場合、初期版はその営業の途中再開をしない案。既存の設備・コイン・進捗は維持し、開始前の準備へ戻る。保存されていない今回の営業報酬を勝手に付与しない。既に正規終了し結果送信だけが残っていた営業は、未完了営業と区別して結果の再送・二重付与防止を行う。

終了時の復旧可能性、長時間休止の認証・セッション期限は要検証。クラッシュと任意終了を端末申告だけで確実に区別できるとは扱わない。障害救済は既定の方針に従って別途具体化する。

通信だけが一時切断し、アプリと営業が動いている場合は、既定のソロ継続・結果同期待ち方針を維持する。ポーズ導入を恒久オフラインプレイ解放や、広告・認証要件の変更と解釈しない。

## 4. マルチでは個人のポーズで世界を止めない

メニューを開いても営業時間・注文・配送・仲間の操作は継続し、「営業は進行中」と示す案。本人の操作入力はメニューに切り替わり、運転等の入力持越しを解除する。アプリ背面移行で操作できない間も営業は止めず、通信が切れた場合は既定の切断・安全停止・再接続処理を適用する。

全員の同意を取るマルチポーズや、ホストだけが強制的に営業を止める操作は初期案では追加しない。ゲーム中の人数・注文難度・星ラインを切断で変えない既定仕様を維持する。再接続の試作猶予60秒と報酬救済の既定は変更しない。

## 5. 途中リトライと終了

ソロのポーズ画面には「再開」「最初から」「営業をやめる」を置く案。最初から／やめるでは、今回の営業の報酬を受け取れない確認を一度だけ出す。単なるポーズ解除では確認を増やさない。

任意に途中でやめた営業は、今回のコイン・評判・星・記録を確定しない。既に過去の営業で獲得したものまで没収しない。前半だけ高速で納品してリトライし報酬を回収する方式にはしない。

通常営業の最初からは営業Lv・献立・配置を維持して、新しい注文順・配達先で開始する案。出張・シーズンの固定条件挑戦は同じ固定条件へ戻す。途中の料理・火災・荷物・配送・保留上乗せは初期化する。再生成目的のリトライで有利列を探すコスト・偏りは検証し、今回新たな回数制限・広告・料金は設けない案。

マルチは途中の個人退出を通常操作にしない既定を維持し、一人の操作で全員をリトライさせるボタンも設けない案。再挑戦・メンバー変更は営業終了後にロビーで行う。アプリ自体を終了できなくする意味ではない。

## 6. 検証

- ポーズで全時計・全物理・非操作作業が同じ時点で止まり、復帰で配送期限がずれないか。
- 正常ポーズ、背面化、通信のみ切断、プロセス終了、正規終了後の同期待ちを混同しないか。
- ソロのポーズと二キャラ切替、マルチのメニュー表示の違いを理解できるか。
- 順番判定や保留上乗せの直前・直後に中断しても、報酬が二重付与されないか。
- 復帰でアクセル・作業・投げ等の入力が勝手に継続しないか。
- サーバーが扱う時刻・注文ログ・結果検証とポーズ区間を整合できるか。シーズン・連続営業のランキング条件を揃えられるか。
