# COOKED OUT! 週次ミッションを省くデイリー具体案 v0.1

- 作成日: 2026-09-14
- 状態: 2026-09-14、ユーザー指定でデイリーの具体検討を後日に保留。以下の内容・固定方式・引直し廃止・切替時刻・自動付与は未承認、未実装。週次ミッションの初期版不採用も確定扱いにしない
- 既定: シーズンは月次4課題で、毎週1課題公開。毎週リセットするランキングへ変更しない。デイリーは2件・各80コイン・全件追加50という既定報酬を使う

## 1. シーズンとデイリーの二つに整理する案

週単位の目標はシーズンの課題公開が担うため、別の週次ミッション4件は初期版から外すことを推奨する。旧週次各250＋全件300コインも、不採用なら配らない。他報酬へ自動上乗せせず、収入バランスは別途確認する。

シーズンは育成後の競技、デイリーはその日の気軽な追加目標とする。シーズン未解放者には週単位の別ミッションがなくなるが、初期は日次目標・本店成長・出張進行で遊びを支える案。旧7日周期の連続ログイン報酬は別制度であり、今回の週次整理だけでは変更しない。

## 2. 初期は毎日同じ固定2件にする案

| ミッション | 条件案 | 既定報酬 |
|---|---|---:|
| 営業を1回終えよう | 有効な提供・配達が1件以上ある営業を正規終了 | 80コイン |
| 料理を10食届けよう | 当日の対象営業で提供・配達を合計10件完了 | 80コイン |
| 2件とも達成 | 上記両方を達成 | 追加50コイン |

一日のデイリー報酬上限は210コイン。通常の納品報酬・星に応じた評判・ログイン報酬等とは別枠。日次上限はこの追加報酬だけであり、通常営業のコイン収入を制限しない。デイリーから評判を追加しない。

10食は試験候補で、料理や人数による所要時間を実測して決める。毎日2営業必須ではなく、一営業で10食なら両方を達成できる。標準1〜2営業程度、1営業4分なら4〜8分のプレイを目安とするが、初心者や難しい献立でそれ以上かかる可能性がある。

同じ2件を毎日出すことで、課題確認のために献立や配送方法を変える手間をなくす。一方、日替わりの意外性は少ない。初期は気軽な追加報酬という役割を優先し、変化は普段の献立・出張・シーズンに任せる。

固定2件とする場合、既定の一日一回無料引直しは不要なため廃止する案。固定方式と引直し廃止はセットで承認を求めるもので、現時点で既定を無断撤回しない。

## 3. カウントの具体例

- 1回目に6食納品して正規終了：営業1回を達成して80コイン、料理は6／10
- 2回目に4食納品して正規終了：料理10／10で80コイン、全件達成50コイン。日次合計210コイン
- 1回で10食納品：その営業終了時に2件と全件分で210コイン
- 料理を作ったが提供・配達未完了：納品数へ加えない
- 納品が0件の放置完走：営業回数にも加えない
- 星0や失注があっても、有効な納品と正規終了がある：その納品と営業回数は対象にする案
- 同じ料理を繰り返し納品：それぞれ別注文の成功なら全て数える。種類数10種類を要求しない

数字の進捗と報酬は営業終了時の正規結果で確定し、途中リタイア・報酬なし練習は対象外。新しい営業で失敗しても前回までの確定進捗を消さない。無操作の協力放置等を正規参加として扱うかの判定は別途必要であり、納品1件の条件だけで不正対策が完了するとはしない。

## 4. どの遊び方でも進むようにする案

通常営業、ソロ・マルチ出張、参加可能なシーズンの正規営業を対象にする。現地提供・自前配達・配送代行を同じ成功納品として数える。同じ日のモード跨ぎでも合算する。特定料理・設備・星数・シーズン参加を必須にしない。

協力出張では、正規参加者にその回のチーム納品数を反映する案。最後に提供した人だけを評価せず、切る役や皿洗いの役も同じ進捗を得る。チーム10食を4人で40食と数えるのではなく、各人へ10食ずつ反映する。

初回チュートリアルも正規結果なら対象にできる案。デイリーを見る操作や受注をしなくても自動で進める。解放演出や詳細説明を初回起動時へ追加しない。

## 5. 表示・更新・受取の初期案

表示名は「デイリーミッション」を候補とし、週別のシーズン営業課題と区別する。ホームで料理アイコンと6／10等を簡潔に表示し、条件の詳細はタップで確認する。営業中の達成ポップアップで操作を遮らない。

達成報酬は営業結果の検証後に自動付与する案。受取ボタンを作らず、日付が変わっても付与済み報酬は失わない。再送による二重計上・二重付与を防ぐ。

切替は毎朝5:00日本時間を候補とする。深夜0時の境界を避けるための初期案で、シーズン切替の月末21時とは別。未達進捗は次の日へ持ち越さない。通常のアプリ内の1日の演出とは区別する。

日付をまたぐ営業の対象日、通信保留結果の遡及、自動付与失敗の再処理はまだ確定しない。アプリを開いた時刻で一律に判定して旧日の正当な達成を消す方式にはせず、結果の所属日を一意に決める必要がある。
