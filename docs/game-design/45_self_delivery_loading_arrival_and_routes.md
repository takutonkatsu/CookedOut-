# COOKED OUT! 自前配達の積載・到着・経路案 v0.1

- 作成日: 2026-09-13
- 状態: 次の相談案。追加操作・到着条件は未承認・未実装
- 後続変更: 最新は46。積載は置く・乗車は作業ボタン。同地点の複数注文とまとめ納品は避ける方向。最寄り優先ではなく古い注文優先の案内とする。自配達チップは到着順で確定し、発送時確定・到着順で再計算しないという以下の旧案は撤回。停車で自動納品などの残りの提案は未承認のまま
- 前提: バイクLv1〜5で容量1〜5。積載だけでは発送せず乗車時確定。到着時得点・コイン対象。徒歩配達なし。詳細な運転物理・事故は別途

## 1. 注文時点で行先を知る

注文発生時に目的地確定・表示する既定仕様を維持する。街で道路から到達可能な配達地点を建物ごとにあらかじめ設置し、その中から通常営業では偏りを抑えて抽選する案。建物内部探索・NPC会話は不要。出張・シーズン競技の配達先は競技用の固定条件を維持する。

注文票と地図の同じ行先を番号や形で対応させ、色だけに依存しない。厨房での表示は注文票の小さな行先記号、必要時に開く地図を基本案とし、常時大型地図は置かない。配達代行の見込み時間は既定どおり受理前に確認可能にする。

距離区分は情報の補助であって得点・時間を単純な3値に丸める仕様ではない。代行時間の道路距離比例は維持する。具体記号・地図位置・距離表示の粒度は試作で決める。

## 2. 積載と出発を分ける

- 完成料理を持ってバイクの荷台へ共通アクションを行うと、1個積む。容量は個数で示し、積み順を並べ替えるパズルは作らない。
- 積む操作と乗車は区別し、積んだだけで出発しない。荷台と乗車対象の輪郭表示を分ける等、入力の誤判定を検証する。
- 乗車前は取り出して入れ替えられる。取出対象の選択UIは別途試作し、誤廃棄を避ける。
- 乗車時に有効な注文との対応を再確認し、既定どおりタイマー・通常チップ・注文順コンボを確定する。複数注文は古い順に照合する既定方針を維持する。
- 乗車後の発送済み料理は配送取消・入替・代行切替を不可とする。未発送料理や誤料理、積載中に失注した料理の乗車前処理、複数人で同一注文に対応する競合処理は別の確定対象として残す。仮の注文表示だけで不可逆予約が成立するとは決めない。

現地で降車して歩いて納品する工程は新設しない。厨房の運搬・仕込みと、乗り物でまとめて回る判断に集中する。

## 3. 目的地で停車すると自動受渡し

目的地の道路沿いに分かりやすい配達エリアを置く。対応する発送済み料理を積んでエリア内でほぼ停止した時、自動で受渡しする案。精密な駐車角度、荷物の手動選択、降車や玄関までの徒歩は要求しない。

通過するだけでは受渡しせず、ブレーキを使う意味を残す。エリアの広さと停止判定の許容速度は初心者でも扱えるよう実測する。長い受渡し演出や確認ダイアログを追加しない。同じ地点へ複数件あれば対応する荷物だけまとめて渡し、個々に到着・得点判定する。別地点の荷物は残す。対応荷物なしでは何も消費せず、誤配減点を新設しない。

これは既定の「到着時加点」の到着判定を具体化する提案であり、今回すでに確定した仕様ではない。

## 4. 行先を案内しても経路は拘束しない

配達中のミニマップには、既定の厨房・道路・仲間等に加え、自分の積荷の目的地を強調する。初期の目標は現在地から道路距離が近い未完了行先とする案だが、プレイヤーが別の行先へ変更・先行できる。近い順が複数件全体の最短巡回になると保証しない。

特定の巡回順・ナビ経路を強制しない。先に遠い場所へ行く、近い注文をまとめて回る、寄り道する等を許容する。経路逸脱による追加減点は設けず、既存の営業時間と帰還まで厨房を操作できない時間が自然な代償となる。オート運転は初期案に追加しない。

到着順は自由で、発送時確定済みコンボやチップを到着順で再計算しない。最後の配送を終えても閉店前なら厨房へ戻って続けられ、閉店までに帰還する義務はない。

## 5. 検証と後続論点

- 積載対象と乗車対象をタッチ入力で誤認しないか。
- 行先情報を見て一件発送・複数積載・代行を選べるか。
- 停止で受渡しが伝わり、配達エリアに入り直すストレスが大きくないか。
- 同地点複数納品と閉店の同時刻境界、誤積載・発送競合、事故・転倒・復帰は別途詰める。
- 自配達と代行の得点/分・コイン/分・厨房不在時間を検証する。今回距離や報酬係数は変更しない。
