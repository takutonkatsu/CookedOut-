# COOKED OUT! エンドゲーム・経済・配達均衡案 v0.1

- 更新日: 2026-09-11
- 状態: 難度Tier、連続営業、4週合計スコアシーズン、経済、配達、設備Lv効果、日次・週次件数を採用。数値はプレイテスト用初期値

## 1. 無限に遊べる構造

有限の54出張ステージを遊び終えても、通常営業そのものは終わらない。長期進行を次の四層へ分ける。

| 層 | 上限 | 役割 |
|---|---|---|
| 機能成長 | 店ランク10・設備Lv5 | 新しい遊びと便利さを段階的に解放する |
| 熟練記録 | 上限なし | 通常営業累計星、累計XP、料理・献立・人数別自己ベストを伸ばす |
| 周期課題 | 毎日・毎週・シーズン | 同じ厨房でも異なる制約と目標を提示する |
| 収集 | 更新で追加可能 | 称号、バッジ、プロフィール枠、帽子、制服、バイク外見、厨房テーマを集める |

設備Lv6以降や無限の能力値上昇は作らない。能力差が伸び続けると、後発プレイヤーが追いつけず、通常営業ランキングも設備値の比較になってしまうためである。

### 1.1 ランク10後は合計スコアランキングへ移る

名声レベルと実力レート案は撤回する。店ランク10・設備Lv5を恒久的な機能成長の上限とし、その先の主目標は4週間ごとに競う合計スコアランキングとする。

- 店XPと店ランクは「遊んで店を育てた量」を表す
- シーズン合計は「固定された4厨房へ個人設備を配置して出した自己ベスト合計」を表す
- 店XP、通常営業星、出張営業星、コインをランキング得点へ直接加えない。設備種類・台数・Lvは実際の営業能力として反映される
- 毎週1厨房を追加し、公開済み厨房はシーズン終了まで残す
- 挑戦は無制限で、練習と本番を分けない
- シーズン終了時の人数別順位と合計スコアをプロフィールへ保存する
- 詳細は[4週間シーズン・合計スコアランキング仕様案](16_season_score_ranking_system.md)を参照する

### 1.2 終わらない通常営業

通常営業は、習得済み料理と現在の厨房能力から成立する献立候補を毎回3つ生成する。厨房そのものを自動生成せず、次の組合せを変える。

- 料理系統と注文派生
- 単一料理、同文法セット、複合セット
- 注文順と注文間隔
- 配達先と距離帯
- 自前配達／配送代行を選ぶ局面
- 報酬Tierと追加条件

通常営業はソロ専用とし、記録は累計通常営業星だけでなく、料理系統別、献立セット別、店ランク帯別に最高スコアを残す。過去の自己ベストはシーズン終了で消さない。

#### 通常営業の難度Tier

「詰まる、稼ぐ、設備を強化する、同じ難所へ再挑戦する」を本店内で成立させるため、通常営業には選択可能な難度Tier 1〜5を置く。報酬Tierと同じ番号を使い、用語を増やさない。この方針を採用する。

| 難度Tier | 解放の初期案 | 推奨設備 | 主な変化 |
|---:|---|---:|---|
| 1 | 通常営業解放時 | Lv1 | 単一料理、長い猶予、低い注文密度 |
| 2 | 店ランク3 | Lv2 | 注文派生と並行作業を増やす |
| 3 | 店ランク5 | Lv3 | 二料理セットと設備競合を増やす |
| 4 | 店ランク7 | Lv4 | 複合セット、短い判断猶予 |
| 5 | 店ランク9 | Lv5 | 最大三料理、高密度、最終成長帯 |

- 解放済みなら低いTierも自由に選べる
- 推奨設備レベル未満でも開始可能にし、上手いプレイヤーの早期突破を許す
- 高Tierで詰まったら、クリア済みTierでコインを稼ぎ設備を強化して再挑戦できる
- 出張営業は本店設備を持ち込まないため、この成長ループの対象外。出張の難所は操作と作戦で越える
- Tier 5星3後も、献立、注文列、配達先、自己ベストが変わるので通常営業は反復できる

#### 連続営業

エンディング後の上級スコアアタックとして、時間固定ではなく失敗まで続く「連続営業」を初期実装対象に加える。

- 9-4星1かつ店ランク10で解放する
- 通常営業Tier 3相当から開始し、納品5件ごとに難度段階を一つ上げる
- 注文間隔は段階ごとに3%短縮して初期値の55%を下限、注文タイマーは2%短縮して初期値の70%を下限とする
- 10件と20件で注文料理系統を一つずつ増やし最大3系統、同時注文上限は3件から4件、5件へ増やす
- 30件以降は料理系統数と同時注文上限を増やさず、注文順と配達先で変化を作る
- 注文失効3件で終了し、到達注文数、継続時間、スコアを記録する
- 設備は全員共通のLv5固定ロードアウトとして、恒久能力差ではなく処理判断の限界を競う
- 一時停止は認めるが、アプリ終了後の途中再開は初期版では認めず、その走行を終了扱いにする
- ランキングはソロ一部門とし、スコア、納品数、失効数、達成時刻の順で順位を決める。継続時間もプロフィール記録へ残す
- 一回が長くなりすぎないか、難度下限と端末発熱を実機試験する
- 通常営業の無限反復に必須ではなく、上級者向けの追加目標とする

### 1.3 周期チャレンジ

- デイリーは毎日2件。一件80コイン＋40XP、二件達成で追加50コインとする
- ウィークリーは毎週4件。一件250コイン＋150XP、四件達成で追加300コインとする
- すべての課題をソロで達成可能にし、マルチ専用課題は出さない。マルチで条件達成が速くなることは許す
- デイリーは一日一回だけ、条件を無料で引き直せる
- 連続ログイン報酬は7日周期で、30／40／50／60／80／100／200コイン、周期合計560とする。欠席時は1日目へ戻る
- 限定的な機能設備や料理、強さは報酬にせず、コイン、XP、称号、バッジ、性能差のない外見を中心にする
- 取り逃した外見は将来のローテーションや通常交換へ戻し、恒久的な欠落を避ける

### 1.4 個人設備を使うシーズン競技

通常営業ランキングとは別に、全員が同じ条件で遊ぶ「週替わり出張営業」を用意する。マルチプレイは出張営業だけという既決定を維持する。

- 厨房、料理、注文列、配達先乱数を同じシードで固定する
- 設備種類、台数、Lvはホストの本店所持状態を使い、指定ソケット内でロードアウトと配置を変更する
- シーズンは店ランク10かつ9-4星1で解放する。参加時点で全料理と全プレイヤー配置可能設備を解放済みとし、各設備Lv1を一台以上所有する
- 1人、2人、3人、4人を別ランキングにする
- ソロだけでも全報酬種別へ到達でき、2〜4人参加を長期進行の必須条件にしない
- 週ごとの自己ベスト挑戦は無制限とし、練習区分を設けない
- シーズンは4週間とし、4厨房の自己ベスト競技スコアを合計する
- シーズン終了時の順位で報酬を決め、リーグは設けない
- 上位報酬は強さに影響しない称号、バッジ、プロフィール枠とし、参加報酬も用意する

## 2. コイン経済の採用初期値

通常営業・出張営業を難度と長さから報酬Tier 1〜5へ分類する。以下は星2・標準時間の基本コインである。

| 報酬Tier | 星2基本コイン | 主な時期 |
|---:|---:|---|
| 1 | 120 | 導入・店ランク1〜2相当 |
| 2 | 180 | 序盤・店ランク3〜4相当 |
| 3 | 260 | 中盤・店ランク5〜6相当 |
| 4 | 380 | 後半・店ランク7〜8相当 |
| 5 | 540 | 終盤・店ランク9〜10相当 |

```text
営業コイン = Tier基本コイン × 星倍率 + 初回クリア加算 + 課題報酬
星倍率: 星0=0.25、星1=0.75、星2=1.00、星3=1.25
初回クリア加算: Tier基本コイン×0.50
```

- 星0でも少量を得て、失敗を完全な無駄にしない
- 協力人数によるコイン倍率は付けず、参加者全員が同額を得る
- 同じ短い簡単なステージだけが最適解にならないよう、想定時間と難度でTierを設定する
- 広告視聴を前提に基本価格を上げない

### 2.1 設備強化価格

各段階の標準営業2〜3回で、設備種類全体を一段階強化できる初期値とする。

| 強化 | 価格 | 対応Tierでの星2営業目安 |
|---|---:|---:|
| Lv1→2 | 450 | Tier 2で2.5回 |
| Lv2→3 | 750 | Tier 3で2.9回 |
| Lv3→4 | 1,100 | Tier 4で2.9回 |
| Lv4→5 | 1,500 | Tier 5で2.8回 |

価格は個体一台ごとではなく、鍋、フライパン、まな板等の設備種類ごとに一度だけ支払う。同種類の所有設備すべてへ同じLvを適用し、後から追加購入した個体も現在Lvで入手する。追加台数の価格と固有上限は[店ランク・設備進行仕様](18_store_rank_and_equipment_progression.md)を正とする。

### 2.2 コインの長期消費先

設備が最大になった後もコインが無価値にならないよう、性能差のない外見へ使えるようにする。

| 種類 | 初期価格帯 |
|---|---:|
| 小さな色替え・アクセサリー | 300〜600 |
| 帽子・制服セット | 1,200〜2,500 |
| バイク外見 | 2,000〜4,000 |
| 厨房テーマ | 3,500〜6,000 |

無料コイン外見と有料外見は台帳で明確に区別する。通常コインの直接販売は行わない既決定を維持する。

本店は12×9固定のため、厨房面積・閉鎖区画・設備ソケットを商品にしない。旧厨房拡張向けに想定していたコイン支出は必須の別システムへ移さず、設備追加、設備Lv、性能差のない外見を長期消費先とする。経済が余る場合は、まず外見価格と供給量を調整し、性能に関わる新しい消費を安易に足さない。

## 3. 自前配達と配送代行の採用初期値

どちらかが常に正解になるのではなく、厨房の混雑、注文残り時間、現在人数から注文ごとに判断する設計にする。

### 3.1 共通ルール

- 料理完成後、プレイヤーは自前配達へ持ち出すか、配送代行棚へ置く
- 注文タイマーはどちらの方式でも止まらない
- 自前配達は目的地到着時に納品完了し、帰路時間は次の作業機会へ影響する
- 配送代行は棚へ置いた後、所定時間経過で納品完了する
- 配送代行棚は初期1枠。使用中は次の料理を置けない
- 自前配達は人数分のバイクを使い、複数人が同時に配達できる

### 3.2 初期時間

| 方式 | 初期値 | 主なコスト |
|---|---|---|
| 配送代行 | 棚投入から30秒で納品 | 完了が遅く、棚1枠が塞がる |
| 自前配達 | 厨房離脱から帰還まで平均20〜30秒 | 一人が厨房から抜け、運転失敗でさらに遅れる |

配達先は、平均往復25秒になる近・中距離帯を中心に重み付き抽選する。同じ建物の連続、到達不能、極端な遠距離連続を除外する。

### 3.3 得点式

料理そのものの得点、残り時間チップ、注文順コンボは共通にする。自前配達だけ、厨房を離れる機会費用へ人数別ボーナスを加える。

```text
共通納品点 = 料理基本点 + 残り時間チップ + 注文順コンボ
自前配達点 = 共通納品点 + (料理基本点 + 残り時間チップ) × 自前配達率
配送代行点 = 共通納品点
```

| 営業人数 | 自前配達率の初期値 |
|---:|---:|
| 1人 | +50% |
| 2人 | +30% |
| 3人 | +20% |
| 4人 | +15% |

一人営業ほど厨房が完全に無人になるため、高い自前配達率を与える。人数が増えるほど一人離脱の影響が小さいため、率を下げる。

### 3.4 均衡の合格基準

- 人数別に、理想的な自前中心運用と代行中心運用の最終スコア差を±5%以内にする
- 自前だけ、代行だけでも星3へ届く構成を少なくとも一部用意する
- 最高記録では状況に応じて両方を混ぜる余地を残す
- 初期版では配達専用コンボを増やさず、注文順コンボへ統一する
- 調整候補は代行24／30／36秒、自前配達率、配達距離、棚枠、注文密度とする

### 3.5 必須分析ログ

- 注文ごとの自前／代行選択
- 完成から納品までの時間
- 自前配達の厨房離脱時間、往路、帰路、衝突回数
- 代行棚の占有時間と、満杯で置けなかった回数
- 方式別の納品点、失効率、1分当たり得点
- 人数別、料理別、距離帯別の方式選択率
