## 1. 第1章の材料を5種類にまとめる

レタス、トマト、キュウリ、タマネギ、生ハンバーグの5種類を候補とする。生ハンバーグは成形済みの生パティで、肉挽き・こね・成形操作は追加しない。火を通す工程は必須にする。

野菜の見た目・切断操作を系統間で共用し、切ったトマトをサラダ、スープ、主菜の付け合わせへ使える。料理名を増やしても専用器具や操作ボタンは増やさない。

塩、水、油、調味料は第1章では運ぶ独立アイテムにせず、料理表現に含める案。これは後続料理に調味料アイテムを一切導入できないという決定ではない。

## 3. 共通工程の運用案

### 3.1 下処理

第1章の野菜は全て1単位につき1回の切断作業。レシピによって同じ野菜の切る回数や操作を変えない。未加工・切断済みは裸の作業台へ置ける既定仕様を使う。

### 3.2 スープ

- 鍋へ切断済み野菜を3個入れた時に自動加熱する。1・2個では加熱を進めない。3個の投入順は問わない。
- 第1章スープは全派生で3個に揃え、「1個で加熱開始した後、3個の注文へどう足すか」という曖昧さをなくす。
- 一鍋は一注文分。Lvによって人前数を増やさない。
- 加熱開始後に4個目の追加は受け付けない。火から外した時の加熱・焦げ進行は既存の退避操作と整合させる。
- 受け付けた3個の組合せがレシピに一致しなければ誤料理とし、完成しても提供できず廃棄する。正しいレシピだが現在の注文にない場合は、誤料理とはせず一致注文が出るまで保管できる。
- タマネギ3個とトマト3個を学んだ後、混合派生で材料アイコンと数量を見る判断を加える。専用混ぜボタンは設けない。

### 3.3 フライパン

- 生パティを1個入れると自動加熱。こねる・裏返す・火力調節を要求しない。
- 焼いている間に副菜を切れる。容器には副菜から先に置いてもよい。
- 加熱済みパティは皿・共通容器か元のフライパンで保管し、裸の作業台へ置かない既定仕様を使う。

### 3.4 完成した基本料理への追加

S1→S2→S3、P1→P2→P3のように、完成扱いの料理にも発送前なら対応材料を足して別派生へ変えられる案。材料を抜き取って元に戻す操作は設けない。

配達容器は有効なレシピ成立時に透明蓋を閉じる既定の見た目を維持し、追加材料を置く操作で自動開閉する。蓋の開閉ボタン・包装の長押し工程を追加しない。完成扱いと編集不可は同義にせず、発送した後は追加できない既定ルールを守る。

単純なサラダが一度完成しても、追加具材を受け付けず作り直しになる不便を避ける。後から具材を足したため元の注文へ出せなくなる判断はプレイヤーに残す。誤った組合せまで自動で正解へ修正しない。

## 4. 各ステージの献立候補

| ステージ | 採点営業の候補 | 学ぶこと・狙い |
|---|---|---|
| 1-1 | S1・S2・S3 | 最初はS1、次に具材追加。切る・容器・注文差 |
| 1-2 | N1・N2・N3 | 3個投入、自動加熱、加熱待ちに次の下処理 |
| 1-3 | S1・S2・N1 | 既習料理に絞り、投擲と配達へ注意を向ける |
| 1-4 | S2・S3・N1 | 料理を増やさず、ダッシュ・注文順・移動判断 |

| 1-6 | N1・P1・P2 | 二種類の加熱設備と火災からの復旧 |
| 1-7 | S2・S3・N1 | 既習料理で皿の循環を学ぶ |
| 1-8 | S2・N1・P2・P3 | 3系統・計4派生で自前／代行と厨房変化の総合判断 |

全9派生を一営業へ同時に出さない。初回ガイドは最も単純な派生で一工程を教え、採点区間では固定された注文列を使う。初回学習の成否でランキング用の採点区間だけ簡単な料理へ変わる仕様にしない。

この表は献立の相談であり、既存の投擲必須・マルチ解放・総星8・火災実演・皿洗い実績等のクリア条件を変更しない。注文密度、ガイド切替時の状態リセット、切替操作の初回導入位置は個別ステージ設計で整合確認する。

## 5. 通常営業解放時につなぐ

第1章で習得・解放した料理だけを通常営業の候補に出す既定方針を維持する。章完了時にこの3系統を扱える状態へつなげる案とし、最初の通常営業で全3系統混合を強制しない。

3候補の最初の例は「サラダ中心」「スープ中心」「ハンバーグ中心」。既定のランダム3セット方式を固定3択へ置き換える決定ではない。最低必要設備・供給箱が成立する候補だけを生成する。複合献立は営業Lv上昇に合わせて増やす。

## 6. 確定前の確認

- 基本点はLv3標準工程から再試算し、旧15の20／40／50点や34の仮点数を流用確定しない。
- 猶予・工程時間は検証待ち。初心者・熟練者、ソロ1キャラ対2キャラの比較を行う。
- 1-1の3派生・1-2の3個投入が初見に重すぎないか、アイコンの数量が読めるか確認する。
- 生パティが切断必須の食材と誤認されず、焼いた状態も判別できるか。
- 完成した基本料理への具材追加が蓋の表示と矛盾しないか。
- サラダとスープで同じ切断済みトマトを使えて、派生ID・解放・報酬を二重登録しないか。
- サラダは移動・組立、スープは下処理量・鍋占有、プレートは加熱と副菜並行、という違いが遊びで現れるか。
