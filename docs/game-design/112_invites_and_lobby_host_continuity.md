# COOKED OUT! 招待とロビー管理の残件案 v0.1

- 作成日: 2026-09-16
- 状態: 2026-09-16、公開4点をユーザー承認で採用。6桁コード＋リンク、部屋継続と入室不可理由、ロビーホスト引継ぎ、開始前の人数変更時の再確認。具体猶予秒数・技術方式・範囲外事項は未決。実装・外部サービス選定は行わない
- 既定: 初回から友達との2〜4人出張営業、野良なし、料理詳細から練習不可、全員準備後ホスト開始、営業中の新規参加なし。ロビーの本人実績・プロフィール表示は採用済みで再審議しない

## 1. 部屋を作る／部屋に入る

部屋を作ると6桁数字のコードを表示し、友達は入力して参加できる方式を推奨する。招待リンクの共有にも対応し、リンクをタップしてその部屋の参加へ進める。ゲーム内フレンド登録を必須にしない。

同じ部屋で次の面に進むたびにコードを変えたり、再入力したりしない。部屋が解散したらその招待を無効にする。リンクは部屋存続中のみを対象とし、永続的な参加権や解放権を付与しない。

## 2. 入れない理由を短く示し、現在の営業を邪魔しない

満員、営業中、見つからない／解散済みを短く案内する。営業中の新規参加待機席や自動合流予約は初期に設けず、営業終了後に再試行してもらう。

自分が営業中に招待リンクを開いても、営業を勝手に中断・退出して別部屋へ移動しない。営業後の入室に再試行を必要とする場合もその旨を伝える。リンク未インストール時・OSからの復帰の詳細、期限、コードの不正試行対策は技術設計時に確認する。

## 3. ホストがロビーを抜けても、部屋は継続する

明示的な退出時は、残る接続中メンバーで最も早く参加した人に管理役を移す案。誰が新ホストか表示し、全員の準備完了を解除する。新ホストが現在の面を解放済みなら選択を維持し、未解放なら選び直す。旧ホストの解放権を部屋に残さない。

ロビーでの一時通信断は即時退出にせず短い復帰猶予を置き、その間は開始しない。猶予後に引継ぎ、元ホストが復帰しても自動で管理役を取り返さない。猶予の具体秒数は未確定。

これは営業前後のロビー管理役の交代であり、営業中のホスト切断時にも技術的に継続できる仕組みを確定したことにはならない。営業中も続行するゲーム方針は維持し、実現方式・費用・検証は別途決める。

## 4. 人数が変わったら、開始前に確認し直す

残り一人になってもロビーを維持して友達を待てるが、一人で協力営業を開始したりソロ二キャラへ自動変更したりしない。全員退出で解散する。

ステージ・人数変更時の準備解除は既定を維持する。ロード・開始カウントダウン中にメンバーが抜けた場合は開始を取り消してロビーへ戻り、人数を確定して準備し直す案。営業開始後は既定の切断中継続へ切り替える。

## 5. 範囲外

ボイスチャット、キック・ブロック、フレンド一覧、バックグラウンド中の部屋維持時間、コード・リンク実装、ホスト権威やリレーのサービス選定、営業中のホスト移行方式。特定サービスの対応可否・費用を断定しない。
