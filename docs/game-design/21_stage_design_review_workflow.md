# COOKED OUT! 全ステージ設計・順次レビュー方式 v0.1

- 更新日: 2026-09-12
- 状態: 採用
- 対象: チュートリアル1-1〜1-8、実戦2-1〜9-4の全54出張営業

## 1. 設計順

Core Alphaへ直結する第1章を先に確定し、その後はキャンペーンの一本道順に進める。

```text
1-1 → 1-2 → … → 1-8
→ 2-1 → 2-2 → … → 8-6
→ 9-1 → 9-2 → 9-3 → 9-4
```

原則として、一度に相談するのは一ステージだけとする。前のステージで確定した操作、料理、通路幅、ギミック予告時間を次のステージの前提にする。

## 2. 一面ごとの仕様パッケージ

各ステージについて、必ず同じ順番で決める。

1. **存在理由** — 何を覚える／試す／組み合わせる面か
2. **基本条件** — 人数、提供方式、厨房区分、規模、営業時間
3. **料理と注文** — 使用料理、注文順、同時注文数、初回安全注文
4. **盤面** — 床、壁、穴、設備、スポーン、受渡し点、提供・配達口
5. **必須動線** — 一件の料理が通る最短経路と、混雑が生まれる交点
6. **ギミック時系列** — 予告、動作、安全時間、周期、停止条件
7. **人数別成立性** — 1／2／3／4人の仕事量と遊休・詰まり対策
8. **採点** — 星1〜3、得点源、失効、ランキング固定条件
9. **UI・ガイド** — カメラ導入、輪郭、操作アイコン、音、振動
10. **制作物** — 必要な3D、アニメーション、VFX、SE、背景
11. **検査** — 到達可能性、閉じ込め、進行不能、プレイテスト指標

加えて、各面の設計意図は[全54ステージ「難しさ・面白さ」設計台帳](23_stage_difficulty_and_fun_master_plan.md)を参照し、次の六点を明記する。

- プレイヤーへ投げかける問い
- 六軸のうち主に上げる難しさ
- 一走行で繰り返し起こしたい面白い瞬間
- 笑えて立て直せる「良い失敗」
- 待つだけ・見えない・復旧不能になる「悪い失敗」の防止策
- 同じ盤面で1〜4人それぞれに成立する遊び

## 3. 盤面を確定する手順

各面で盤面をいきなり一案へ固定しない。

1. 仕様側が役割の異なる2〜3案を提示する
2. 推奨案と、他案を不採用にする場合の理由を示す
3. ユーザーが方向を選ぶ
4. 選択案を正確なグリッド座標へ落とす
5. 静的検査後にグレーボックスへ反映する
6. 1人、2人、4人で実測する
7. 数値だけで直せる範囲を調整し、盤面をロックする

盤面ロック後の構造変更は、進行不能、カメラ外、重大な遊休、単一最適解等の問題が実測された場合だけ行う。

## 4. 人数別設計規則

- 床と壁、主要ギミック、設備位置は原則として全人数共通
- 注文間隔、注文タイマー、同時注文上限、星ラインを人数別にする
- 人数が増えても仕事が消えないよう、切断・加熱・受渡し・配達の並行作業を最低二系統用意する
- チュートリアル初回の強制ガイドはソロだけ。マルチ再プレイではガイドを省略できる
- 全人数で同じ盤面が成立しない場合だけ、既定カウンターを第二設備へ置換する人数別ロードアウトを許可する
- 常設ランキングでは、同じ人数内の設備、注文、周期、配達先を固定する

## 5. チュートリアル固有規則

- 新しい主題は一面につき原則一つ
- 新操作を使わない近道を盤面上で塞ぐ
- 最初の成功までは時計停止または大幅緩和
- 成功後は説明を縮小し、短い採点営業へ移る
- 以前に学んだ操作を次面で再利用する
- 1-3星1でマルチ、1-8星1で通常営業を解放する
- 1-8解放には1-1〜1-7の章進行星8を要求する

## 6. レビュー時の回答形式

各面の相談では、ユーザーが判断すべき項目を3〜5個に絞る。回答後、以下を同時に更新する。

- そのステージの詳細仕様
- 初期54ステージ・マスター表
- 第1章または該当章の数値表
- 企画・意思決定ログ
- 実装が必要な場合だけ実装申し送り

全体台帳の一文は設計意図であり、盤面座標、周期、注文列を確定した時点で、その面の実測結果に合わせて更新する。
