# COOKED OUT! ソロ出張の二キャラ切替と配送中の扱い v0.2

- 作成日: 2026-09-13
- 状態: ユーザー承認により厨房と街をまたぐ切替、非操作バイクの停止待機、全時計継続、非操作側の帰還でも選択を奪わない方針を採用。安全停止物理・同時イベント・画面切替は実機検証待ち。通常営業へ二キャラ切替は追加しない。未実装
- 既定: ソロ出張は原則二キャラを即時切替、非操作側は開始済みの定位置作業だけ継続。自律移動・判断AIなし。配送期限は出発単位、配送完了／期限切れで自動帰還。配送担当は料理人に固定

## 1. 配達中も厨房の料理人へ切り替えられる案

片方が街、もう片方が厨房にいても、既存の切替入力を使える。厨房にいる同士なら厨房全体カメラのまま選択だけ変更。街と厨房をまたぐ時は、選択先の料理人に対応するカメラと操作群へ切り替える。新たな管理画面・確認ダイアログ・切替クールダウンは追加しない。

運転のアクセル等を押していた指が、切替後の調理・廃棄・投げとして継続入力されないようにする。二人の料理人の立場や配送担当を交換するわけではなく、操作対象だけを変更する。

## 2. 非操作中のバイクは停止・待機する案

非操作となった料理人のバイクは停止して待機し、自動で目的地まで運転・巡回しない。再び選択したら停止状態から運転を再開する。街の非操作キャラが勝手に事故パックを拾ったり、別注文を積んだりもしない。

走行中に切り替える場合の安全停止処理は試作で確定する。切替だけで目的地へ進める自動運転・遠方への路肩ワープにはしない。切替を通常ブレーキより得な急停止手段として連打できないか、画面外で車両に押されて連続転倒しないかを検証する。物理減速・安全な停車扱い・周辺交通との接触の詳細を、この抽象方針だけで実装確定しない。

この規則の代償として、運転と厨房作業を両方同時に能動操作することはできない。調理を開始してから運転へ移り、開始済み作業や加熱を並行進行させることに切替の価値を置く。

## 3. すべての期限はそのまま進む

- 営業時計、厨房の未発送注文、配送期限、加熱・焦げ等は切替で停止・延長しない。
- 配送中の元の注文タイマーは停止済みのまま、別配送期限が進む。
- 片方の配送が期限切れになった場合は、操作している料理人に関係なく既定の失注・共有コンボ処理・自動帰還を行う。
- 互いの配送期限は独立した出発の締切として保持し、切替や別便の帰還で更新しない。

例: Bに切る作業を開始させる→Aで配達へ出る→Bは切り終えるまで作業し、その後待機。途中でBへ切り替えて次の料理を準備すると、その間Aのバイクは待機し、Aの配送バーは減る。Aへ戻れば元の期限の残りで配達を再開する。

「切替中も始めた作業だけ継続」と、通常操作中に作業入力を離したら中断する規則を混同しない。ソロ切替イベントで開始済み作業を引き継ぐ例外は既定方針を使い、一般のボタン解除をすべて自動作業へ変えない。

## 4. 非操作側が帰還しても選択を奪わない案

厨房Bを操作中にAが配送期限切れで戻っても、Bの操作と厨房カメラを維持する。Aは荷台横で待機し、配送状況欄に帰還の短い反応を出すだけとする。自動的にAへ切り替えてBの作業を中断しない。

操作中のAが配送完了／期限切れで戻る場合は、既定どおりAのまま厨房カメラ・徒歩操作へ切り替える。戻ったAに新しい仕事を自動指示しない。閉店が先なら結果画面へ進む既定処理を優先する。

非操作側も、既に成立済みの納品イベントや安全停止処理で全件完了した場合は同じ帰還処理を使う。自動納品の停車条件と切替イベントが重なった時の順序は実装前に検証する。非操作だから未処理イベントを永久保留する方式にはしない。

## 5. 適用範囲と確認

- 通常営業は一キャラのまま。街に出ている間に別の料理人へ切り替えることはできない。
- マルチは各人が一キャラを操作し、ソロの切替で配送担当を交代する機能を流用しない。
- ソロでも事故回収をもう片方のキャラで手伝う場合は、55の元バイクへ再積載・担当固定を維持する。見えていない場所へ料理人を瞬間移動させない。
- 非操作の料理人が待機していることは既存の顔アイコン等で把握できる範囲に留め、常時の分割画面・ライブ小窓・新たな指示UIを増やさない。
- 切替時の画面酔い、時間バーの読み違い、配送中の待機による初心者負荷、入力持越し、配送中失注からの復帰を実機で確認する。難度の秒数を先に一律決めない。
