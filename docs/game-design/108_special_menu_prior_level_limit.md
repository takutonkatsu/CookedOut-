# COOKED OUT! 追加メニューを前の営業Lvの系統に限定する案

- 作成日: 2026-09-15
- 状態: 2026-09-15、ユーザー承認で公開方針を採用。追加系統は今回営業Lvより前の定番系統に限る。店ランクではなく今回営業Lvで判定し、基本2品・調理適合も必要。初期上限で餃子が定番専用となる点を含む。具体候補適合と経済均衡は未検証
- 前提: 通常営業の定番割当は106で採用。Lv1〜4は1系統、Lv5〜20は定番＋追加1系統、各系統は基本2品のみ

## 1. 推奨する判定

追加系統は「定番として初めて出る営業Lv」が、今回選んだ営業Lvより低いものに限ることを推奨する。料理自体の品質・難度を数値化した新しい料理ランクは作らない。

従来の基本2品習得・定番と異なる系統・原料箱／設備／容量適合も引き続き必要。候補数は料理系統の候補数で、個別注文品数とは区別する。

| 今回の営業Lv | 定番 | 追加系統の範囲（適合による絞込前） |
|---|---|---|
| 5 | 寿司 | Lv1〜4のサラダ・オムレツ・焼きそば・スープ |
| 6 | おにぎり | Lv1〜5の上記4系統＋寿司 |
| 10 | パスタ | Lv1〜9の9系統 |
| 20 | 餃子 | Lv1〜19の19系統 |

本人の現在の店ランクではなく、今回プレイする営業Lvで判定する。店ランク20で営業Lv5へ戻る場合も追加はLv1〜4までとし、後半系統を低Lvへ持ち込む経路を残さない。日替わり候補の制限であって料理の習得記録を削除する意味ではない。

## 2. 利点

- 最新の料理を定番で覚え、既に定番で使える段階を経た料理を追加枠で組み合わせる流れが分かりやすい
- 出張先行だけで後半料理が低Lvへ入り、想定と異なる基本点・設備負荷を持ち込む経路を抑えられる
- 営業Lv上昇で定番だけでなく組合せ候補も一つずつ増え、通常営業を進める意味になる
- 序盤の選択肢を抑えつつ、Lv5時点でも4候補、終盤は最大19候補という幅を残せる。ただし実際は設備・原料適合で減る

料理の基本点が高いほど必ず得点／分やコイン／分が高いという前提ではない。制限は調整対象を減らす手段であり、収益と難度の均衡を自動で保証するものではない。

## 3. 欠点と扱い

先行して出張で覚えた料理を、すぐ本店の低Lvへ持ち帰る自由は減る。ただし出張・習得済みの練習・図鑑では引き続き利用でき、その料理の定番Lvへ進めば通常営業でも扱える。シーズンの固定献立には本制限を適用しない。

最終Lv20の餃子は、初期上限20の間は追加メニューに登場せず、Lv20の定番としてのみ通常営業へ出る。これは特例で先行選択を許可せずとも遊ぶ機会は確保されるため、推奨案では許容する。将来Lv21以降が増えた時にはルール上追加候補になり得るが、追加時の具体献立は保留を維持する。

各Lvの定番より前の系統すべてを無条件に作れるわけではないので、最低一つの適合候補が残るかは検証する。Lv5で初めて2系統になる際のサラダ推薦とも整合する。

簡単で処理効率のよい一系統ばかり選ぶ最適化は、この制限だけでは防げない。材料共用・設備競合・料理基本点・注文比率の組合せで選択の意味を作り、強制ローテーションで解決しない。

## 4. 表示と保存

「ほかのメニュー」は今回選べる候補を中心に表示する。料理図鑑の習得済み表示と、今回の営業で選べるかは別情報として扱う。具体の制限理由表示は未決定。

Lv別の前回選択保持は維持し、読み込み時に今回Lv・基本2品・設備適合を確認する。本仕様採用時も既存の料理実績・コイン・報酬を取り消すことは提案しない。現状は設計段階であり実データの移行は実施しない。
