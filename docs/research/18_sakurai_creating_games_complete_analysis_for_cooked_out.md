## 0. 結論

桜井政博氏の制作論を一文に圧縮すると、次のようになる。

> **プレイヤーが実際に触れている時間を中心に置き、作品固有の強い遊びを早く形にし、伝わる表現と素早い反復で磨き、不要なものを切る。**

COOKED OUT!へ最も強く適用すべきなのは、料理工程や厨房ギミックを増やすことではない。営業中にプレイヤー自身が「何を受けるか、どう厨房を整えるか、いつ忙しさを上げるか、どう届けるか」を選び、その判断が数十秒以内に成功、失敗、立て直しとして返る中核ループを作ることである。

本作の独自コンセプト候補を、暫定的に次のように再定義する。

> **すぐ遊べて何をすればよいか分かり、慣れるほど厨房を自分たちなりに回せる協力料理アクション。**

この定義なら、通常営業の献立・設備配置、作業台上の可搬設備、二つの提供経路、自前配達を、ばらばらの付加要素ではなく一つのテーマで結べる。一方、各要素が「選べるだけ」で正解が一つ、結果が遠い、面倒な準備になるなら、プレイヤー主導ではなく管理作業になる。注文票は自動発生とし、ウェーブ開始をプレイヤーへ管理させない。

最優先で行うべきことは、全54面や全36料理を作り進めることではなく、次の15分を遊べる一つの試作を作ることである。

```text
注文票が自動で入る
→ 初期配置のまま始める
→ 必要なら可搬設備を一台だけ移す
→ 同じ共通操作で料理を続ける
→ 自前配達か代行を選ぶ
→ 結果を見て即座に再挑戦する
```

これが面白く、初見でも理解でき、二回目に改善したくなるなら、本作には固有の核がある。成立しなければ、54面へ展開する前に仕組みを変えられる。

### 1.2 「全て分析」の扱い

本書は254章を254個の独立した規則へ機械的に変換するものではない。同じ思想を別角度から扱う章を束ね、COOKED OUT!で判断可能な原則へ再構成した。章ごとの題名、区分、タイムスタンプ付き公式URL、適用領域は付属CSVに全件収録している。

チャンネル終了時の最終スペシャル等、指定再生リスト外の動画は254章の件数へ含めていない。したがって本書の「全」は、指定された公式まとめ再生リスト全件を指す。

## 2. 全体を貫く14の制作エッセンス

### 2.1 開発者ではなくプレイヤーの都合で考える

制作の難しさ、実装済みであること、作り直しの費用は、遊ぶ側の価値にはならない。実機で分かりにくい、遅い、気持ちよくないなら、技術的な代案を探し、必要な変更を早く決める。[^a1][^a2]

COOKED OUT!では「実装が簡単だから」「Overcookedもそうだから」を最終理由にしない。正方形グリッドは開発効率だけでなく、距離、当たり判定、役割分担、予測可能性がプレイヤーに伝わるから採用する、と説明できる必要がある。

### 2.2 コンセプトは短く、強く、最後まで貫く

企画の核は、機能一覧ではなく「その作品で何が面白いのか」を短く伝える軸である。長期開発では要素が増え、平均的な作品へ寄りやすい。判断に迷った時、核へ戻して切る必要がある。[^a2][^a3]

本作の現行一文「町の小さな料理店を育てながら……」は内容説明としては正しいが、固有の遊びがまだ見えにくい。「同じ簡単操作で厨房も自分たちなりに整えられる」を核として試し、それが成立した後に町、育成、配達、動物を支える要素として並べるべきである。

### 2.3 アイデアは問題を定義し、多数出し、切って残す

最初に解くべき問題を明確にし、案を一つに飛びつかず、複数出して比較する。多数決で無難な案へ平均化せず、情報を持つ責任者が決める。決めた後も実物が悪ければ変える。[^a2][^a3]

本作の問題は「Overcookedと違う機能が足りない」ではなく、「営業中の一秒ごとの意思決定が既存作と同じに見える」である。可変厨房、注文選択、忙しさ開始、配達選択は、この問題へ直接効くかで評価する。

### 2.4 ゲーム性は、近接したリスクとリターンで作る

判断には、取る危険、得られる見返り、結果までの近さが必要である。大きなリターンに大きなリスクが対応し、行動後すぐ結果が分かるほど、選択はゲームになる。全ての楽しさをリスクとリターンで説明する必要はないが、攻略の核には有効である。[^b1]

COOKED OUT!では次が良い例になる。

- いま数秒を使って設備を移すと後の動線は短くなるが、目の前の注文処理は遅れる
- 二つの厨房接続状態は、一方が調理距離を短くし、もう一方が提供距離を短くする
- 自前配達は高得点だが厨房から人が減り、代行は低リスクだが得点が抑えられる
- 複数個をまとめて配達すると効率が上がるが、失注時の損失も増える

「設備をLv5にすると常に速い」のような、見返りだけの強化は選択を減らす。成長要素は、違う戦術を開くか、攻略の詰まりを軽くする程度に抑える。

### 2.5 圧力を凝縮し、解放で気持ちよくする

忙しさを一定に流し続けると疲労と単調さが出る。注文が重なる圧力、完成が連鎖する解放、短い息継ぎを設計する。難度は滑らかな右肩上がりではなく、山、谷、見せ場、回復を持つ。[^b1][^b2]

一営業を次の波形で設計する。

```text
理解  →  小さな圧力  →  注文の重なり  →  連鎖提供  →  息継ぎ
                                      ↓
                           終盤の自然な盛り上がり
```

残り30秒の音楽変化だけで盛り上げず、注文構成、厨房状態、得点機会も同期させる。

### 2.6 初心者に優しく、熟練者の工夫は奪わない

初心者が操作不能や説明不足で脱落しないようにしつつ、自動化しすぎて本人の判断を消さない。星1は理解と完走、星2は安定、星3とランキングは最適化という多層構造は本作と相性がよい。多少の有利な工夫や「うまい抜け道」を全て潰さないことも、発見と所有感につながる。[^b1][^b3][^c1]

許すべき工夫と潰すべき不具合を分ける。

- 許す: 投げによる受け渡し短縮、厨房状態の先読み、役割の高速交代、注文のまとめ仕込み
- 条件付き: 角越し受け渡し、バイクの近道。再現性と公平性があり、見た目に納得できれば残す
- 潰す: 壁抜け、無限得点、入力不能、同期ずれ、知らない人だけが極端に不利な隠し仕様

### 2.7 入力には必ず反応を返す

押したのに何も起きなかったように見える状態は、操作不良と学習失敗を生む。成功だけでなく、対象外、禁止、未完成、満杯にも短い反応が必要である。褒める演出は気持ちよさと理解を同時に作る。[^c1][^c2]

各アクションは以下を返す。

| 入力結果 | 必須反応 |
|---|---|
| 成功 | 手、対象物、SE、必要最小限の振動 |
| 対象違い | 対象輪郭の拒否表現と短いSE |
| 工程不足 | 欠けている工程アイコンを対象付近に一瞬表示 |
| 投げ不可 | 軌道を出さず、禁止形状をボタン付近と対象へ表示 |
| 混雑・満杯 | 置けない場所と代替候補を区別 |

失敗を全画面ダイアログで止めるのではなく、場の中で理解させる。

### 2.8 プレイヤーへ早く操作を返し、待ち時間を削る

開始、再挑戦、画面遷移、ロード、結果演出は、プレイヤー時間を消費する。冒頭の強い体験を早く見せ、操作を渡し、失敗後は短く理由を示してすぐ戻す。[^b2][^c3][^d1]

本作の目標値を置く。

- アプリ起動から前回モード再開候補まで: 10秒以内を目標
- ステージ開始操作から移動可能まで: 5秒以内を目標
- 失敗確定から同条件リトライで再操作まで: 6秒以内を目標
- 結果画面の強制演出: 3秒以内。以降は即スキップ可能
- 厨房内で入力不能なカメラ演出: 初見5秒以内、再挑戦時は省略

ロード中のコツ表示は補助であり、遅さの正当化には使わない。

### 2.9 チュートリアルは実際の面白さの中で行う

説明専用の無味乾燥な空間より、本番の遊びを簡略化して触らせる。最初に強い瞬間を見せ、自然な制約で正解行動へ導き、文章ではなく反応から学べるようにする。[^c2][^c3][^d1]

現在の1-1は基本操作の網羅としてはよいが、切る、入れる、提供するだけでは、本作固有の遊びが見えない。最初の一皿を短く完成させた直後、二択の厨房スイッチまたは二つの注文セットの選択を一度入れ、「自分で次の忙しさを決めた」感覚を与えるべきである。

### 2.10 情報は重要度で差をつけ、言葉以外でも伝える

全要素を同じ大きさ、明るさ、音量で見せると、整っていても判断しにくい。重要なものを大きく、対話対象を背景より強く、絵と形を文字より先に、色を唯一の手掛かりにしない。UIは分かりやすさと作品らしさの両方を担う。[^f1][^f2][^j1][^j2]

厨房中の優先順位は次とする。

1. 焦げ、火災、失注直前、変形予告など不可逆に近い危険
2. 現在対象と可能アクション
3. 注文の完成条件と残り時間
4. 仲間、配達、設備の状態
5. スコア、連鎖、報酬予告
6. 装飾、世界観演出

ただし危険表示を常時最大にすると慣れて無視されるため、平常、予告、危険の三段階を明確に分ける。

### 2.11 見た目、動き、効果、音は全部ゲーム情報である

グラフィックは飾りではなく、操作面、判定、重要度を伝える。モーションは準備、発生、余韻を使い分け、必要な所は誇張する。エフェクトと画面振動は大小関係を守り、音は物理的な音量ではなくゲーム上の重要度で混ぜる。最終的な画面と実機スピーカーで統一して確認する。[^f1][^g1][^h1][^i1][^i2]

COOKED OUT!の二頭身動物キャラクターでは、顔の大きさを利点にできる。

- 持つ前に目線を対象へ向ける
- 加熱完了で耳、尾、顔が先に反応する
- 重い設備移動は踏ん張りと遅い予備動作で伝える
- 誤料理は表情と短い鳴き声で本人にも仲間にも知らせる
- 成功提供は長く止めず、走りながら喜べる上半身モーションにする

### 2.12 報酬は早期に設計し、使い道と対にする

報酬は後から付ける飾りではない。何を目標に反復し、その報酬で次に何が変わるかを早く決める。収集量を増やしすぎると作業になる。順位表示も、大多数へ敗北だけを見せると継続動機を失う。[^b2][^c2]

本作では、同じ結果に複数の前進を用意する。

- ステージ進行: 星1
- 上達: 星2・3、自己ベスト、工程別改善
- 所有: 外見、称号、厨房装飾
- 長期: XP、店ランク、通常営業の戦術幅
- 競技: 人数別ランキング、シーズン記録

順位そのものは残してよいが、結果画面の第一メッセージを「12,384位」にしない。自己ベスト差、前回より短縮した工程、上位何%か、次の小目標を併記し、勝てる距離を見せる。

### 2.13 ランダムは適応を生み、技能を消さない範囲で使う

ランダム性は反復に変化を作るが、勝敗を決めすぎると努力の意味を薄める。予測可能な候補、同価値帯、シード固定、事前予告で、対応力を問うランダムへする。[^d1]

- 通常営業の献立3候補: 解放済み料理から同難度帯を提示
- 配達先: 距離帯と経路難度を揃えた候補から抽選し、受注前に見せる
- 注文列: 通常営業はルール内ランダム、競技は全員同一シード
- 厨房変化: 発生時刻の完全ランダム化は避け、予告後に選択または既知周期で発生

### 2.14 作って見せ、測り、即決し、切る

企画書は素早く共有できる形にし、試作で答えを出す。全員が意図を知り、進捗を画面で共有し、懸念は提案と共に即時に出す。デバッグ、モニタリング、初心者観察を継続し、ディレクターは追加だけでなく削除を決める。[^e1][^e2][^k1]

COOKED OUT!の開発では、文書量や機能数を進捗とみなさない。毎週、次の四つを同時に見せる。

1. 実機で遊べるビルド
2. 30〜90秒のプレイ動画
3. 主要計測値
4. 続ける、直す、切るの決定

## 3. A〜N、全カテゴリーの要点と適用

### A. 仕事の姿勢

プレイヤー視点、変更を恐れないこと、密度の高い企画書、強い仕上げ、価値観の幹と枝、責任ある判断、コンセプト維持、発想と削減が中心である。[^a1][^a2][^a3]

COOKED OUT!では、決定ログを「何を決めたか」だけでなく「どのプレイヤー体験を守るためか」まで残す。アート修正が多い現状では、画像を量産する前に、俯瞰実機画面での輪郭、色、サイズ、アニメーションの合格条件を一枚のビジュアル契約へ固定する。

### B. ゲーム性

リスクとリターン、緊張と解放、難しさを自分で選ぶこと、許されるズル、報酬、難度の波、リトライ、一般性、ランキング、作業化、強制感、長所と短所、ハンデが扱われる。[^b1][^b2][^b3]

本作への中心適用は、注文票は自動で流しながら、可搬設備の位置、仕事の優先順位、提供経路をプレイヤーが自然な操作で変えられること。ただし全部を同時に必須化せず、一面の固有判断は原則一種類へ限定する。

### C. 企画・ゲーム設計

すぐ遊ばせる、報酬、少数入力、分解・考察・再構築、自然なチュートリアル、反応と称賛、階層的な仕様、カスタマイズ、既存作品との差、スコアの見せ方、序盤のクライマックス、初心者、時間尊重が中心である。[^c1][^c2][^c3]

特に重要なのは、既存作を物差しにして「同じだが追加要素がある」と企画しないこと。本作では「簡単な共通操作のまま、作業設備の位置まで自分たちで直して攻略する」という独立した言葉で説明できる状態を目指す。

### D. 仕様

停止して見せるべき瞬間、ボタンの重さ、注視点、速度、マップの情報性、想定外の完成形、遊び方の伝達、ランダム、ハンデ、平均化の危険、更新、画面遷移が扱われる。[^d1]

本作では四行動ボタンの数を固定するだけでなく、入力受付、先行入力、対象切替、持ち替え、投げ軌道、衝突減速、アニメーションキャンセルを「気持ちよさの仕様」として数値化する。操作数が同じでも、ここが独自の手触りになる。

### E. チーム運営

情報共有、早い懸念報告、全員の意図理解、日報、継続デバッグ、当日処理、決定を先送りしないこと、デバッグ体制、モニタリング、初心者観察、削る責任が中心である。[^e1][^e2]

実装、ステージ、アート、音を別タスクで並行する場合も、週一回は同じ実機ビルドへ統合しなければならない。個別に美しい画像や正しい機能ができても、最終画面で競合すれば未完成である。

### F. グラフィック

光、判定の強調、重要度、スケール、タッチの統一、絵と楽しさ、監修、ミニチュア性、色調、最終出力、漫画的表現、キャラクター性が扱われる。[^f1][^f2]

本作は「かわいい3D」より先に、「料理、加工状態、容器、設備、床、非操作背景を縮小画面で誤認しない」を合格条件にする。12×9厨房全体をiPhoneで表示した実寸スクリーンショットをアート審査の正とする。

### G. モーション

動作指定、やり過ぎ、構えの速度、フォロースルー、誇張、ポーズ、変形、補間、表情、ブレンドが扱われる。[^g1]

高速調理では、入力から道具接触までは短く、余韻は移動と併存させる。かわいさのために操作を待たせない。設備や食材状態は、静止画でも読めるポーズを先に作り、補間だけに頼らない。

### H. エフェクト

曖昧に見せないこと、キャラクターを立てること、画面振動、正しい大きさ、フラッシュ、パーティクル上限が扱われる。[^h1]

火災、焦げ、完成、注文失効の効果は区別する。常時派手にせず、重要度で面積、持続、音、振動を変える。iPhoneでは発熱、視認性、光刺激への配慮から、全画面フラッシュと連続振動を抑える。

### I. サウンド

ゲーム速度に合うテンポ、SEの重要度、複数環境確認、楽曲数の整理、音の虚実、短いアタック、指示方法、環境音、作品品質としての音が扱われる。[^i1][^i2]

本作の音は「何が起きたか」の優先度で混ぜる。火災と失注直前はBGMより前、加熱完了と注文完成は次、足音と食器は下。章ごとに曲を量産するより、一つの主題を通常、忙しい、残り30秒、結果へ変奏して作品の記憶を作る。

### J. UI

分かりやすさとスタイル、言語ごとの文字寸法、親切設計、ロード、文字強調、世界観、色区分、重要度による大きさ、高速選択、スキップ・停止、ボタン設定、テキスト、ヘルプ、非言語、HUDが扱われる。[^j1][^j2]

COOKED OUT!の「UIと導線を既存作より洗練する」という目標へ最も直接的である。重要情報を厨房中央へ重ねず、対象付近、画面上端、操作領域へ役割分担する。設定は多くても初回画面へ並べず、必要時に見つけられる階層を作る。

### K. プログラム・テクニカル

合理的な命名、調整しやすい構造、パラメータ化、チケット、複数人編集、デバッグモード、透過表現が扱われる。[^k1]

料理、注文、厨房状態、設備、星条件、人数補正をデータ駆動にする現方針は適合する。加えて、ゲーム速度、注文停止、全料理完成、任意厨房状態、通信遅延、擬似切断、当たり判定表示を切り替えられる開発用メニューをCore Alphaから持つ。

### L. 広報

複数の魅力を掛け合わせること、製品像を正しく伝えること、体験版、Web、実ゲーム画面、目の前で遊ぶこと、対象層が扱われる。[^l1][^l2]

トレーラーの一枚目で「料理ゲーム」と分かり、その直後にプレイヤーが厨房を組み替え、注文波を開始し、配達へ飛び出す映像を見せる。独自性を文章で弁明するより、10秒の実画面で理解できる必要がある。

### M. 雑談

制作環境、仕事観、作品・ハードの歴史、遊び手としての観察等を通じ、他カテゴリーの原則がどの経験から生まれたかを補強する。直接的な仕様規則として無理に全てを採用せず、制作者が遊び、現物を観察し、伝達可能な形にする姿勢を汲む。[^m1][^m2]

### N. 企画コンセプト

実作品ごとに、依頼、ハード、対象層、技術、既存ジャンルをどう組み替え、一言で強い企画へしたかが示される。重要なのは完成形を模倣することではなく、制約を作品固有の長所へ変える過程である。[^n1][^n2][^n3]

本作なら、iPhone横持ち、タッチ操作、1〜4人、ソロ通常営業、フレンド協力という制約を弱点として隠さず、短いセッション、直接操作、即時合流、配置のタッチ編集、ノンバーバル共有へ転換する。

## 4. COOKED OUT!の現行仕様診断

### 4.1 そのまま強化すべき点

| 現行方針 | 評価 | 強化方法 |
|---|---|---|
| 少数の共通操作 | 強い | 入力反応、先行入力、自動対象選択の品質を最優先する |
| 星1〜3とスコア更新 | 強い | 星1理解、星2安定、星3最適化と意味を分ける |
| 外部配達の二経路 | 独自核になり得る | 毎回の局所的リスクとリターンへする |
| 12×9固定本店の配置 | 独自核になり得る | 配置を装飾ではなく営業判断へ直結させる |
| 現地提供と外部配達の使い分け | 強い | 全面へ一律に配達を足さず、面の問いを一つに絞る |
| 動物料理人 | 表現上有効 | 顔、耳、尾、体格を状態伝達へ使う |
| 文章に頼らないUI | 強い | 形、動き、音、位置を組み合わせる |
| 一操作リトライ | 必須 | 実測で6秒以内を狙う |
| データ分析と自動テスト | 必須 | 遊びの理解と操作時間を測るイベントを優先する |

### 4.2 再定義が必要な点

#### 「厨房操作は本家と同じ」

参考作品と同じ入力項目を持つこと自体より、COOKED OUT!が目指す反応時間、対象選択、キャンセル、投げ、衝突、復旧を独立仕様にする。文書では以後「同じ」と書かず、次の体験目標へ置換する。

- 一度見れば操作を推測できる
- 押した瞬間に反応が返る
- 忙しい時も対象の選択理由が読める
- ミス後に数秒で仕事へ戻れる
- 初心者の補助が熟練者の速度を妨げない

#### 可変厨房

可変厨房は独自性の最有力候補だが、床、壁、原料箱、水場、提供口まで自由移動できる仕様は、テンポ中断、誤タッチ、責任衝突、最適解固定、経路破綻、同期・QA爆発を起こす。Core Alphaでは次に限定する。

- 本店営業前: 12×9内を広く編集できるが、通路と必須設備を自動検証
- 固定要素: 共通作業台、原料箱、水場、提供口、床、壁、通路は作者が配置
- 可搬要素: 空のまな板、卓上コンロ＋鍋／フライパン、容器スタンド、卓上ゴミ箱等だけを共通作業台間で移動
- 操作: 手ぶらで短く長押しして持ち上げ、既存の持つ／置く操作で空き作業台へ設置
- 制限: 食材が載っている、加熱中、焦げ・火災中の設備は動かせない
- 面設計: 初期配置でも星1、移動を最適化すると星2・3とランキングを狙える

#### 配達

自由運転は笑いを生むが、厨房を離れる時間が長いと、料理協力から別ゲームへ分断される。配達は30〜45秒の独立走行ではなく、短いリスク判断へ圧縮する。

- 近距離、遠距離、危険経路を受注前に見せる
- 配達1件の厨房離脱はCore Alphaで8〜15秒を基準に試す
- バイク事故は長い硬直ではなく、積荷、時間、倍率の一部損失にする
- 配達中も厨房の危険と次注文を簡易表示する
- 目的のない道路遊びは許すが、競技では時間コストが自然な抑制になる

#### 設備レベルと稼ぎ壁

「詰まる→同じ面で稼ぐ→数値強化で突破」は分かりやすいが、反復が作業になり、技能より数値が勝つ危険がある。星1は標準設備で可能にし、レベルは速度の恒常強化だけでなく、選択肢または失敗許容量を増やす。

例:

- 鍋Lv: 単純な全段階高速化ではなく、保温猶予、完成通知の先行、容量型の選択
- まな板Lv: 切断速度だけでなく、一時置き枠か連続作業補助を選択
- バイクLv: 最高速だけでなく、積載、旋回、衝突耐性のどれかを選択

同一ステージ2〜3回で必要額へ届くという現方針は維持できるが、「稼がないと星1が物理的に不可能」は避ける。

### 4.3 量産前に止めるべき点

初期54ステージ、36料理系統、設備Lv1〜5、シーズン、常設ランキング、オンライン、広告を同時に詳細化すると、核が変わった際の手戻りが巨大になる。目標を削除する必要はないが、制作ゲートを設ける。

```text
Gate 0: 15分の独自核試作が面白い
Gate 1: 1-1〜1-3で初見が理解できる
Gate 2: 1-8＋通常営業で30分反復したくなる
Gate 3: ソロ／2人同期で同じ核が成立する
Gate 4: 4料理・8面のデータ駆動量産が安定する
Gate 5: 12→24→36料理、8→18→54面へ拡張する
```

## 5. 抜本的な独自要素「プレイヤー主導営業」

### 5.1 三つの自然な選択

プレイヤー主導は、選択肢の数ではなく、次の三問へ料理中の自然な行動で答える体験とする。

1. **どこで作るか** — 可搬設備を初期位置のまま使うか、別の共通作業台へ移す
2. **何を先にするか** — 自動で入る注文票を見て、工程と役割を選ぶ
3. **どう届けるか** — 自前配達か配送代行を選ぶ

全てを毎ステージへ必須化しない。通常営業は三つをやり込みへ使い、出張営業は毎面一つの固有判断へ焦点を当てる。通常営業の開始前に営業メニューを選ぶ場合も、推奨候補を選択済みにして即開始できるようにする。

### 5.2 基本ループ

```text
注文票が自動で入る
        ↓
初期配置で料理を始める
        ↓
必要なら可搬設備を一台移す
        ↓
料理・受け渡し・優先順位変更
        ↓
自前／代行／まとめ配送を判断
        ↓
結果で「選択→結果」を可視化
        ↓
同条件または別方針で即リトライ
```

### 5.3 選択をゲームにする六条件

各選択は全て以下を満たす。

1. 二秒以内に違いを比較できる
2. 正解が常に一つではない
3. 結果が30秒以内に返る
4. 失敗しても立て直せる
5. 初心者は選ばなくても最低限進める
6. 熟練者にはスコア差が出る

### 5.4 可変厨房のデメリットと対策

| リスク | 何が悪いか | 初期対策 | 検証指標 |
|---|---|---|---|
| 調理テンポ中断 | 配置画面が主役になる | 営業中はドック間の一手移動だけ | 移動操作の中央値2秒以内 |
| タッチ誤操作 | 料理中に設備を誤選択 | 長押しハンドル、専用輪郭、実行前ゴースト | 誤配置率5%未満 |
| 初心者負荷 | 何を動かすか分からない | 最初は二状態、推奨状態を表示 | 初見正解意図理解80%以上 |
| マルチの妨害 | 他人の作業を壊す | 予約表示、短い取消、即復帰状態 | 意図しない取消・口論の観察 |
| 一人支配 | 一人だけが配置を決める | 複数地点の局所レバー、同時仕事 | 手持ち無沙汰時間10%未満 |
| 最適解固定 | 毎回同じ配置になる | 固定された原料箱・水場・提供口と料理構成で価値を変える | 上位記録の配置多様性 |
| 経路破綻 | 詰みや到達不能 | グリッド接続検証、必須通路予約 | 進行不能0件 |
| 同期・QA増大 | 組合せが爆発する | 状態ID同期、任意座標を送らない | 100回切替の不一致0件 |

### 5.5 間口を狭めないための補正

「プレイヤー主導」を、全員が常に多数の選択を比較するゲームにはしない。目標は、初心者でも料理へすぐ参加でき、慣れたプレイヤーだけが同じ操作の奥にある判断を使って得点を伸ばせる構造である。

そのため、先に挙げた三つの選択を全て必須にはしない。出張営業では一面につき固有判断を一種類、通常営業では推奨設定を選べば詳細判断を省略できるようにする。

```text
初心者: 目の前の仕事をするだけで貢献し、星1へ届く
慣れた人: 先読み、受け渡し、厨房切替で星2・3へ届く
競技者: 配置、注文波、配達経路まで最適化してスコアを伸ばす
```

厨房内のレバーを一度押す、完成料理を二つの置き先から選ぶ、といった自然な一動作を優先し、営業を止める選択画面を増やさない。「何も選ばない」場合には安全な推奨状態で進み、理解している人だけが自発的にリスクを取れるようにする。

## 6. UI・導線・UXの具体方針

### 6.1 画面ごとの一番大事な行動を一つにする

| 画面 | 第一行動 | 二次行動 | 隠してよいもの |
|---|---|---|---|
| 起動後 | 続きから遊ぶ | 通常／出張／マルチ | 規約済み通知、詳細設定 |
| ステージ選択 | 次のステージ開始 | 過去面・ランキング | 報酬内訳、詳細統計 |
| 営業前 | 営業メニューと配置を決める | 推奨へ戻す | 詳細パラメータ |
| 営業中 | 料理と危険判断 | スコア確認 | 長文説明 |
| 結果 | 次へ／再挑戦 | 詳細分析 | 複数回の報酬受取 |

重要な項目は視覚上も大きくする。ただし「大きいボタン＝常に強制」にならないよう、戻る、設定、スキップは位置を固定して発見可能にする。

### 6.2 厨房HUD

- 上中央: 最大5枚の注文票。残り時間より工程と現在完成可能性を先に読む
- 上左: 営業時間とフェーズ予告
- 上右: スコア、連鎖、次の小目標
- 対象付近: 実行可能操作、進捗、失敗理由
- 画面端: 配達中の仲間、積荷、帰還見込み
- 左下: 移動。右下: 四行動。指で厨房中央を隠さない

注文票は完成品画像、材料、工程を絵で示す。蓋は注文票上で開き、完成品を識別できる。色だけに頼らず、材料形状、切断記号、加熱記号、器の輪郭を併用する。

### 6.3 結果画面

結果は「褒める→理由→次の一手」の順にする。

1. 星、自己ベスト、チーム成功演出
2. 失注、焦げ、停止時間、配達経路等の最大改善点を一つ
3. 前回比と次の到達可能な目標
4. 再挑戦、次へ、退出

生スコアを内部に隠して競技スコアだけ見せる現方針は成立する。ただし、換算理由がプレイヤーに不透明で「同じ行動なのに点が違う」と感じないよう、人数別ランキング、条件固定、加点イベントの一貫性を守る。

### 6.4 アクセシビリティ

独立したアシストモードを作らない方針でも、利用しやすさの設定は必要である。

- HUD倍率、字幕・文字倍率
- 色覚向け記号、コントラスト
- 画面振動、カメラ揺れ、点滅の軽減
- 振動強度、左右ボタン配置、ボタン間隔
- 長押し時間、連打を長押しへ置換
- 音量カテゴリ別調整
- チュートリアル再表示

これらは難度を下げる特別扱いではなく、同じ判断へ到達するための入口である。

## 7. チュートリアル第1章への適用

### 7.1 全体原則

- 説明してから遊ぶのではなく、触ると反応し、成功すると次が開く
- 一面の新要素は主題一つ、補助一つまで
- 文章は行動を代替せず、詰まった時の補助にする
- 初見は安全に見せ、二回目から本番判断へする
- 各面に一度は「自分がうまくやった」と分かる連鎖成功を作る
- 1-3でマルチ解放するなら、1-3終了時点で本作固有のプレイヤー主導選択も一度経験させる

### 7.2 改訂案

| 面 | 学ぶ操作 | 面白さの先出し | プレイヤー主導要素 |
|---|---|---|---|
| 1-1 | 移動、取る、切る、組立、提供 | 一皿目を30〜45秒以内に完成し連鎖演出 | なし。まず迷わず料理させる |
| 1-2 | 注文票、鍋、加熱タイマー | 加熱中に別作業を進め、同時完成 | なし。自動注文と加熱監視へ集中させる |
| 1-3 | 投げ、容器、バイク | 投げ→完成→短距離配達を一続きに成功 | 自前高得点／代行安全の二択を一度行う |
| 1-4 | ダッシュ、注文順 | 連鎖提供で圧力を一気に解放 | なし。移動と注文優先順位へ集中させる |
| 1-5 | フライパン、部品合流 | 二工程が同時に完成 | 配置済み二ドックから一つを選ぶ |
| 1-6 | 焦げ、火災、復旧 | 事故後すぐ二皿成功 | 安全策／高得点策を選び直す |
| 1-7 | 現地提供、皿洗い | 皿循環が噛み合う連続提供 | 返却皿の一時流路を切替 |
| 1-8 | 既習総合、可搬厨房 | 自動注文を自分たちの配置でさばく | 可搬設備一台と二経路を統合 |

1-1へ選択を入れるのは操作説明を増やすためではない。本作が何のゲームかを最初に約束するためである。選択UIは二枚の絵から一枚を押すだけにし、選ばなくても数秒後に推奨案が始まる。

### 7.3 マルチ解放

1-3後のマルチ解放は維持できる。ただしゲストが未習得要素を含む面へ参加できる仕様では、ロビーに長いガイドを出すのではなく、未習得アイコンと30秒の任意プレビューを示す。プレイ中は仲間の行動を見て学べるよう、持ち物、対象、投げ先、操作中モジュールを明瞭にする。

## 8. ステージ設計へ適用する規則

### 8.1 一面一問

各ステージは、プレイヤーへ投げる問いを一つにする。

- どの順番で運ぶか
- いつ厨房を切り替えるか
- 誰が配達へ出るか
- どこで中間部品を合流させるか
- どの設備をどの作業台へ置くか

複数ギミックがあっても、同じ問いを強める時だけ併用する。

### 8.2 一面レビューカード

各面のグレーボックス前に以下を一枚で埋める。

| 項目 | 質問 |
|---|---|
| 一文コンセプト | 既存作名なしで面白さを説明できるか |
| 主な問い | プレイヤーは何を決めるのか |
| リスク／リターン | 何を危険にさらし、何を得るか |
| 圧力／解放 | 最も忙しい10秒と、気持ちよい10秒はどこか |
| 初見理解 | 文字なしで最初の行動を推測できるか |
| 良い失敗 | 笑えて、次の改善が分かる失敗は何か |
| 悪い失敗 | 見えない、戻れない、責任不明な失敗をどう防ぐか |
| 初心者 | 星1まで何を免除・緩和するか |
| 熟練者 | 星3でどんな工夫が伸びるか |
| 人数差 | 1、2、3、4人で手持ち無沙汰と過密がないか |
| 独自性 | プレイヤー主導の選択が最低一つあるか |
| 計測 | 仮説の成否を何のログで判断するか |

### 8.3 難度の作り方

新料理、初見ギミック、長距離、設備競合、短い注文期限を同時に上げない。章内は単調な坂ではなく、導入、応用、解放、複合、休息、章試験の波にする。

```text
2-1 新しい問いを安全に理解
2-2 同じ問いを速度化
2-3 別の料理で転用
2-4 既習要素と組み合わせ
2-5 ごほうび的に大量連鎖
2-6 章の総合判断
```

背景が動くだけの移動厨房は、難度要素ではなく雰囲気と高揚を担う。そこへ無理に操作妨害を足さない。

## 9. アート、モーション、エフェクト、音の制作基準

### 9.1 アート

- 正方形グリッドと操作可能面の輪郭を最優先する
- 背景は厨房より彩度、明度差、細部密度を一段下げる
- 食材は未加工、切断、加熱、完成、焦げをシルエットでも区別する
- 共通容器は統一するが、中身、湯気、液体、量で料理を識別する
- 料理単体画像ではなく、12×9俯瞰、注文票、手持ち、台上の四寸法で承認する
- 最終照明、影、輪郭、UIを重ねた画面を正とし、モデル単体レンダーだけで決めない

### 9.2 モーション

- 移動開始とアクション発生を最短にする
- 大きな顔、耳、尾で状態を先読みさせる
- 重要なポーズは止め絵で読める
- 余韻は操作不能時間にせず、移動中にブレンドする
- 投げの構え、軌道、着地は三者が一致する
- キャラクター種ごとの差は当たり判定や性能へ影響させない

### 9.3 エフェクト

- 完成、焦げ予告、焦げ、火災、失注、厨房切替を固有形状にする
- 重要度と画面面積を比例させる
- パーティクルで食材や床を隠さない
- 画面揺れと点滅は設定で軽減可能にする
- 低性能iPhoneの上限を基準に発生数を制限する

### 9.4 サウンド

- 火災、失注直前、厨房変化予告を最上位
- 加熱完了、注文完成、配達到着を次点
- 取る、置く、切る、投げるは短く識別可能にする
- 忙しい場面ほど長い残響を減らし、音の頭を明瞭にする
- BGMは章ごとの大量新曲より、主題の変奏とレイヤーで統一感を作る
- イヤホン、iPhoneスピーカー、小音量、無音＋振動の全てで確認する

## 10. 制作、実装、QA、データ分析への適用

### 10.1 仕様の階層

```text
L0: 一文コンセプト
L1: 体験原則（忙しいが理解できる、プレイヤー主導等）
L2: 中核ループとモード差
L3: 共通操作・状態・得点契約
L4: ステージ／料理／設備データ
L5: 演出値、秒数、座標、端末別調整
```

下位仕様が上位原則に反する時は、実装済みでも見直す。逆にL5の微調整を、全体方針の議論へ戻さない。

### 10.2 Core Alphaに必要なデバッグ機能

- ゲーム速度0.25、0.5、1、2、4倍
- 営業時間停止、任意秒数移動
- 任意注文列と固定乱数シード
- 全食材・料理状態の生成
- 鍋、フライパン、火災、皿、容器の状態変更
- 可変厨房の全状態切替と経路検査
- プレイヤー人数の擬似設定
- 通信遅延、パケット欠落、切断、再接続
- 対象選択範囲、NavMesh、グリッド、当たり判定の可視化
- スコア内訳と星閾値の表示
- 画面解像度、Safe Area、UI倍率の切替

### 10.3 記録すべきイベント

ログは数を集めるためではなく、設計仮説へ答えるために取る。

| 仮説 | 指標 |
|---|---|
| 最初から面白さが伝わる | 初操作、初完成、初選択、初提供までの時間 |
| UIが伝わる | 誤対象、無効入力、ヘルプ再表示、停止時間 |
| プレイヤー主導が機能する | 各選択率、選択後の変更率、選択別成功・得点 |
| 可変厨房が作業でない | 操作時間、誤配置、元へ戻す率、状態多様性 |
| 配達が分断しない | 厨房離脱時間、配達中の無操作、帰還後の仕事復帰時間 |
| 難度の波が適切 | 10秒窓ごとの入力、移動、待機、危険件数 |
| 再挑戦したくなる | 結果からリトライ率、リトライ開始までの時間 |
| マルチで全員参加する | 人別の作業、待機、移動、提供、配達割合 |

### 10.4 テスト方法

自動テストだけでは「面白い」「伝わる」を判定できない。三層で行う。

1. **自動**: 状態遷移、得点、保存、経路、同期、ビルド
2. **観察**: 説明しない初見プレイ。発言より手の停止と誤操作を見る
3. **熟練**: 最適化、抜け道、ランキング公平性、長時間反復

開発者が横で説明したテストは、チュートリアル評価として無効にする。子どもを対象にする場合は、本人の同意、保護者対応、データ最小化等を別途整える。

## 11. ランキング、長期運営、収益化

### 11.1 ランキング

1-1から全ステージを競技対象にする考えは面白い。簡単なルールほど純粋な最適化が出る。ただし順位だけでは大多数を敗者にするため、次を併記する。

- 自己ベストと前回差
- 友人内順位
- 上位割合
- 次の現実的な到達点
- 人数別、条件別の明確な区分
- 不正・切断・バージョン違いの扱い

結果画面では「競技スコア」を単に「スコア」と表示する現方針を維持できる。内部の生スコアを見せなくても、同じ条件と行動には一貫した表示結果が返る必要がある。

### 11.2 デイリーとシーズン

毎日ログインすると得をする設計は、遊びたい時に遊ぶ自由を壊さない範囲にする。連続ログインを逃した時の損失を大きくせず、七日周期の途中再開や取り戻しを許す。デイリーは通常の楽しい行動を少し変える課題にし、退屈な回数稼ぎにしない。

### 11.3 広告と常時オンライン

常時オンラインと強制広告は、プレイヤー時間、遷移速度、初回体験、再挑戦の四点で強く衝突する。広告収益の仮説だけで採用せず、以下を比較実験する。

| 方式 | UX | 収益 | 推奨 |
|---|---|---|---|
| リトライ間の強制広告 | 最悪。反復の核を壊す | 短期表示は増える | 不採用推奨 |
| 数営業ごとの強制広告 | 区切り次第 | 中 | チュートリアル、初回、マルチでは不採用 |
| 任意報酬広告 | 選択を守れる | 視聴率次第 | 主候補。ただし拒否時に罰を作らない |
| 外見課金 | ゲーム技能を壊さない | 商品品質次第 | 主候補 |
| 買い切り広告除去 | 明快 | 転換率次第 | 候補 |

ソロ常時オンラインは広告表示のためだけに必須化せず、ランキング送信、クラウド保存、広告取得は接続時、基本営業は切断耐性を持たせる方が、初回離脱と移動中利用には有利である。これは現行決定を上書きするものではなく、Core Alpha後に計測して決めるべき重要再検討項目である。

## 12. 採用判断表

### 12.1 直ちに採用する

- 既存作名を使わない一文コンセプト審査
- 一面一問、主な難しさ一つ
- 入力に対する無反応の排除
- 一操作リトライと短い遷移
- 重要度に応じたUI、視覚、音の強弱
- 初心者の観察テスト
- 実機最終画面でのアート承認
- データ駆動パラメータとデバッグモード
- 懸念と代案を当日共有する制作ログ
- 量産前ゲート

### 12.2 Core Alphaで条件付き採用を試す

- 営業前の本店設備配置と推奨配置
- 営業中に空の可搬設備を共通作業台間で移す仕組み
- 通常営業開始前の営業メニュー三択
- 共通作業台上の可搬設備
- 自前配達、代行、まとめ配達のリスク差
- 設備Lvを速度ではなく戦術選択へ寄せる案
- 1-1で本作固有の選択を見せる案

### 12.3 現時点で不採用または延期する

- 原料箱、水場、提供口、床、壁を含む営業中の全面自由配置
- 可変厨房の任意座標ネットワーク同期
- 初期から54面・36料理を本番品質で一括量産
- 星1突破に必須の長い稼ぎ壁
- リトライ間の強制広告
- 順位だけで継続動機を作る設計
- 操作感、UI、盤面を「本家と同じ」として確定すること
- 更新で直せることを前提に弱い初回版を出すこと

## 13. Core Alphaの優先順位を組み替える提案

現在の2週間計画は機能範囲が広い。桜井氏の原則を適用するなら、完成機能数より「独自核が初見で成立したか」を終了条件に加える。

### P0: 最初の3日

1. 一文コンセプトを仮固定する
2. 1-1相当の一厨房で、可搬設備一台と自前／代行を試す
3. 仮アセットで15分反復できるようにする
4. 入力、対象選択、即リトライを磨く
5. 説明なしテスト3〜5人で、理解と二回目意欲を観察する

### P1: 成立後

1. 1-1〜1-3へ自然な学習順で分解する
2. 1-8へ全体ループを統合する
3. 通常営業へ配置、営業メニュー、提供経路を広げる
4. ログ、デバッグ、自動テストを接続する
5. iPhone実機の最終画面でアート、UI、音を調整する

### P2: 延期可能

- 1-4〜1-7の本番美術
- Tier3〜5
- 店ランク10の全表示
- 全配置プリセット
- 本格ランキング、シーズン、広告
- 54面と36料理の量産

2週間終了時の合格条件へ、次を追加する。

- 初見者の80%以上が、本作固有の選択を説明なしで一度使える
- 10分プレイ後、何を改善して再挑戦したいかを一つ言える
- 無効入力の90%以上に認識可能な反応がある
- 一営業に占める操作不能時間が5%未満
- 一操作リトライから6秒以内に再操作できる
- 可変厨房を使わない場合と使う場合で、攻略方針が実際に変わる

## 14. 今後の仕様判断チェックリスト

新しい仕様、料理、ギミック、UI、課金を加える前に確認する。

1. 既存作品名なしで価値を説明できるか。
2. プレイヤーが何を判断するのか。
3. リスクとリターンは近く、比例しているか。
4. 入力と結果は明確に返るか。
5. 忙しさに山、解放、息継ぎがあるか。
6. 初心者は理解でき、熟練者は工夫できるか。
7. 失敗から短時間で戻れるか。
8. 文字、色だけに依存せず伝わるか。
9. 最終的なiPhone画面と音で成立するか。
10. 調整値をデータで変えられるか。
11. 仮説をログと観察で判定できるか。
12. 同じ価値をより小さな仕様で実現できないか。

一つでも重大な否定があれば量産へ進めず、試作、簡略化、延期、削除のいずれかを選ぶ。

## 15. 最終提言

COOKED OUT!が「似ている料理ゲーム」から抜け出すために必要なのは、料理を複雑にすることでも、奇抜な厨房を増やすことでもない。

**注文は自動で流れる分かりやすさを保ったまま、厨房の道具を自分たちで整え、仕事の優先順位と届け方を変え、立て直せるものにすること**が最も有望である。

この改革は通常営業、出張営業、配達、可変厨房、スコア、マルチ協力を一つに束ねられる。ただし、自由度を増やしすぎると管理、誤操作、最適解、口論、QA負荷に変わる。したがって「少数の意味ある選択」「すぐ返る結果」「いつでも立て直せる」の三条件を守る。

最初に完成させるべき商品単位は54面ではなく、**一度遊ぶと別の方針でもう一度試したくなる15分**である。その15分を説明なしで成立させた後、料理、ステージ、アート、オンライン、ランキングを拡張するのが、全254章からCOOKED OUT!へ引ける最も重要な制作順である。
