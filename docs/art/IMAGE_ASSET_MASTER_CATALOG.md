# COOKED OUT! 画像アセット・マスター台帳 v0.1

- 更新日: 2026-09-11
- 状態: 初期正式版に必要な画像資産の種類を網羅。個別ID・正確な数量は料理派生数とステージ詳細の確定後に固定
- 対象: コンセプト画像、2D UI、3D制作資料、ストア素材。音声、プログラム、3Dモデルそのものは対象外
- 制作原則: キャラクターは全員動物。注文票では共通容器の透明蓋を開き、ゲーム内完成品では閉じる

## 1. この台帳の使い方

AI画像は「完成ゲームへそのまま入れる画像」と「3D・UI制作の設計資料」を分ける。厨房設備、キャラクター、食材は最終的に一貫した3Dモデルへ作り直し、生成画像をそのままメッシュ化しない。UIの単純な記号、枠、ゲージは、生成画像よりFigma等のベクターまたはUnity UIで制作する。

各資産は次の状態で管理する。

```text
未着手 → ラフ → 方向承認 → 制作資料完成 → 実装用制作 → ゲーム内確認 → 完了
```

ファイル名には `asset_id`、`style_version`、版番号を含め、生成元、入力画像、プロンプト、手修正、権利確認を `ASSET_PROVENANCE.csv` に記録する。

共通コック帽と共通制服を維持し、種固有の顔・腕・脚・耳等を差し替える。人間、写実的な獣、白手袋、種ごとに異なる職業服は使わない。

本番3Dの納品条件は[キャラクター3D本番制作仕様](CHARACTER_3D_PRODUCTION_SPEC.md)を正とする。Unityは所定のカピバラPrefabを検査して読み込み、不完全または未納品の場合はgrayboxを使用する。

[第14ラウンド](VISUAL_DEVELOPMENT_ROUND_14.md)でカピバラのBlender編集正本、10骨FBX、3段階Skinned LOD、URP Lit材質、本番Prefabを作成し、Unityの優先読込へ接続した。出荷状態ではなく本番候補であり、実機負荷と材質の承認後に残る11体へ展開する。

[第15ラウンド](VISUAL_DEVELOPMENT_ROUND_15.md)でカピバラ本番候補を、より大きい顔と目、短い手足、強い色面、丸い面取りへ改修した。既存作品の固有表現は複製せず、一般的な可愛さと固定俯瞰での可読性を強化したv2基準を作成した。

[第16ラウンド](VISUAL_DEVELOPMENT_ROUND_16.md)で通常表情を歯・舌・口内のない閉じ口へ改修した。小耳、広い二葉口吻、鼻、輪郭で種を識別し、前歯には依存しないv3を現在の3D基準とする。

[第18ラウンド](VISUAL_DEVELOPMENT_ROUND_18.md)で、レタス・にんじん・玉ねぎの未加工／切り済み計6状態をBlender編集正本と製品用候補FBXへ移行した。完成料理と鍋内容はレシピ状態に応じる動的表示を維持し、注文票とゲーム内完成品の蓋規則も変更しない。

料理画像は、細かな盛り付けより大きな色面と形を優先する。一注文は通常4部品以下、最高難度でも5部品以下とし、小さい注文票で材料差を判別できることを採用条件にする。

同じ工程文法でも料理系統が異なる場合は完成輪郭を変え、同じ料理系統内の3〜5注文派生は土台と容器内配置を固定して一つの主材料スロットだけを大きく追加・差し替える。36系統シートは代表形の台帳であり、派生画像は代表形の承認後に一注文一生成で作る。

## 12. 量産開始ゲート

画像量産用の別タスクは、最初に次の順で作業する。

1. 全動物12体の候補名簿と選択肖像を作り、種と顔の幅を確認する
2. 料理36系統を12種×3枚で作り、注文票では蓋を完全に開く
3. 基本設備と1-1〜1-3厨房で、材質・色・輪郭を固定する
4. 三つが同じ作品に見えることを確認し、`style_version 1`を宣言する
5. その後だけ個別注文票、三面図、章別厨房を量産する

第10ラウンドで第1〜9章の厨房キーアート承認候補9枚を作成した。比較・評価と章別プロンプトは[ビジュアル開発 第10ラウンド](VISUAL_DEVELOPMENT_ROUND_10.md)を参照する。

新しい画像を作るたびに、[ビジュアル基準](VISUAL_BIBLE_AND_IMAGE_FACTORY.md)と[来歴台帳](ASSET_PROVENANCE.csv)を更新する。
