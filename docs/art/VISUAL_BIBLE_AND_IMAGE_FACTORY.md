# COOKED OUT! ビジュアル基準・画像量産工程 v0.7

- 更新日: 2026-09-11
- 状態: キャラクター、料理、設備、厨房の`style_version 1`方向を固定。個別制作へ展開中
- 目的: 毎回異なる画風になることを防ぎ、キャラクター・料理・厨房画像を短時間で量産する

## 1. 共通造形言語

- 角を丸めた太い形、少ない部品、低いテクスチャ密度
- 写実ではなく、手で成形した玩具・粘土のような3D
- 小画面では細部より輪郭、大きな色面、状態差を優先
- 照明は明るい中立光。強い被写界深度、映画的な暗部、光沢過多を避ける
- UI用画像には文字、ロゴ、背景の物語要素を入れない
- 参考作品の固有キャラクター、衣装、厨房配置、UI、色配置は複製しない

## 2. キャラクター基準

- 全身は約2頭身、選択画面では顔・帽子・肩を大きく表示
- 初期12体はすべて動物。人間キャラクターは採用しない
- 初期名簿はカピバラ、カエル、アホロートル、ヤギ、カワウソ、カメレオン、タヌキ、ウサギ、ブタ、ニワトリ、ペンギン、ワニ
- 分類は哺乳類6、鳥類2、爬虫類2、両生類2。分類数の均等さより、顔の輪郭と種固有部位の見分けやすさを優先する
- 帽子と基本制服の形は共通
- 顔、頭部、耳、角、外鰓、腕、脚、尻尾等は固有
- 大きな単純な目、小さな鼻、広く読める口と眉
- 一キャラクター一つの明確な外形特徴に絞り、小物を増やさない
- 全員が同じ骨格、手の作業位置、当たり判定へ収まることを優先
- 最初の外見課金は新動物の販売より、共通帽子・制服の外見セットを中心にし、無料キャラクターの選択肢を狭めない

第5ラウンド画像は顔の読みやすさの基準候補である。帽子は添付参考と似すぎないよう、本番三面図では膨らみ数、帯位置、傾き、後頭部形状をさらに独自化する。

## 3. 料理基準

- 注文票は共通配達容器を上から約20〜30度傾けて表示
- 容器は全料理で同じ大きさ。料理が画面面積の70〜80%を占める
- 主材料を2〜4個の大きな塊で表現する
- 微細な刻み、粉、複雑なソース模様、写実的な照りを避ける
- 同系統の派生は土台の輪郭を共通にし、追加材料一つを大きく変える
- 生、切り済み、加熱済み、焦げを形と色の両方で区別する
- 透明蓋はゲーム内完成モデルでは閉じ、注文票では完全に開いた状態で表示する

### 3.1 同じ工程・同じ料理系統の中身違い

料理の見た目は、`工程文法 → 料理系統 → 注文派生`の三段階で管理する。

- 工程文法が同じでも料理系統が異なる場合は、完成品の大きな輪郭、主色、占有方向のうち二つ以上を変える。色替えだけで別系統にしない
- 同じ料理系統の注文派生は、土台、容器内の配置、カメラ、縮尺を固定し、追加または差し替える主材料を原則一つだけ大きく変える
- 追加材料は、小さな散らしではなく、注文票を縮小しても読める一塊または一帯として置く
- 差は色だけにせず、円、角、葉、帯、塊等の形状差も持たせる
- 材料数は通常4以下、最高難度でも5以下とし、派生差を細部の数で作らない
- 36系統のスタイルシートは各系統の代表形であり、108〜180件の注文派生そのものではない
- 派生量産時は系統代表画像を固定アンカーにし、`変更する材料スロットだけ`を一回ずつ差し替える。複数派生を一回の生成数指定で作らない
- 注文票では透明蓋を完全に開き、ゲーム内完成品の設計では同じ中身のまま蓋を閉じる
- 注文票と完成品はレシピ定義にない材料を描かない。見栄え用の飾り材料も注文材料として定義されるまでは追加しない

例:

- グリーンサラダ: レタスの土台を固定し、トマト帯またはキュウリ円を大きく追加
- サンドイッチ: パンと積層幅を固定し、野菜層、卵層、肉層の主役を差し替え
- 寄せ鍋: 汁面と葉物の大配置を固定し、肉巻き、魚介、野菜塊の主役を差し替え

## 4. 厨房基準

- 固定高角度の三人称俯瞰、正方形論理グリッド
- 標準設備は一セル幅、床目地は中程度
- 厨房中央を空けすぎず、島、短い補助台、通路幅の変化で密度を作る
- 料理に触れる設備だけ識別色を使い、外周背景は彩度と情報量を下げる
- 食材供給箱は本体を共通化し、上面の角丸写真カードだけを食材ごとに交換する
- 写真カードは食材一個を中央へ大きく置き、文字と色だけに依存せず輪郭でも識別する
- 供給箱の写真カードと、操作で生成される食材IDは同じデータ参照から決める
- コンセプト画像は美術参考。実装配置はステージデータを正とする

## 5. 固定テンプレート

### キャラクター選択画像

- 4×2または3×2の等間隔グリッド
- 正面寄り胸上、帽子全体を含む
- 無地の暖色背景、全員同一カメラ・同一照明
- 文字、矢印、選択UIなし

### 料理スタイルシート

- 4×3で12料理、または3×2で6料理
- 同一容器、同一カメラ、同一縮尺
- 無地の明るい背景、文字なし
- 36系統は12種×3枚に分けて確認し、その後個別切り出しを作る

### 厨房コンセプト

- 10×8等の論理サイズを別途明記
- 厨房全体と外周を一画面に収める
- プレイヤー1〜4体は実際の操作位置へ置く
- 画像内の設備数・座標を実装仕様として採用しない

## 6. 量産工程

1. 基準画像を承認し、`style_version`を固定する
2. キャラクター、料理、食材、設備ごとにマスタープロンプトを固定する
3. 変数だけをCSV化する。例: `asset_id`、料理名、材料、主色、状態、カメラ
4. 一資産一生成で出力し、複数種類を一回の`n`指定で済ませない
5. 形、色、背景、文字混入、類似性、料理内容を人が検査する
6. 承認画像をワークスペースへ保存し、来歴台帳へプロンプト、入力、生成元、修正内容を記録する
7. 3D本制作では画像を直接メッシュ化せず、モデラーが共通寸法・ポリゴン・UV・LODへ再構築する

## 8. 承認ゲート

次の四点を承認したら`style_version 1`として量産を始める。

1. 第5ラウンドの顔の大きさと帽子の方向
2. 全動物12体の種と顔シルエット
3. 第5ラウンド料理画像の容器角度、簡略度、色の強さ
4. 厨房の材質、床目地、設備識別色

量産開始後に基準を変えると全画像の再生成・再修正が発生するため、ここだけは先に固定する。

必要資産の全分類、用途、優先順位は[画像アセット・マスター台帳](IMAGE_ASSET_MASTER_CATALOG.md)を正とする。画像生成は企画相談とは別の専用タスクで進める。
