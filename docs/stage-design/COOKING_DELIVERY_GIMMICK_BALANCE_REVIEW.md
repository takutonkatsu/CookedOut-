# 料理・配達・ギミックの負荷比較とパーティ性の検討

- 日付: 2026-09-15
- 状態: 資料に基づく評価と相談案。新しい採用決定・料理変更・共通仕様変更・実装なし。
- ユーザーの懸念: 料理が本家より難しければ、配達とギミックの重ね合わせが過剰にならないか。一方、仕掛けが少なすぎると単調ではないか。
- 比較対象: 主にOvercooked! 2の通常本編の料理文法。本家DLC・最高星・高難度面と本作の初見星1を混ぜて優劣を断定しない。

> 最新相談（2026-09-16）: 「料理や調理工程の豊富さ、配達で差別化し、多少のギミックを入れる」方向の是非とデメリットを§10に追記。方針決定ではなく評価・提案。

## 1. 結論

本作の全料理が本家より難しいとは言えない。序盤は同程度の文法だが、後半には中間素材の作成・複数の機械処理・別系統の合流が重なる料理があり、厨房内の管理負荷が高くなる懸念はある。工程秒数・移動距離・注文密度・星の具体基準点が未実測なので、総合難度や何倍難しいかは確定できない。

現時点の提案は、確定献立を維持し、面の負荷を料理・提供方式・配置・ギミックで分けて調整すること。ギミックの種類の多さと、同じ瞬間に対処する量、失敗の損失を分離して扱う。これはS-D004の「シンプルなギミックをいくつも取り入れたい」と両立する。

## 2. 料理工程の比較

根拠は[全60品の最新台帳](../cooking-design/CAMPAIGN_CHAPTERS_1_8_COOKING_CATALOG.md)、[本家2既存調査](../research/17_overcooked2_base_game_complete_reference.md)。料理専用の[検討本文冒頭](../cooking-design/COOKING_DESIGN_WORKING.md)も確認した。第1章の比較案表記については従来通り台帳掲載構成を最新計画基準とし、別案まで承認しない。

| 対象 | 本作の構造 | 評価 |
|---|---|---|
| グリーン／トマトサラダ | 切って提供容器へ載せる | 本家と近い基本工程で、操作が特に複雑なわけではない |
| オムレツ・焼きそば | 材料を揃え同じフライパンで加熱 | 成型・混ぜ方・麺の下茹で等を追加しておらず、単一路線の加熱料理 |
| 焼肉おにぎり・ラーメン等 | 米・麺の鍋と具のフライパンを並行し、提供容器で合流 | 本家のブリトー・パスタにも近い並行調理があり、この構造だけで本家以上と断定しない |
| ミートソースパスタ（6-6） | 麺鍋＋肉のミキサー処理＋トマトの別ミキサー処理＋玉ねぎ切断＋具の加熱＋合流 | 一食でミキサー二回。材料4種類でも器具の競合と中間素材管理は軽くない |
| ピザ（8-3・8-4） | 生地とトマトを別々にミキサー加工し、トレーで合流後に焼く | 本家の切断・組立中心のピザに対し、機械処理待ちと容器の受渡しが増える懸念。ただし切る操作をミキサーへ置き換えるため、単純な入力回数増とは限らない |
| 肉餃子（8-5・8-6） | 生地と肉を別々にミキサー加工＋葉野菜を切る→自動形成→加熱 | 手包みは不要だが、複数の中間素材を揃える必要がある |
| 天丼（7-5） | 米鍋と、ミキサー衣→衣付け→フライヤーの枝を合流 | 材料・器具・別工程を同時に扱うため、単純な揚げ物とは負荷が異なる |

本家2にも混合後の加熱を要するケーキ・パンケーキ・蒸し料理があるため、「ミキサーがあるから本作だけ難しい」という比較はしない。[料理文法の公開説明](https://www.fanatical.com/en/blog/overcooked-2-new-recipes-whats-being-served)

今回のWeb確認では本家Wiki個別ページの本文が取得できないものもあり、その細部は既存保存調査に基づく。工程時間の直接比較・全レシピの操作回数採点はしていない。

## 3. 難度を抑えている既定仕様

- 一料理の材料単位数は最大4。本編各面の必要原料種類も最大4。ただし工程数・物理箱台数の上限を意味しない。
- 自動形成で、餃子を包む・ハンバーグを手で成型する等の専用操作はない。
- 熱源の外で材料を揃えられ、高速な追加入力を必須にしない。
- ミキサージャーの洗浄はなく、中身は対応先へ全量を移す。ミキサー加工完了後に焦げない。
- 可搬設備の移設は工夫の余地だが、初期配置で成立することを設計側で確認する。

4原料制限や簡単な入力があっても、同時監視と移動・受渡しが少ないという保証ではない。自動処理が増えることには、待ち管理が増える面と、手を離せる面の両方がある。

## 4. 学習頻度の懸念

台帳上、新料理がないのは3-6・5-6だけで、48面中46面には少なくとも一品の初出料理がある。60品中35品は本編一面のみの登場。これは工程や操作が46回すべて新しいという意味ではなく、材料差し替え等の派生を含む。

それでも「慣れた料理を無意識に回しながらギミックを覚える」面を作りにくい可能性がある。新料理なしの3-6も四品の注文候補があり、無条件にギミックを重くしてよいとは言えない。

本作で本家以上になり得るのは、一皿の操作難度だけでなく、レシピ確認・器具競合・配達判断を同時に要求する頻度。献立や登場順を今ここで変更せず、配置と注文負荷を含めて検証する。

## 5. 配達は全てが単純な追加ではない

根拠: [CURRENT_GAME_SPEC §4.6、§5](../game-design/CURRENT_GAME_SPEC.md)。

- 現地提供型は配達なし。皿洗いも選ばれた面だけに導入する。
- 外部配達型は共通使い捨て容器を使い、皿洗いがない。完成料理を容器へ入れるので、皿盛付けに別の梱包工程を丸ごと追加するとは扱わない。
- 外部型では自配達と代行を注文ごとに選べ、現行方針で星1〜3・進行はどちらでも達成可能。ただし達成は未実測で、代行の受付枠と到着待ちは残る。
- 自配達では積載・運転・納品・厨房から人が離れる負荷がある。既定の自動納品と自動帰還で省略されている操作もある。
- ソロは二キャラがいても人間の注意は一人分であり、二人協力と同じ負荷とはみなさない。配送中に厨房へどの程度注意を割けるかも試験対象。

したがって「料理＋皿洗い＋梱包＋自配達＋ギミック」を常に全部積む設計ではない。一方で代行を選べば無条件に負荷問題が消えるわけでもない。

## 6. 提案: ギミックの種類と罰の重さを切り離す

以下は新規の相談案。ユーザーの採用はまだ得ていない。

### 6.1 主役を面ごとに変える

| その面の負荷 | ギミック・盤面の提案 |
|---|---|
| 新器具や長い料理工程が主役 | 動線を短くし、追加の対処を頻繁に要求しない。軽い仕掛けや非妨害の演出は使える |
| 自配達を楽しむ外部面 | 厨房の中断要因を控えめにし、離れている間に失敗が連鎖しない構成を試す。代行は維持 |
| 既習工程が中心で料理負荷に余裕がある | シンプルなギミックを目玉として導入・応用する。新料理があるかどうかだけで負荷を判定しない |
| 複合挑戦を扱う面 | 習得済みの要素を組み合わせるが、同時対処の量と復旧コストを抑える。高星・Sでも理不尽な損失は前提にしない |

種類を増やすことと、一面で全種類を同時に働かせることは別。具体的な種類数・同時数の上限は今回は決めない。

### 6.2 カラスの例

「長く置くと盗む」は一文で分かるが、完成料理を連続して盗めば非常に厳しい。特にミキサー二回・加熱済みの一皿を失うと、簡単な原料一個の損失と復旧コストが違う。

初回候補としては、置いた原料を対象に絞る、来る前に分かる、頻繁に連続襲来しない、という調整を比較する。これは複数解を義務付けるための安全台追加ではなく、既存の焦げ・注文・配達の失敗と重なって苦しくなりすぎないための調整。対象と頻度は未決定。

### 6.3 パーティ性の評価

提案する目標は「成功しか起こらない」でも「常に何かに追われる」でもなく、「小さな事件に声を掛け、短く助け合って調理へ戻れる」状態。

例: カラス接近に気付く、通り道を譲る、届いた材料を受け取る。一つの仕掛けに多彩な戦略は必須でない。派手な景観・音・アニメーションは、操作負荷を大きく増やさず会場の変化を見せる補助として使える。ただし見た目だけで遊びの単調さを解決できるとも断定しない。

前回の候補R01〜R06は損失・待ち・禁止が中心だった。シンプルさだけで選ぶと小さな制約の積み重ねになるため、既存の搬送・受渡しなど助けになる仕掛けも比較対象に戻す提案。新しい専用設備追加の決定ではない。

## 7. 星・進行の扱い

星1で次へ進める面と、高星のやり込みを分ける既定は有効。ただし第2章以降の章最終には先行五面で合計8星が必要で、全部星1だけでは本編を通過できない。必要な星2等もパーティゲームとして無理なく狙えるか確認する。

既定の星割合や8星条件を変更する提案は現時点ではしない。低い基準点だけで、営業中ずっと追われる感覚や失敗の連鎖を解決したことにはしない。

## 8. 検証の提案（実施前）

1. 代表料理でギミックなしの基本厨房を試し、料理自体の詰まりを把握する。重い例は6-6、8-3、8-5等。新料理なしだが四品ある3-6も別に見る。
2. 同じ料理・設備条件でギミックを一つ加え、中断時間と損失がどれだけ増えたかを見る。初めから注文数も同時に増やさない。
3. 外部面では自配達・代行の双方で、離脱中の厨房と閉店前の到着を確認する。現地面へ無理に配達を追加しない。
4. ソロ二キャラ、初心者二人、三人、四人、慣れた人と初心者の混在で試す。単純な人数比例では補正しない。
5. 星1・章進行に必要な星・高星を分けて、クリア率だけでなく「料理を完成できたか」「自分の担当があったか」「失敗後に戻れたか」「急かされ続けたか」を確認する。

秒数・合格率・注文密度の確定値は今回置かない。

## 9. 申し送り

H-014に負荷懸念と検証対象を未送信で記録する。現段階で料理や共通仕様の変更要求はない。配置・注文負荷・提供方式・ギミック調整でも初心者に重いと分かった場合のみ、反復機会や工程を変更する必要があるか、理由と影響面を添えてユーザーに相談する。勝手に料理を削ったり、配達・進行条件を変えたりしない。

## 10. 料理・配達を中心に差別化する方向の評価（2026-09-16）

### 総評

有力な方向だと考える。ただし強みは「本家より多くの手順を要求する」ことではなく、「いろいろな料理を分担して仕上げ、届けるまでをチームで回す」体験に置く提案。

本家2は動く厨房・ポータル・移動足場を特徴として紹介している一方、料理の多様さも公式の訴求点である。[Team17公式紹介](https://www.team17.com/games/overcooked-2)。したがって「本家はギミックだけ、本作は料理だけ」という排他的分類や、料理品数だけで独自性を証明する比較はしない。

料理の種類、共用工程、可搬設備で変えられる分担、自配達と代行の選択がつながれば独自の体験になり得る。実際の楽しさ・差別化の伝わり方は未検証。

### 主な利点

- 理解した調理文法を違う料理に使い、作れる料理が増える達成感を作れる。
- 仕込み・加熱・合流・発送準備を一つの共同作業として見せられる。
- 外部面では「誰がいつ厨房を離れるか」という判断があり、既存の代行選択を維持したまま分担を変えられる。
- 過剰な地形妨害を抑えれば、調理と連携の成功が見えやすくなる。

### デメリットと対策案

| リスク | 起こり得ること | 対策として検討すること |
|---|---|---|
| 覚える負担が大きい | 料理に詳しい一人が指示し、初心者は材料運びだけになる | 共通工程の理解を利用できる配置、担当を一つ任せても完成に貢献できる作業区、レシピの反復機会を確認。現行献立は独断変更しない |
| 豊富さが作業量にしか見えない | 中間素材・容器移動が増えても「同じことを長くする」だけになる | 工程が見た目の変化や受渡しの場面を作るかを見る。共用中間素材も注文ごとの既定一食分を守り、複数食バッチを新設しない |
| ステージの記憶が弱くなる | 料理だけ変わり、毎回同じ厨房のように感じる | 献立に加え、提供方式・設備の距離・受渡し場所・可搬と固定の配置・小さなギミックで違う動きを作る。景観だけの差に頼らない |
| 調理班と配達班が別々のゲームになる | 配達担当が孤立し、二人協力では厨房側も一人作業が続く | 出発前の積載・仕込み・引継ぎと帰還後の再参加をつなぐ。恒久的な運転専任・強制交代・新連携ボーナスは導入しない。既定の自動帰還・代行を活かせるか確認 |
| 協力パーティ性より効率作業に寄る | 役割が固定され、無言で工程を繰り返すようになる | 短い応援・受渡し・助け合いが起こる配置を用意。小さなギミックを残し、ミスの復旧は短く。初心者の失敗を長い作り直しで罰しない |
| 開発負荷が別の場所へ移る | ギミックが少なくても多数の料理表示・中間状態・配達・同期・人数調整が必要 | ギミック削減だけで制作費や検証量が減るとは扱わない。既存の共用器具・原料・操作を使い、品数や専用工程の追加を今回の評価から要求しない |

### 配達がない面でも個性が成立するか

現地提供面や代行中心のプレイでは、自配達を差別化の根拠にできない。その場合も、料理の合流、設備の寄せ方、受渡し配置が楽しい必要がある。差別化を示すために自配達を必須化したり、空中会場へ不自然に配送路を追加したりしない。

### 提案のまとめ

「料理の種類とチームの仕事を主役にし、小さなギミックをアクセントとして残す」を比較方針として推奨する。ただし料理工程数をさらに増やす意味ではなく、すでに決まっている工程から楽しさを引き出す。初見の分かりやすさ、調理と配送の分断、舞台ごとの違いを主な検証点とする。

ギミックの採用数・同時発生数・章配分は未決定。ユーザーの質問を方針の採用表明として扱わず、既定資料・料理・共通配達ルールは変更しない。
