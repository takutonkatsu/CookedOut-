# 実装申し送り: 本店12×9固定化と通常営業準備UI

- 更新日: 2026-09-11
- 対象: 並行実装タスク
- 優先度: 本店通常営業・ショップ実装より前

## 決定差分

1. 本店厨房は通常営業解放時から12×9全域固定とする
2. 店ランク3・5・7・9の厨房拡張、閉鎖区画、追加ソケット解放を廃止する
3. 厨房拡張商品・価格・購入状態をセーブモデルへ追加しない
4. 成長は設備種類、種類共通Lv、追加台数、通常営業Tier、外見に限定する
5. 組立台と受渡し台は同じLvなし設備として扱う
6. 鍋・フライパンは専用熱源込みの一設備・一所有単位として扱う

## 実装時の正本

- 固定グリッドとソケット: `docs/game-design/19_fixed_home_kitchen_layout.md`
- 営業前・ショップ・配置UI: `docs/game-design/20_pre_service_shop_and_layout_ui.md`
- 設備Lvと台数: `docs/game-design/18_store_rank_and_equipment_progression.md`
- 現在仕様: `docs/game-design/CURRENT_GAME_SPEC.md`

## 実装順

1. `home_kitchen_v1`を幅12、高さ9の決定的ステージデータとして追加する
2. 地形と固定部材を厨房定義へ、プレイヤー設備だけを配置プリセットへ分離する
3. 汎用ソケット18、組立・受渡し面8、食材供給6、容器供給1、配送代行専用2、積込1、退出1をデータ化する
4. 未使用の汎用ソケットを通常カウンターとして操作可能にする
5. 献立要求タグと所有設備から、必須不足、推奨不足、到達不能を検証する
6. 決定的な推奨配置適用と、3枠の手動プリセット保存を作る
7. 献立3候補、設備確認・配置、ショップの順にUIを追加する

## 非対象

- 既存チュートリアル1-1、1-2、1-5の10×8厨房は出張営業なので変更しない
- 1-3の12×9出張厨房を本店データへ流用しない
- 厨房の装飾テーマや美術品質はこの差分で完成させない
- 本番課金、サーバー購入検証、シーズン競技はこの差分で実装しない

## 必須テスト

- 本店データが常に12×9で生成され、ランク1と10で地形・固定ソケット数が同じ
- 未所有設備を配置できず、購入上限と固有上限を超えられない
- 鍋・フライパン一式が各1ソケットを占有する
- 必須設備不足は開始不可、推奨不足は警告のみ
- 推奨配置を同じ入力へ適用すると毎回同じ結果になる
- 保存した3プリセットが互いに混ざらず復元される
- 全固定設備と退出口への到達可能性を検証できる
- 旧厨房拡張フィールドを持つ試験セーブが存在する場合、値を無視して安全に読み込める
