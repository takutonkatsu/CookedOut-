# COOKED OUT! 基幹仕様確定からCore Alpha実装へ進む計画 v0.1

- 作成日: 2026-09-12
- 状態: 推奨進行案
- 目的: 仕様変更による再実装を減らしつつ、触らなければ判断できない操作感は早期検証する

## 1. 結論

現在は量産実装へ進む前に、再実装コストの高い基幹仕様を確定させる方が効率的である。ただし全54面の盤面、全数値、全画像を完全確定するまでコードへ触れない方式にはしない。

```text
紙上で確定できる構造
→ 先に仕様固定

触らないと分からない感触
→ 最小試作で比較

量産物
→ 構造と試作の合格後に着手
```

既存のCore Alpha実装は破棄せず、仕様検証用の試験場として使用する。基幹仕様確定中は、新しい量産機能、全ステージ制作、画像の大量生成を一旦止める。

## 2. 実装前に確定する基幹仕様

### A. モードと進行

- 通常営業、ソロ出張、マルチ出張、練習厨房、競技の役割
- 店ランク1〜20、営業Lv.1〜20、出張進行上限
- 料理解放、設備解放、シーズン競技解放
- 星、店の評判、コイン、初回報酬、重複付与防止

### B. 一営業のルール

- 営業時間と終了条件
- 注文生成、注文猶予、失注、チップ、連続成功
- 料理別基礎スコア、配達得点、星基準
- 自前配達と配送代行の均衡

### C. 厨房アクション

- 移動、ダッシュ、対象選択、持つ、置く、投げる、作業
- 切る、加熱、焦げ、火災、組み立て、廃棄、皿洗い
- 可搬設備の対象、移動条件、禁止配置、経路保証
- ソロ出張の二人切替と非操作キャラクター

### D. コンテンツ構造

- 料理系統、全料理候補、工程タグ、必要設備
- 出張9章の学習順と各章テーマ
- ギミック一覧、同時使用規則、人数別成立条件
- チュートリアル1-1〜1-8の習得内容

### E. 技術・運営上の基礎

- セーブデータID、バージョン移行、オフライン境界
- マルチの権限、同期対象、切断、報酬確定
- ステージ・料理・設備をデータ追加できる構造
- 分析イベント、テスト分類、サーバー責務
- 広告と課金がプレイ導線へ入る位置

### F. UXとデザイン基準

- 画面遷移図と各画面の情報優先順位
- 厨房HUD、配達HUD、結果画面、昇格画面
- キャラクター、料理、設備、厨房、街のデザインガイド
- 代表一体・一料理・一厨房を使った品質基準

## 3. 実装と並行して試作する項目

次は文章だけでは確定できないため、Core Alphaで比較する。

- 仮想スティックと共通アクションの反応
- 対象自動選択と輪郭表示
- 投擲距離、軌道、受け取りやすさ
- 可搬設備を動かす頻度と誤操作
- ソロ二人切替のテンポ
- 厨房固定カメラの見やすさ
- バイクの四ボタン操作
- 一営業の適正時間

試作では仮素材を使い、アート量産と数値磨き込みを行わない。比較条件と合格基準を先に決める。

## 4. 後から調整してよいもの

- 各料理の正確な秒数と基礎点
- 星1〜3の最終スコア
- 評判量、コイン価格、設備強化価格
- 注文間隔と配達距離の細かな曲線
- 各出張ステージの最終タイル配置
- 演出、SE、エフェクト、アニメーションの磨き込み
- 全54面と全アセットの量産

これらはデータ化しておき、コード改修なしで調整可能にする。

## 5. 推奨する進行順

1. 基幹仕様一覧を未決定・提案・確定へ分類する
2. モード、進行、スコア、料理・設備データを先に確定する
3. チュートリアル1-1〜1-8と通常営業一周分を紙上で通す
4. 画面遷移と代表デザインを確定する
5. Core Alphaを検証用として必要最小限だけ修正する
6. 実機で操作感、所要時間、難度、スコア式を検証する
7. 検証結果を仕様v1.0へ反映して基幹部分を凍結する
8. 以降、全ステージ、料理、キャラクター、UI、音を量産する

## 6. 仕様凍結の意味

仕様凍結は永久に変更しないことではない。次を満たさない変更は量産開始後に行わないという基準である。

- 初心者が進行不能になる
- 通信、セーブ、報酬の整合性が壊れる
- Core Alphaの検証で中心的な面白さが成立しない
- 法務、審査、性能上の重大問題が見つかる

細かな数値は調整可能に保つ一方、モード関係、基本操作、データID、報酬の流れ、画面遷移を頻繁に変えない状態を作ってから量産へ進む。
