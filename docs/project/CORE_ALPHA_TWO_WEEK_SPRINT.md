# COOKED OUT! Core Alpha 2週間スプリント案 v0.1

- 作成日: 2026-09-11
- 目標期間: 2026-09-12〜2026-09-25（14暦日）
- 状態: 期限を決定。オンライン範囲だけ企画判断待ち
- 前提: 現在の1-1〜1-5、12×9本店データ、40 EditMode／34 PlayModeテストを起点とする

## 1. 結論

2週間で狙えるのは、`Core Alpha Feature Complete`である。

> 第1章1-1〜1-8をソロで完走し、通常営業を解放して、献立選択、設備配置、料理、自前／代行、結果、報酬、設備強化、再挑戦までを一周できる内部検証版。

元のCore Alphaに含めた「全8面の1〜4人オンライン」「60秒再接続」「クラウドセーブ」「製品品質のアート」「十分な人数別バランス検証」まで同じ2週間へ入れることは、現在オンライン実装が未着手であるため現実的ではない。これらを含む安定化完了版と、2週間の機能完成版を区別する。

## 2. 2週間版の必須範囲

### 必ず完成させる

- 1-1〜1-5の既存機能を一本道進行へ統合
- 1-6の誘導火災、延焼、消火器、復旧、提供
- 1-7の現地提供、汚れ皿返却、継続入力の皿洗い、再利用
- 1-8の配送代行、自前配達、予告付き二島接続変化、章完了
- 1-1〜1-8の解放、星、再挑戦、初回ガイド
- 第1章完了後の通常営業解放
- 第1章3料理から互換性のある3献立候補を提示
- 本店12×9で推奨配置、手動配置、配置保存1枠以上
- Tier1〜2、コイン、XP、設備種類Lv1〜2、購入・強化
- 自前配達と配送代行を含む通常営業一周
- 結果、自己ベスト、ローカルセーブ、再起動読込
- 最小分析ログをローカル出力し、イベント内容を検査可能にする
- 自動テスト、Unity compile、iOS未署名build

### 時間が残れば完成させる

- 配置プリセット3枠すべて
- Tier3〜5の仮データ
- 店ランク1〜10の全閾値表示
- iPhone署名実機buildとTestFlight内部配布
- 料理・設備・UIの見た目修正。ただし可読性を妨げる問題に限定

## 3. オンラインの二択

### 推奨: 2週間では1-1二人同期の技術試験まで

- 1-1でホスト／ゲスト二人の移動、所持、切断、提供を同期する
- パッケージ、権威境界、安定ID、走行snapshotを決める
- 第1章全8面の2〜4人化は、Feature Complete直後の安定化スプリントで行う

この場合、ソロ第1章と通常営業を中途半端にせず、2週間終了時に一周を確実に評価できる。

### 非推奨: 全8面の2〜4人オンラインを2週間へ入れる

この場合は通常営業を、固定献立一つ、固定配置、Tier1、設備強化一種類程度まで縮小する。認証、クラウド、再接続、ランキング有効記録、十分な切断試験は含めない。それでも期限は高リスクであり、完成保証ではなくなる。

## 4. 10営業日の進行

| 日 | 実装の主対象 | その日の終了条件 |
|---:|---|---|
| 1 | スコープ固定、共通データ、章遷移 | 1-1から1-5を順番に起動でき、既存テストが通る |
| 2 | 1-6 火災 | 誘導火災を消し、復旧後に料理を提供できる |
| 3 | 1-7 皿洗い | 汚れ皿を洗い、同じ皿を再利用して提供できる |
| 4 | 1-8 代行・動的厨房 | 自前一件、代行一件、接続変化を含め星1を取れる |
| 5 | 第1章統合 | 初回起動から1-8結果まで、開発者操作なしで完走できる |
| 6 | 通常営業前半 | 解放、献立3候補、Tier、推奨配置、開始まで通る |
| 7 | 通常営業後半 | 本店営業、自前／代行、結果、コイン、XPが一周する |
| 8 | 設備成長・セーブ | 購入・Lv強化・配置・自己ベストが再起動後も残る |
| 9 | 統合QA | 自動テスト、iPhone画面、操作不能、進行不能を修正する |
| 10 | リリース候補 | クリーン環境compile、全テスト、iOS build、既知問題表を完了する |

オンライン推奨案を採る場合、ネットワーク試験は別作業レーンで日1〜8に並行し、日8に1-1二人同期の成否を判定する。

## 5. 期限を守る凍結事項

2週間中は次を変更しない。

- 第1章の料理3系統と導入順
- 厨房の基本操作と四行動ボタン
- 1-1〜1-8の主ギミック
- 本店12×9と通常営業が外部配達型であること
- 現在のカピバラ、P0厨房、料理アセットを仮採用すること
- 得点式、星0〜3、Tier1〜2の基本構造

見た目の修正は、対象が見えない、料理を識別できない、ボタンを押せない、画面外へはみ出す等のプレイ阻害だけにする。好みや仕上げの修正はスプリント後の美術安定化へ送る。

## 6. 並行する54面設計の上限

同じ2週間で全54面の正確な配置まで完成させない。企画側では既存マスター表を企画カードへ拡張し、実装側とはファイルと担当を分ける。

- 全54面: 一文コンセプト、料理、提供方式、主要・補助ギミック、規模、美術テーマまで
- 第2章6面: 2〜3個のグリッド構成案まで
- 厳密な座標、周期、人数別星ライン: Core Alpha実測後

## 7. 完了の判定

2026-09-25時点で、次をすべて満たせば2週間版を完了とする。

- クリーンな初回状態から1-1〜1-8をソロ完走できる
- 第1章完了後に通常営業を開始できる
- 通常営業を3回連続で完走し、1回以上設備強化できる
- アプリ再起動後に星、コイン、XP、設備、配置、自己ベストが残る
- 進行不能、データ破損、再起動不能の既知P0不具合がない
- EditMode／PlayModeテストとiOS未署名buildが成功する
- 既知P1／P2不具合と未完成の美術を一覧化している

オンラインを推奨範囲へ限定した場合は、1-1二人同期を別の技術合格条件とし、Core Alpha Feature Complete本体の進行を止めない。

## 8. 運用ルール

- 実装、ネットワーク、企画・ステージ、美術を別作業レーンにする
- 実装レーンの統合責任者を一つに固定する
- 一日一回だけ統合し、常にテストが通る状態へ戻す
- ユーザー確認は原則一日一回、実機画面または短い動画でまとめて行う
- 当日中に回答がない美術判断は現候補で進め、ゲーム進行を止めない
- 新しい要望はP0の進行不能修正を除き、スプリント後のバックログへ追加する
